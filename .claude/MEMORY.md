## 実装済みの機能

- メンバーと割り当て(`forms.py` の `build_members` / `open_members_dialog`、`timeline.py`、`task_dialog.py`、`gantt.py`): ヘッダーの「メンバー」ボタンで、名前と相対比率(10〜300%)を管理(改名は担当者に伝わる。担当するタスクがあるメンバーは削除不可)。タスクの担当者はメンバーから選び、割り当て率(1〜100%)を設定。工数は基準の人の時間で、`工数 ÷(相対比率×割り当て率)` を稼働枠に割り当てて完了予定を求める(手で指定の完了予定は換算しない)。ダイアログに日工数の換算を表示。同じ担当者の期間が重なるタスクの割り当て合計が100%超の期間は、保存時に通知し、棒の内側に縞で示す(状態「終了」は数えない)。古いファイルの自由入力の担当者は、読込時にメンバー(100%)として補う。

- ドラッグ操作(`arrange.py`、`gantt_drag.py`、`gantt.py`): 名前のラベルをつかんで行を移動(同じセクション内、セクション間、セクションなしとの往復。見出しと「タスク追加」の行は末尾に入る)、Alt/Option を押して落とすとコピー(名前に「(コピー)」、`predecessors` は空、通知あり)。日次スケールでは、バーを横にドラッグして開始予定を日単位でずらす(手指定などで入っている完了予定は同じ日数、締切は動かさない。基準日より前へは動かさない。割り当て超過は通知)。絞り込み中は行の移動・コピーを無効にする。取り消しはない。
- メイン画面: プロジェクト名(右隣に「祝日を更新」)、プロジェクトファイルのコンボボックス、「開く」「保存」ボタン、テーマ FAB(左展開)、ヘルプダイアログ。
- 保存(`views.py`、`forms.py`、`storage.py`):
  - 「保存」ボタン。新規は初回の保存時に名前入力ダイアログ(`open_name_dialog`)、開いたファイルは同じ名前で上書き。名前の変更は不可。
  - `validate_name`: 空、使えない文字(`/ \ : * ? " < > |` と制御文字)、先頭の `.`、予約名(`config`、`holidays`)、新規での重複を拒否。前後の空白は取り除く。
  - `save_project`: 一時ファイル経由。新規(`overwrite=False`)は `os.link` で、同名ファイルを上書きしない。失敗は通知のみで、画面の状態(`path`、名前)は変わらない。
  - 読込時に `project.name` をファイル名にそろえる。前後に空白のある名前や `.` で始まるファイルは、一覧に出さない。
- 稼働時間の設定(`views.py`、`forms.py`、`timeline.py`):
  - ヘッダーの「設定」ボタンで、設定ダイアログ(`open_settings_dialog`)を開く。1日の稼働可能時間(1 以上 8 以下、小数点以下2桁まで。範囲外と3桁目以降は入力中に警告する。丸めない)と始業時刻(`HH:MM` のテキスト入力 + 時計アイコンで開く時刻選択ダイアログ)をプロジェクトごとに変更できる。始業時刻 + 稼働時間が 24:00 を超える組み合わせは拒否(`build_work_settings`)。
  - 適用(`apply_settings`): 値を更新して再描画する。完了予定は表示のたびに計算するので、再計算の処理と通知はない。確認なし・保存は自動では行わない(変更は編集中の判定に入る)。同じ値なら何もしない。
- タスクの日付(開始予定・完了予定・締切。設計書 `2026-10-03-planned-dates-design.md`): `Task.planned_start` / `planned_end` / `planned_end_manual` / `deadline`。完了予定は `effective_end` で求める(工数が 0 以下なら `planned_end`、手で指定ならその値、それ以外は開始予定+工数から算出、算出できなければ締切、締切もなければ開始予定の翌日)。旧形式のファイルは読み込み時に変換(旧 `start` は開始予定、手入力の旧 `end` は締切、自動算出の旧 `end` は捨てる)。実績の開始・終了は後続機能。
- 開く動作:
  - コンボボックスで選ぶと、すぐ開く。「開く」は、基準ディレクトリを走査し直して、ファイル一覧ダイアログ(`open_file_dialog`)を出す。
  - 編集中(`is_dirty()`: 開いた直後・保存した直後の `snapshot` との差)は、`open_unsaved_dialog` で「保存して開く」「保存せず開く」「キャンセル」を確認する(コンボボックス・一覧の両方)。
  - 「保存して開く」は、保存に成功したときだけ開く(新規の未保存は名前入力を経由)。読込に失敗したら、現在のプロジェクトと `path` を変えず、コンボボックスの表示を戻す。
- タスク編集ダイアログ(`task_dialog.py`、検証は `forms.py` の `build_task`):
  - 優先度は色付きチップ(`PriorityChips`。高=オレンジ、中=黄、低=青。赤は予定超過と競合するため使わない)。色の入力は `preview=True`。
  - 開始予定・完了予定は横並び(2行目に締切と工数)の日付入力(テキスト + `ui.date` のダイアログ)。開始・終了の各列の「時刻を指定」のチェックで、その側の時刻入力(`ui.time` のダイアログ)が出る(チェックは側ごと。外しても入力欄の値は保つが、保存と変更の判定ではチェックのない側は補う時刻を使う。自動算出の終了で時刻が補う終了と違うときは、終了側のチェックをオンに固定して無効化し、外して 18:00 に変わるのを防ぐ)。時刻なしは、開始=始業時刻(`Project.work_start`)、終了=始業+8h+昼休憩1h(`default_times`。固定の定数 `STANDARD_WORK_HOURS`・`LUNCH_HOURS`)。日付と時刻は `compose_datetime` で文字列にして `build_task` に渡す。開くとき、側ごとに、補う時刻と違えばチェック済みで出る(`needs_start_time`・`needs_end_time`)。
  - 閉じる: `persistent`。「キャンセル」と `ESC` は、変更があるときだけ確認(保存・破棄して閉じる・編集に戻る)。変更の判定は、開いた時点の入力値との比較(`current()`)。
  - 削除: 編集時だけ左端に削除ボタン。確認ダイアログ → `MainView.delete_task`。保存は自動では行わず、「編集中」になる。
- ガントチャート(`gantt.py`): 棒は開始予定から完了予定まで、締切に「◆」(クリックで編集)。
  - 日次・週次・月次のスケール切替。見出しは年・月の結合帯と、日(日次は下段に（曜日）)。
  - 格子線(縦・横)。日次は土日祝の背景(祝日は内閣府 CSV、初回のみ自動取得して `~/.projectapp/holidays.json` にキャッシュ)。
  - セクション、セクションなしのタスク(`Project.tasks`、一覧の末尾に追加行)。
  - タスクの追加・編集ダイアログ(`forms.py`。名前必須、有効な完了予定 ≥ 開始予定、年は 2000〜2100、タイムゾーン付き日時と負の工数は拒否)。
- 日程計算(`timeline.py`):
  - `calc_end`: 稼働日(月〜金で祝日でない日)の稼働枠(始業 9:00 から 6.5h、連続)に工数を割り当てる。
  - `effective_end` / `computed_end`: 完了予定の決め方(上記)。`is_overdue`: 締切か完了予定を過ぎて未完了のタスク行を薄い赤の背景にする(バーの色は不変)。`deadline_position`: 締切の位置(範囲外は `None`)。
  - 工数が NaN・inf・0 以下・3650 稼働日分超、`daily_hours` が 0 以下・24 超のときは、算出せず締切(なければ開始予定の翌日)にする。
- 保存・読込(`storage.py`): 日時、基準日、列挙型、`tasks`、`work_start` を復元(古いファイルは既定値で読む)。

## 主な設計判断

- 描画は NiceGUI 要素と CSS による自前描画(外部のガントライブラリは使わない)。
- 日時から位置への変換は純粋関数(`timeline.py`)にして、NiceGUI から切り離す。
- 祝日の取得は、ファイルがない初回のみ起動時に自動、以降は更新ボタンで行う。失敗しても画面は変えず通知だけ出す。
- 完了予定は保存しない値(手で指定のときだけ `planned_end` を使う)。稼働設定や祝日の変更はすぐ反映される。
- 編集中の判定は、各編集用の関数に目印を付けず、`asdict(project)` と `snapshot` の比較にする(今後の編集機能で判定が漏れない)。
- 確認ダイアログを出す前に、コンボボックスの表示を現状に戻す(どの選択肢でも、閉じたあとの表示が正しい)。

## 保留中: 始業が15:00以降のときの補う終了(別ブランチで扱う)

補う終了(始業+9h)は、始業が15:00以降だと24時以上になる。このブランチでは暫定で `23:59` に頭打ちにしているだけ。本来の対応と、稼働設定のオプション「始業時刻を制限する」(オンのとき始業は 00:00〜14:59 のみ、ほか制限事項7点)は、設計書 `2026-10-03-task-edit-dialog-design.md` の「保留事項」に記載。未決: オフのときの本来の対応(頭打ちを残す・翌日にまたぐ・時刻の入力を必須にする)、昼休憩を設定にするか。

3. 未コミットの変更があれば、コミットしてよいかユーザーに確認する。マージとプッシュも、許可を得てから行う。

**注意(作業で学んだこと)**

- 全体のテストは、直列で約 1 分(36〜47 秒)、`uv run pytest -n auto` で約 10 秒(pytest-xdist。2026-10-06 に導入)かかる(2026-10-06 の対策前は約 6〜7 分。原因と対策は「次にやること」の 7)。念のため、時間制限(`timeout`)を付けずに、バックグラウンドで実行して、結果の行まで待つ(制限で途中で切れると、結果の行が出ない)。
- 新しいプロジェクトの `base_date` の既定は「今日」。日付に依存するテストは、`view.project.base_date = date(2026, 10, 5)` のように固定する(固定を忘れたテストが、日付が進んで落ちた)。
- 文字列の置換スクリプトは、置換する範囲が空でないことを確認する(空の範囲の `replace` は、全文字の間に挿入して、ファイルが壊れる。2 回起きた)。
- NiceGUI の `User` は、非表示の要素を `find` で見つけず、クリックを親へ伝えず、キー入力のシミュレーションがない。
- NiceGUI の websocket は、1 メッセージ約 1MB まで(大きいデータは分けて受け取る)。
