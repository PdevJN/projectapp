## 実装済みの機能

- メイン画面: プロジェクト名(右隣に「祝日を更新」)、プロジェクトファイルのコンボボックス、「開く」「保存」ボタン、テーマ FAB(左展開)、ヘルプダイアログ。
- 保存(`views.py`、`forms.py`、`storage.py`):
  - 「保存」ボタン。新規は初回の保存時に名前入力ダイアログ(`open_name_dialog`)、開いたファイルは同じ名前で上書き。名前の変更は不可。
  - `validate_name`: 空、使えない文字(`/ \ : * ? " < > |` と制御文字)、先頭の `.`、予約名(`config`、`holidays`)、新規での重複を拒否。前後の空白は取り除く。
  - `save_project`: 一時ファイル経由。新規(`overwrite=False`)は `os.link` で、同名ファイルを上書きしない。失敗は通知のみで、画面の状態(`path`、名前)は変わらない。
  - 読込時に `project.name` をファイル名にそろえる。前後に空白のある名前や `.` で始まるファイルは、一覧に出さない。
- 開く動作:
  - コンボボックスで選ぶと、すぐ開く。「開く」は、基準ディレクトリを走査し直して、ファイル一覧ダイアログ(`open_file_dialog`)を出す。
  - 編集中(`is_dirty()`: 開いた直後・保存した直後の `snapshot` との差)は、`open_unsaved_dialog` で「保存して開く」「保存せず開く」「キャンセル」を確認する(コンボボックス・一覧の両方)。
  - 「保存して開く」は、保存に成功したときだけ開く(新規の未保存は名前入力を経由)。読込に失敗したら、現在のプロジェクトと `path` を変えず、コンボボックスの表示を戻す。
- ガントチャート(`gantt.py`):
  - 日次・週次・月次のスケール切替。見出しは年・月の結合帯と、日(日次は下段に（曜日）)。
  - 格子線(縦・横)。日次は土日祝の背景(祝日は内閣府 CSV、初回のみ自動取得して `~/.projectapp/holidays.json` にキャッシュ)。
  - セクション、セクションなしのタスク(`Project.tasks`、一覧の末尾に追加行)。
  - タスクの追加・編集ダイアログ(`forms.py`。名前必須、終了 ≥ 開始、年は 2000〜2100、タイムゾーン付き日時と負の工数は拒否)。
- 日程計算(`timeline.py`):
  - `calc_end`: 稼働日(月〜金で祝日でない日)の稼働枠(始業 9:00 から 6.5h、連続)に工数を割り当てる。
  - `fill_end`: 保存時に、開始あり・終了なし・工数ありのときだけ終了を補完。手入力の終了は変えない。
  - `is_overdue`: 終了を過ぎて未完了のタスク行を薄い赤の背景にする(バーの色は不変)。
  - 工数が NaN・inf・0 以下・3650 稼働日分超、`daily_hours` が 0 以下・24 超のときは終了を空のままにする。
- 保存・読込(`storage.py`): 日時、基準日、列挙型、`tasks`、`work_start` を復元(古いファイルは既定値で読む)。

## 主な設計判断

- 描画は NiceGUI 要素と CSS による自前描画(外部のガントライブラリは使わない)。
- 日時から位置への変換は純粋関数(`timeline.py`)にして、NiceGUI から切り離す。
- 祝日の取得は、ファイルがない初回のみ起動時に自動、以降は更新ボタンで行う。失敗しても画面は変えず通知だけ出す。
- 編集ダイアログの終了欄には自動算出値が残る。工数だけを変えても終了は動かない(空にして保存すると再計算)。
- 編集中の判定は、各編集用の関数に目印を付けず、`asdict(project)` と `snapshot` の比較にする(今後の編集機能で判定が漏れない)。
- 確認ダイアログを出す前に、コンボボックスの表示を現状に戻す(どの選択肢でも、閉じたあとの表示が正しい)。

## 保留中の課題: 保存の `os.link` と書き込み途中のファイル(プロジェクト保存 UI)

状況: `feature/project-save` で保存 UI を実装済み(コミット済み)。新規保存(`overwrite=False`)は、一時ファイルに書いてから `os.link` で本来の名前にする(`storage.save_project`)。**対応は保留。いつでも着手できる。**

課題: ハードリンクに対応しない場所(FAT/exFAT、一部のネットワークドライブなど)では、`os.link` が `OSError` になり、新規保存が常に失敗する。`~/.projectapp` が通常のローカルディスクなら実害は小さい。

対応案(推奨は案 1):
1. **link → 失敗したら確認して置き換え(推奨)**: 一時ファイルに書き切り、`os.link` を試す。`FileExistsError` 以外の `OSError` なら、`exists()` で同名がないことを確認してから `os.replace`。壊れたファイルが残る経路がなくなる。競合の隙間が残るのは、ハードリンク非対応の場所だけ。
2. 新規保存は `open(path, "x")` で直接書く(失敗時は削除)。コードは最も少ないが、書き込み途中でプロセスが落ちると壊れたファイルが残りうる(読込失敗は通知され、別ファイルは上書きしない)。
3. 存在確認のみで `os.replace`: 競合を防げないので非推奨。
- あわせて入れてよい: `fsync`(電源断で空ファイルになるのを防ぐ。M-3 の解消)。一時ファイル(`.save-*.tmp`)の起動時の掃除は、溜まって困ってからでよい。
- テスト案: `os.link` を失敗させても保存できる、そのフォールバックでも同名があれば `FileExistsError`、書き込みが途中で失敗したら本来の名前のファイルも一時ファイルも残らない。
- 変更の範囲は `src/projectapp/storage.py` の `save_project` と `test/test_storage.py` のみ。

保存 UI のレビューで先送りした軽微な点:
- 保存に失敗すると、名前入力ダイアログが閉じて入力が消える。
- 一時ファイルの権限が umask を無視する。
- 名前の末尾が `.` や空白だと Windows で問題になる。
- 名前の競合を実ファイルで確かめる views のテストがない。
