# ヘッダー・メニュー・ショートカット・git 連携

> `CLAUDE.md` から分けた仕様。ここが現在の仕様の正。仕様を変えたら、該当するファイルを更新する。

## ヘッダー

- メイン画面の上部に、1 行のヘッダーを置く(左から、メニュー 5 つ。右側に、git の状態のチップ・プロジェクトの切り替えのコンボボックス・ダッシュボードのアイコン・プロジェクト格納フォルダを開くアイコン・全体の設定のアイコン・テーマのメニュー)。プロジェクト名は、ヘッダーの外の、メイン側の左上に出す(12px の太字)
- git の状態のチップ(プロジェクトの切り替えのコンボの左。読み取り専用): 格納先が git の作業ツリーのときだけ出す(`git`がない・作業ツリーでないときは出さない)。文言は`main ↑1 ↓2 ●3`(ブランチ・未プッシュ・未取得・未コミットの変更。0 は省く。detached は`(abc1234)`)。「変更」は、格納先のプロジェクトファイル(直下の`*.json`。`config`・`holidays`を除く)だけを数える。ahead/behind は、最後に`fetch`した時点のリモートとの比較で、アプリは`fetch`しない。未取得があると橙、未コミットがあると黄、読めないと赤(文言は`git`、マウスオーバーに理由。通知は出さない)。マウスオーバーに、ブランチ・上流・件数の意味を出す。更新は、起動時・格納先の変更後・プロジェクトを開いたとき・保存の成功後・チップのクリックだけ(定期実行はしない)。プルは`Git`メニューの`プル`
- ヘッダーは、画面の上端・左右いっぱいの四角い帯(角丸にせず、ページの余白の外に固定する)で、テーマカラーの背景 + 白文字にする(ダークテーマでは、暗めのテーマカラー)。フォントは標準より 2 小さく(12px)、メニューのボタンは楕円型(半透明の白の背景)。ヘッダーは折り返さない(狭いときに縮むのは、プロジェクトを切り替えるコンボだけ。コンボの中のファイル名は 10px)
- `ファイル`メニュー: `開く`(ファイル一覧のダイアログ)・`PlantUML を取り込む`・`CSV を取り込む`・`設定を取り込む`・`新規プロジェクト作成`・(水平線)・`上書き保存`・`名前をつけて保存`・(水平線)・`格納先を変更`・`祝日を更新`
- プロジェクト格納フォルダのアイコン(テーマの左): 押すと、格納先(既定は`~/.projectapp`)を OS のファイラ(Finder など)で開く(まだなければ作る。開けなければ通知する)
- `プロジェクト`メニュー: `設定`・`メンバーとパラメータ`・`ダッシュボード`。`メンバーとパラメータ`は 1 つのダイアログのタブ(メンバーが先)で、適用はタブごと(`適用`は閉じない。下の 1 行に`キャンセル`と`閉じる`を並べ、`閉じる`は変更のあるタブをパラメータ→チーム→メンバーの順に確定して閉じる〔エラーなら閉じずそのタブを出す〕。`キャンセル`は、このダイアログで適用した分がなければ確認なしで未適用の編集を捨てて閉じ、あれば`適用しなかった分だけ取り消す`・`すべて取り消す`〔開いた時点のプロジェクトと元に戻す履歴に戻す〕・`戻る`の確認を出す。メンバーの表は、先頭の列にアイコン〔画像と、`選ぶ`・`外す`のボタン。`選ぶ`はネイティブのみ〕を出す。キャンセルで閉じ、未適用の編集は捨てる)。パラメータを適用すると、メンバーのタブの表の列を作り直す(メンバーの未適用の編集は残し、段階の選択は改名・削除に追従する)。チームを適用すると、メンバーのタブの未適用の行から、削除したチームへの所属を外す。未適用の編集があるタブの見出しには`●`を出す
- どのメニューの項目にも、左にアイコンを添える(`ダッシュボード`の項目には、右端にキー`D`も添える)
- `エクスポート`メニュー: `チャートプレビュー`(ガントチャートのプレビュー。画像と PlantUML で保存できる)・`担当者へ書き出し`・`TSV として書き出す`・`設定を書き出す`
- `Git`メニュー(`エクスポート`と`ヘルプ`のあいだ): `コミット…`・`プッシュ`・`プル`・`状態を読み直す`(左にアイコン、右端にキー)。作業ツリーでないときは、`コミット…`・`プッシュ`・`プル`は押せない(`状態を読み直す`は、いつでも押せる)。`プッシュ`は、上流がない・未プッシュが 0 のときも押せない。`プル`は、上流がない・プロジェクトファイルに未コミットの変更がある・開いているプロジェクトに未保存の編集があるときも押せない。押せない理由は、項目のマウスオーバーに出す(ショートカットで押したときは通知する)
- `ヘルプ`メニュー: `ショートカットヘルプ`
- キーボードショートカット(`Ctrl/Cmd` は macOS では Cmd): `Ctrl/Cmd+S` 上書き保存、`Ctrl/Cmd+Shift+S` 名前をつけて保存、`Ctrl/Cmd+O` 開く、`Ctrl/Cmd+N` 新規プロジェクト作成、`Ctrl/Cmd+,` 設定、`Ctrl/Cmd+Shift+M` メンバーとパラメータ、`Ctrl/Cmd+E` 担当者へ書き出し、`Ctrl/Cmd+P` チャートプレビュー、`Ctrl/Cmd+K` コミット、`Ctrl/Cmd+Shift+K` プッシュ、`Ctrl/Cmd+Shift+L` プル、`Ctrl/Cmd+Z` 元に戻す、`Ctrl/Cmd+Shift+Z` やり直す、`d` ダッシュボード、`/` 検索欄へ移る、`t` 当日・`b` 基準日・`f` 最初のタスク・`g` 日付を指定・`[` 前の週・`]` 次の週へガントチャートを移す、`?` ショートカットヘルプ、`Ctrl/Cmd++`(`=`・`;` でも可)画面を拡大、`Ctrl/Cmd+-` 縮小、`Ctrl/Cmd+0` 100% に戻す、`ESC` ダイアログを閉じる(プレビュー・ダッシュボードから戻る)。文字キー(`d`・`/`・`?`・`t`・`b`・`f`・`g`・`[`・`]`)と`Ctrl/Cmd+Z`・`Ctrl/Cmd+Shift+Z`は、入力欄にフォーカスがあるときは効かない(入力欄では文字の取り消しになる)。ダイアログが開いているとき、プレビュー・ダッシュボードのあいだは、ESC と拡大・縮小以外は効かない。一覧は`ショートカットヘルプ`に出る
- プレビューとダッシュボードのあいだは、ヘッダーとプロジェクト名を隠す

## git のコミットとプッシュ

- `Git`メニューの`コミット…`で、変更のあるプロジェクトファイル(格納先直下の`*.json`。`config`・`holidays`を除く)を、状態(変更・追加・削除)つきで一覧にし、選んでコミットする(既定はすべて選択)。メッセージは自動の案(`プロジェクトを更新: 甲, 乙`。4 件以上は`甲, 乙, 丙 ほか N 件`)が入り、編集できる。空では確定できない
- ボタンは`コミット`と`コミットしてプッシュ`。コミット済みで未プッシュのときは、`プッシュ`だけもできる。上流のないブランチでは、プッシュは押せない
- コミットは選んだファイルだけ(別に stage されたファイルは入れず、その stage も変えない)。開いているプロジェクトに未保存の編集があるときは、コミットされない(ディスクのファイルが対象)ことを、ダイアログに出す
- プッシュは`git push`(上流へ)。リモートが先に進んでいて拒否されたら、`git`のメッセージに「先にプルが必要です」を添える。認証の入力待ちでは止まらず、失敗にする(認証・`user.name`・`user.email`は各自の環境に任せる)。コミットが成功してプッシュが失敗したときは、そう分かる通知を出す
- 実行中は、新しい実行を始めない。実行のあと、git の状態のチップを自動で読み直す
- ブランチの切り替え・マージ(プルの中のものを除く)は含まない。`fetch`は、プルの中でだけ行う

## git のプルとマージ

- `Git`メニューの`プル`(`Ctrl/Cmd+Shift+L`)で、上流の変更を取り込む。まず`fetch`し、相手が先に進んでいなければ`最新です`と通知する。自分に独自のコミットがなく相手だけが進んでいれば、早送り(`--ff-only`)で進める。両側が進んでいれば、マージする
- プルは、プロジェクトファイルに未コミットの変更があるとき、開いているプロジェクトに未保存の編集があるときは、拒否する(先に保存・コミットする。自分の版は`HEAD`になる)
- マージは`git merge --no-commit --no-ff`を土台にし、両側が変えたプロジェクトファイルだけ、アプリが`id`によるタスク単位の 3 者マージ(共通祖先・自分・相手。`merge.py`)で統合して上書きし、マージコミット(`マージ: <上流>`)まで作る。片側だけが変えたファイルと、プロジェクトファイル以外のファイルは、git に任せる
- 3 者マージは項目ごとに行う。片側だけが変えた値を採り、両側が違う値に変えた項目だけを、画面(ファイルごとのダイアログ)で`自分`か`相手`から選ぶ(既定は`相手`)。担当者・先行・リンク・実績の区間は、リスト全体を 1 項目として比べる。片側が削除し、もう片側が変更したものも、選ぶ(`削除する`か`残す`)。タスク・メンバー・セクション・カテゴリ・イベント・チームは`id`で、パラメータ・URL テンプレートは名前で突き合わせる。メンバーの稼働日の上書きは、メンバーの id と日付で突き合わせ、開始と終了を 1 項目(時間帯)として比べる。メンバーの所属(`teams`)はリスト全体を 1 項目として比べ、消えたチームへの所属は外して割合を 100% に揃えて通知する。同名で id の違うチームは、名前を変えて両方残して通知する。
- 統合のあと、削除されたタスクを指す先行・削除されたメンバーを指す担当者・削除されたカテゴリは外し(担当者とカテゴリは通知に出す)、削除されたセクションにあったタスクはルートへ移す。統合の結果が読み込みの検証を通らなければ、取り込まない
- プロジェクトファイル以外の衝突、ファイル単位の衝突(片側がファイルを削除・両側が新規作成)、衝突ダイアログの中止(ESC を含む)、マージコミットの失敗は、`git merge --abort`で元に戻す。取り込んだら、開いているプロジェクトを読み直し、git の状態のチップを読み直す
- 含まない: 自動プル(定期実行)、リベース、`config.json`のマージ、パラメータ・URL テンプレートの名前変更の追従(`id`を持たないので、削除と追加に見える)、git の merge driver
- `全体の設定`のアイコン(歯車。テーマのメニューの左隣。マウスオーバーは`全体の設定`)を押すと、全プロジェクト共通の設定のダイアログを開く。今の項目は`下部パネルを開くときの割合`のスライダー(ガントチャートの割合 50〜90%・5% 刻み。既定 70%)だけ。動かすとすぐ画面に反映し(下部パネルが開いているとき)、`適用`で`config.json`の`bottom_open_ratio`に保存、`キャンセル`・ESC・外側クリックで開く前に戻す。テーマ・今日の線の色・警告の色・倍率は、テーマのメニューのまま(要望 115 で統合する予定)
