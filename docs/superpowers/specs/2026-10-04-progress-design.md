# 進捗度 設計書

## 目的

実績の区間ごとに進捗度(%)を記録し、ガントチャートの実績の棒に表示する。`.claude/MEMORY.md` の要望1に対応する。

- 進捗度: タスクの開始実績・終了実績に、進捗度を追加する。

実績の入力(`2026-10-04-actuals-design.md`)の続き。進捗率に応じたバーの表現(要望14)の前提になる。

## 範囲

**含む**: `Actual.progress` のデータと保存、タスク編集ダイアログの入力、状態の提案への反映、現在の進捗度を求める関数、実績の棒への進捗度の文字表示。

**含まない**:
- 進捗率に応じたバーの見た目の使い分け、遅延・前倒しの判定(14)
- 状態別のバーの色(12)
- 複数区間の入力と、記録方式の設定(15)
- 予定の経過割合との比較、進捗に基づく再スケジュール
- 進捗度の外部インポートと API(5)

## 決定事項

- 進捗度は、実績の区間ごとに持つ。`Actual.progress`。
- 値は「その区間の終わり時点の、タスク全体に対する累積の進捗」(0〜100 の整数、単位は %)。進行中の区間では「現在の進捗」を表す。
- `None` は未入力。入力は任意で、実績の区間があっても空でよい。
- 区間が複数あるときは、前の区間より小さくならない(累積のため)。今回の画面は 0〜1 区間だけを扱うが、読込では複数区間も検証する。
- タスクの現在の進捗度は、`progress` が入っている区間のうち最後のものの値。ひとつもなければ `None`。
- 古いファイル(`progress` のキーがない)は `None` として読む。移行は要らない。
- 進捗度が 100 でも、状態や実績の終了は自動では変えない。状態の提案だけを調整する。
- 行のコピーは実績ごと空にするので、進捗度も引き継がない(既存の動作のまま)。

## データ(`models.py`、`storage.py`)

```python
@dataclass
class Actual:
    start: datetime
    end: datetime | None = None
    progress: int | None = None  # 区間の終わり時点の累積(0〜100%)。None は未入力
```

定数 `MIN_PROGRESS, MAX_PROGRESS = 0, 100` を `models.py` に置く。

保存形式:

```json
"actuals": [{"start": "2026-10-05T09:00:00", "end": null, "progress": 40}]
```

`progress` は未入力のとき `null`。キーは常に出す。

読込時の検証(不正は「開けませんでした」):
- `progress` は `null`、または 0〜100 の整数。`bool`、小数、文字列は不正。キーがなければ `None`。
- 複数区間のとき、入力のある値は前の入力のある値以上。

## 編集ダイアログ(`task_dialog.py`、検証は `forms.py` の `build_task`)

実績の段(開始・終了)の下に「進捗度(%)」の数値欄を1つ置く。0〜100、空欄可。

入力の規則(`build_task`):
- 数値(整数)でなければエラー(「進捗度は0〜100の整数で入力してください」)。範囲外もエラー。
- 実績の開始が空で進捗度が入っていたらエラー(「開始を入れてください」)。
- 保存時は、区間の `progress` に入れる。空欄は `None`。

閉じるときの確認と、変更の判定(`current()`)には、進捗度の入力値も含める。

### 状態の提案(`suggest_status`)

引数に進捗度を足す。

| 開始 | 終了 | 進捗度 | 提案 |
|---|---|---|---|
| なし | なし | — | 変えない |
| あり | なし | 100 | 変えない(終了が空のまま完了とはみなさない) |
| あり | なし | それ以外 | 実行中 |
| あり | あり | — | 終了 |

(既存の表との差は、「あり・なし・100」を実行中にしない点だけ。ほかは変えない。)

### 2 件以上を読み込んだとき

実績の段全体を読み取り専用にする(進捗度の欄を含む)。保存しても `actuals` は書き換えない。

## ガントチャート(`gantt.py`)

- 実績の棒の中に、`40%` の小さな文字を出す。`progress` が `None` の区間は何も出さない。
- 棒が最小幅(`MIN_BAR_PX`)で文字が入らないときは、棒からはみ出して切れてよい(`overflow: hidden` で隠す)。
- 色・塗りの変更はしない。

## エラー処理

- 進捗度の入力エラーは、実績と同じく入力欄の下に出し、ダイアログを閉じない。
- 読込時の不正は「開けませんでした」の通知。現在のプロジェクトは変えない。

## テスト

- `storage`: 保存と読込の往復、`progress` のない古いファイル、不正値(範囲外・小数・bool・文字列・単調減少)。
- `forms.build_task`: 空、0、100、範囲外、小数・文字列、開始なしの進捗度。
- `suggest_status`: 上の表の全組み合わせ。
- `timeline.current_progress`: 区間なし、未入力、複数区間で最後の入力のあるもの。
- `task_dialog`: 欄の表示と保存、変更の判定、2 件以上で読み取り専用。
- `gantt`: 実績の棒に `40%` が出ること、`None` で出ないこと。
- 2 件以上の実績を持つファイルを、保存しても書き換えないこと。
