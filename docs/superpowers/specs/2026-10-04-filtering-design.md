# 絞り込み(検索・担当者) 設計書

## 目的

ガントチャートのタスクを、タスク名の検索と担当者の選択で絞り込み、タスクが増えても目的のものをすぐ見つけられるようにする。メンバーと割り当て率(`2026-10-03-resources-design.md`)の次の段階。

CLAUDE.md の次の項目に対応する。
- `ガントチャート`の表示は、`タスク`の`アイテム名`にて検索できそのアイテムの一番上を表示できる
- `ガントチャート`の表示は、一人担当に注目するフォーカスや、検索による絞り込みを可能とする

## 範囲

**含む**: 絞り込み条件の判定(純粋関数)、検索入力と担当者選択の UI、一致しない行の非表示、0件の表示、絞り込み変更時のスクロール位置のリセット。

**含まない**(後続のサブプロジェクト、または対象外):
- ドラッグ&ドロップ(行の移動・コピー、バーの横移動)。次のサブプロジェクトで扱う
- 絞り込み条件の保存、あいまい検索、複数の担当者の同時選択、「担当なし」の選択肢
- 一致した文字のハイライト(一致しない行を隠すので不要)
- 絞り込み条件に合わなくなったタスクを、追加・編集の直後に知らせる通知

## 決定事項

- 検索は、タスク名への部分一致。大文字小文字を区別せず、前後の空白は取り除く。
- 検索の確定は **Enter キー**。文字の入力中は反映しない(IME の変換中に絞り込みが走らないようにする)。IME の変換を確定する Enter では確定しない(`isComposing` が真、または `keyCode` が 229 のキー入力は無視する。Safari 系の WebView は変換確定の Enter で `isComposing` が偽になるため、`keyCode` も見る)。入力欄が空になったとき(クリアボタン、文字を全部消したとき)は、Enter なしですぐ条件を外す。担当者の選択は、選んだ時点ですぐ反映する。
- 担当者の指定は、`Task.assignee` との完全一致。担当者が未設定のタスクは、担当者を指定した絞り込みでは隠れる。
- 検索と担当者は AND で絞る。条件が空(検索が空で担当者が未指定)なら、すべて表示する。
- 一致しないタスクの行は描かない。表示するタスクの順序は変えないので、一致した先頭のタスクが自然に一番上に来る。
- 一致するタスクがないセクションは、見出しごと隠す。セクションなしのタスクの「タスク追加」行は、絞り込み中も残す。
- 担当者の選択肢は `project.members` の名前。古いファイルの自由入力の担当者は、読込時にメンバーへ補われる(リソースの設計)ので、メンバー一覧で足りる。
- 絞り込みの状態は `Project` に入れず、保存しない。編集中の判定(`asdict(project)` と `snapshot` の比較)に影響しない。
- プロジェクトを開き直したとき(別のプロジェクトへの切り替えを含む)は、条件を空に戻す。

## 判定(`filtering.py`、NiceGUI に依存しない)

```python
@dataclass(frozen=True)
class TaskFilter:
    query: str = ""
    assignee: str | None = None

    @property
    def active(self) -> bool: ...  # query(前後の空白を除く)が空でない、または assignee が None でない


def matches(task: Task, task_filter: TaskFilter) -> bool: ...
```

- `matches` は、条件が空なら常に `True`。`query` は `strip()` して `casefold()` で比較し、`assignee` は `==` で比較する。
- セクションの表示可否は `gantt.py` が、そのセクションに一致するタスクが1つ以上あるかで決める。

## 画面(`gantt.py`)

- 既存のスケール切替の行に、検索入力(クリアボタン付き、`mark("search-input")`)と担当者の選択(`mark("assignee-filter")`。先頭は「すべての担当者」)を足す。
- `GanttChart` は `task_filter: TaskFilter` を持つ。入力や選択が変わったら `set_filter` で更新して `render.refresh()` する。検索入力は、`keydown.enter` で、入力欄の値を `commit_query` に渡して反映する(`on_change` では、空になったときだけ反映する)。
- `render` は、`enumerate` の元の番号を保ったまま、一致しないタスクを飛ばす。`edit_task(si, ti)` に渡す番号と、行・棒・締切の `mark` の名前は、絞り込みの有無で変わらない。
- 絞り込み中に一致が0件なら、チャート領域に「条件に一致するタスクがありません」(`mark("no-match")`)を出す。プロジェクトにタスクが1つもないときは出さない。
- 割り当て超過(`overallocations`)は、絞り込みの有無にかかわらず、プロジェクト全体で計算する。縞は絞り込みで変わらない。
- 絞り込みを変えたとき、チャートの縦スクロールを先頭に戻す。
- 担当者の選択肢は、`set_project` とメンバーの変更のたびに更新する。選択中の担当者が、メンバーの削除や改名で選択肢になくなったときは、未指定に戻す。

## プロジェクトを開き直したとき(`views.py`)

- `GanttChart.set_project` は条件を保つ(メンバーの変更・設定・タスクの保存でも呼ばれるため)。
- 条件を空に戻す `GanttChart.reset_filter`(入力欄と担当者の選択にも反映して再描画する)を新設し、`open_project` だけが `set_project` のあとに呼ぶ。

## エラー処理

- 検索文字列は表示と比較にだけ使うので、検証や拒否はしない。HTML には埋め込まない。
- 判定に必要な値は `Task.name`(必須)と `Task.assignee` だけで、欠けているときの失敗はない。

## テスト

- `test_filtering.py`: 空の条件、大文字小文字、部分一致、前後の空白、担当者との AND、担当者未設定が担当者の指定で隠れること、`active` の判定。
- `test_gantt.py`: 入力しただけでは絞り込まれず Enter で絞り込まれること、空白だけの Enter は条件なしになること、入力欄が空になるとすぐ条件が外れること、Enter のスクリプトが `isComposing` と `keyCode` 229 を見ていること、一致しない行が描かれないこと、元の番号の `mark` が保たれること、一致のないセクションが隠れること、「タスク追加」行が残ること、0件の表示(タスクがないときは出ない)、絞り込み中も割り当て超過の縞が変わらないこと、担当者の選択肢の更新と、選択肢から消えたときの未指定への戻り。
- `test_views.py`: `open_project` で条件が空に戻ること、メンバー変更・タスクの保存では条件が保たれること。
- 実機確認: 日本語 IME で、変換中と変換確定の Enter では絞り込まれず、確定後の Enter で絞り込まれること、絞り込み後のスクロール位置、ライト・ダークでの見た目。
