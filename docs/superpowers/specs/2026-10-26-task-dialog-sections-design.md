# タスクの追加・編集ダイアログの節の折りたたみの設計(要望 62)

> **状態**: 実装済み(PR #90。実機確認済み)— 要望 62。現在の仕様は [`CLAUDE.md`](../../../CLAUDE.md) を参照。要約は別マーカー(`task-section-{key}-summary`)ではなく、`ui.expansion` の `caption` プロパティに出す。

## 目的

タスクの追加・編集ダイアログは、項目が増えて(担当・パラメータ・先行・リンク・実績・週ごとの担当など)縦に長くなり、扱いにくい。項目を節にまとめて折りたため、よく使う項目だけが見える状態から始められるようにする。

成功の目安は次のとおり。

- 開いた直後に見える項目が減り、必要な節だけを開いて入力できる。
- 閉じた節でも、入っている値が見出しの要約で分かる。
- 節を閉じても、値は保存で失われない(今の「隠した項目の値は保持する」と同じ)。
- 新規と編集で、開いた直後の見え方が自然に違う(新規は基本だけ、編集は値のある節も)。

## 今の仕組み

- 1 枚の縦長ダイアログ(幅 44rem)に、種別・名前・カテゴリ・パラメータ・日付・工数・実績・進捗・状態・担当・先行・優先度・リンク・色が並ぶ。
- タイトルの下の切り替え `task-layout`(`予定・実績` / `すべて`)で、付加的な項目の出し入れをする。選択は `~/.projectapp/config.json` の `task_layout` に保存(既定は `すべて`)。
- 種別(通常・チェックポイント・プロジェクト参照。まとめは編集のみ)ごとに、出す項目を `refresh_visibility` で切り替える。

## 決定

- 方針: **節の折りたたみ**(`ui.expansion`)。タブ・グループ化だけの案は採らない。
- 切り替え `task-layout` は**廃止**し、節ごとの開閉を保存する。

## 節と項目

| 節 | 項目 | 開閉の初期値 |
|---|---|---|
| **基本**(`basic`) | 種別、名前、(参照先)、カテゴリ、開始予定・完了予定・締切、工数と換算の説明、状態 | 常に開く(折りたためない) |
| **担当・パラメータ**(`assignees`) | 担当者と割り当て率(週ごとの担当の説明を含む)、パラメータ | 値があれば開く |
| **実績・進捗**(`actuals`) | 実績(簡易 / 区間)、進捗度 | 値があれば開く |
| **関連**(`related`) | 先行タスク、優先度、リンク、色 | 値があれば開く |

- カテゴリは、名前欄のチップに出る頻度の高い項目なので基本に入れる。
- ダイアログの幅・タイトル・種別のトグル・名前は、今のまま。

## 閉じた節の見出しの要約

閉じているときだけ、見出しの右に要約を出す(開いているときは出さない)。空の節は要約を出さない。

- 担当・パラメータ: `田中 100%・鈴木 50%`(3 人まで。以降は `ほか n 人`)。パラメータがあれば `・パラメータ 2`。
- 実績・進捗: `2区間・進捗 40%`(簡易は `実績あり`)。
- 関連: `先行 2・リンク 1・優先度 高`(0 の項目は省く)。優先度が `中`(既定)なら省く。色があれば `・色`。

## 種別との関係

出し分けは今のロジックを活かし、レイアウトの分岐だけをなくす。

- 通常: 4 つの節すべて。
- チェックポイント: 基本は名前・カテゴリ・締切・状態(`未着手`・`終了`)。担当・パラメータと実績・進捗は出さない。関連は出す。
- プロジェクト参照: 基本は参照先・名前・締切。関連は先行と色だけ。ほかの節は出さない。
- まとめ(編集のみ): 基本は名前とカテゴリ。関連は優先度とリンクだけ。ほかは出さない。
- 節の中の項目が 1 つも出ないときは、節ごと隠す。

## 開閉と保存

- 新規作成: 基本だけ開いて始める。
- 編集: 値のある節を開く(担当者・パラメータがある / 実績か進捗度がある / 先行・リンク・`中` 以外の優先度・色がある)。
- 利用者が節を開閉した状態は、`config.json` の `task_sections`(開いている節のキーのリスト。例 `["assignees", "actuals"]`)に保存する。全プロジェクト共通。保存した状態があれば、「値があれば開く」より優先する。ただし、値のある節が閉じていると見落とすため、編集で値のある節は保存した状態に関わらず開く。
- `task_layout` は、古いファイルに残っていても読み飛ばす(読込を壊さない)。新しくは書かない。
- 不正な `task_sections`(リストでない、未知のキー)は読み飛ばして既定にする。

## 検証エラーと節

保存時の検証エラーが、閉じた節の中の項目にあるときは、その節を開いてからエラーを出す(例: 実績の区間が重なる → 実績・進捗を開く)。エラー文は今のまま `form-error` に出す。

## コード構成

- `task_dialog.py`: 欄を作る処理は変えず、`ui.expansion` で包み直す。`refresh_visibility` は、レイアウトの分岐(`full`)をやめ、種別による出し分けだけにする。`layout`・`on_layout_change` の引数を、`sections: list[str]`・`on_sections_change` に置き換える。
- `task_sections.py`(新規・NiceGUI に依存しない): 節のキー、`initial_open(task, saved)`(開閉の初期値)、`summary(section, task)`(要約の文字列)、`section_of_error(...)`(エラーの項目から節を決める)。
- `config.py`: `task_sections` の読み書き(`task_layout` の読み書きを置き換える)。
- マーカー: 節は `task-section-{key}`、要約は `task-section-{key}-summary`。`task-layout` は廃止する。

## テスト

- 純粋関数: 節ごとの要約、値の有無による初期の開閉、エラーの項目と節の対応。
- ダイアログ: 新規は基本だけ開く / 編集は値のある節が開く / 保存した開閉が使われる(値のある節は開く)/ 節を閉じても値が保存される / 閉じた節のエラーで節が開く / 種別ごとの節の出し分け(チェックポイント・参照・まとめ)/ 閉じた節の要約が見出しに出る。
- 設定: `task_sections` の保存と読込、不正値の読み飛ばし、古い `task_layout` を読んでも落ちない。
- 既存のダイアログのテストで `task-layout` を使うものは、節の開閉に置き換える。

## 見送り

- 節の並べ替え、節ごとのキー操作、ダイアログのサイズ変更。
- 新規と編集で項目そのものを変えること(開閉の初期値だけが違う)。
