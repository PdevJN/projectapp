# タスクの子プロジェクトへの切り出しの設計

> **状態**: 設計(2026-10-31。会話で第 1〜3 節を確認済み。書いた設計書のレビュー待ち)。要望 89。

## 目的

大きなタスクを、独立したプロジェクトファイル(子プロジェクト)に切り出して管理できるようにする。元のタスクは、1 行の`プロジェクト参照`に置き換わり、親のガントチャートから子の進捗が見える。

## 決めたこと(会話で確認済み)

| 項目 | 決定 |
|---|---|
| 目的 | 大きなタスクを子プロジェクトに切り出す。元は`プロジェクト参照`の行になる |
| 対象 | ガントチャートで複数選択したタスク(一括操作の選択)を、まとめて 1 つの子プロジェクトにする。まとめの子だけの選択も可 |
| 引き継ぎ | タスクに関わる分だけ(下の「子プロジェクトの中身」) |
| 境界の先行 | 切り出したタスクを先行にしていた外のタスクは、参照行を先行にする。外を先行にしていた切り出し内のタスクは、先行を外して件数を通知する |
| ファイルの作成 | 確定時に子のファイルをすぐ保存する。親は参照行に置き換えた未保存の編集のまま |
| 方式 | 純関数モジュール`extract.py`(`decompose.py`と同じ作り)+`views.py`の薄い画面処理 |
| TSV の書き出し | 参照行を`(参照) 名前`の行として書く(下の「TSV の書き出し」) |
| ダッシュボード | 変えない(参照行は数えない)。参照行の進捗を載せることは別要望(90) |

## モジュールと流れ

### `extract.py`(新設。NiceGUI に依存しない)

- `selection_error(project, ids)`: 選択が切り出せない理由を返す(なければ`None`)。プロジェクト参照行を含む、タスクが 0 件。
- `name_error(project, name, existing)`: 子のプロジェクト名の不正な理由。空、50 文字超、制御文字、親と同じ名前(自己参照になる)、格納先に同名のファイルがある(`existing`に格納先のプロジェクト名を渡す)。
- `expand_ids(project, ids)`: まとめの子を足して表示順に並べる。
- `check(extraction)`: 子と親を保存・読込と同じ検証に通す。
- `extract(project, ids, name) -> Extraction`: 親を変えずに、`child`(子の`Project`)、`parent`(参照行に置き換えた親の複製)、`reference_id`(置いた参照行の id)、`moved`(移した件数)、`dropped`(外した先行の数。通知用)を返す。

### 画面の流れ(`views.py`)

1. 入口は、選択バーの`子プロジェクトに切り出し…`と、選択した行の右クリックメニュー。プレビュー(読み取り専用)では出さない。Web モードでも使える。
2. プロジェクト名を入力するダイアログ。理由があれば確定できない。
3. 確定で、子と親の両方を保存・読込と同じ検証に通す。通らなければ何も変えない。
4. 子を新規保存する(同名は上書きしない)。失敗したら親は変えず、理由を通知する。
5. 親を置き換える。未保存の編集で、元に戻す 1 ステップ。選択を解除する。
6. 通知: `「基盤」に 5 件を切り出しました。親を保存してください`。外した先行があれば件数を添える。

元に戻すは、親の変更(空になったまとめの復元を含む)だけを戻す。保存済みの子のファイルは残る(通知に添える)。親を保存せずに閉じると、子のファイルだけが残る。

## 子プロジェクトの中身

- **タスク**: 選んだタスクをそのまま移す(名前・工数・担当・実績・進捗・状態・リンク・週ごとの担当など)。まとめを選んだら、子は必ず一緒に移す。まとめの子だけを選んだ場合は、まとめを持ち越さず、その子だけが入る。
- **`id`**: タスク・メンバー・カテゴリ・セクションの`id`を維持する。先行とまとめの子の指定を作り直さずに済み、元との対応も追える。別ファイルなので衝突しない。
- **セクション**: 選んだタスクを含むセクションだけを、同じ階層・同じ順で作る。root のタスクは root に置く。
- **名簿と設定**:
  - メンバー: 担当(週ごとの担当を含む)に入っている人だけ。`teams`(所属)は持ち越さない。
  - パラメータ: 切り出すタスクに、担当者がいて`parameters`が空のもの(相対比率が全パラメータの合計になる)が 1 つでもあれば、全パラメータ。なければ、タスクに付けたものだけ。メンバーの段階の選択も、持ち越したパラメータ分だけ残す。
  - カテゴリ・URL テンプレート: タスクで使っているものだけ。
  - 稼働設定: 稼働可能時間・始業時刻・基準日・実績の記録方式・参照の方式・相対比率の上限と下限・PlantUML の通知。
  - イベント: すべて。
  - チーム: 持ち越さない。
- **先行**: 切り出し内どうしは維持する。外を先行にしていたものは外し、件数を通知する。
- 切り出し内にプロジェクト参照行は入らない(断る条件)ので、子から別の子への参照や循環は生じない。

## 親の置き換え

- 切り出したタスクを取り除き、`プロジェクト参照`の行を 1 つ置く。名前と参照先は、子のプロジェクト名。参照の方式がスナップショットなら、その場で値を取る。
- 位置は、選択の中で表示順が最初のタスクの位置。それがまとめの子なら、参照行はそのまとめの子になり、`children`の中でその子がいた位置に入る。
- ほかのまとめの子を切り出したときは、そのまとめの`children`から外す。空になったまとめは、既存の規則(`revert_empty`)で通常タスクに戻る。
- 切り出したタスクを先行にしていた外のタスクは、先行を参照行へ付け替える。

## 参照行をまとめの子にする(既存の規則の拡張)

ファイル形式は変えない(`version` は 17 のまま)。`children`は文字列のリストとしてしか検証されず、参照行を入れても読み込める。変えるのは、まとめの算出である。参照行は、工数・状態・進捗度を持たないので、参照先の値(`ReferenceValue`)から出す。

| 項目 | 規則 |
|---|---|
| 開始・完了 | 参照先の予定の開始・終了を、子の最小・最大に加える |
| 状態 | 参照先が全部終了なら終了、実績があれば実行中、なければ未着手として数える |
| 進捗度 | 参照先の進捗を使う。重みは 1(工数がないため) |

対象は`summary.py`と、まとめの帯・状態・進捗を出している`gantt.py`。読込の検証、子の先行、折りたたみ、ドラッグ移動、3 者マージ(`children`は`id`で見るだけ)への影響は、計画の段階で洗い出す。

## TSV の書き出し(`csv_export.py`)

これまで書かなかったプロジェクト参照行を、次の形の行として書く。

| 列 | 値 |
|---|---|
| `WBS 番号` | 空 |
| `タスクのタイトル` | `(参照) 名前` |
| `タスクオーナー` | 空 |
| `開始日`・`期限` | 参照先の予定の開始・完了(日付がなければ空)。形は通常タスクと同じ |
| `期間` | 期限 − 開始日の暦日数(通常タスクと同じ) |
| `タスク完了率` | 参照先の進捗。なければ、全部終了なら 100、それ以外は 0 |

- 参照先の値は、PlantUML の出力が参照行を出すときと同じ仕組み(`reference.py`)で読む。参照先が見つからない・読めないときは、日付と完了率を空にして通知する。
- 取り込み側は変えない。`(参照)`付きの行は、通常タスクとして読む(往復で参照行には戻らない)。
- 「書かず、件数を通知する」対象は、まとめとチェックポイントだけになる。

## ダッシュボード

変えない。プロジェクト参照行は、どのカードでも数えない(今のまま)。

- 切り出すと、親の`進捗と遅れ`・円グラフ・`工数の予定と実績`などから、切り出した分が消える(子を開けば見える)。
- `全プロジェクト`の負荷は、子のタスクを同名のメンバーで重ねるので、子を重ねれば切り出す前と同じになる。参照行は数えないので、二重には数えない。
- 参照行の進捗・工数を親のダッシュボードに載せることは、要望 90 として別に扱う。

| 新規 | `extract.py` | 切り出しの純関数 |
