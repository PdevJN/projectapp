# タスクの分解の設計(要望 33)

> **状態**: 実装済み — 要望 33 — `feature/task-decompose`(マージ待ち)。当時の記録で、現在の仕様は [`CLAUDE.md`](../../../CLAUDE.md) を正とする。

## 目的

1 つのタスクを、複数のタスクに割れるようにする。割ったあとの元のタスクは「まとめ」として残し、分解したタスクを新しいセクションにまとめるかどうかを選べる。
成功の目安は次のとおり。

- タスクの行のメニューか編集ダイアログから、名前と工数の行を足して分解できる。
- 元のタスクが「まとめ」になり、期間・工数・進捗が、子から算出されて表示される(工数や実績を二重に数えない)。
- 分解は、`Ctrl/Cmd+Z` の 1 回で元に戻る。

「分解」は、1 つのタスクを複数のタスクに割ること。既存のタスクを別のセクションへ振り分けることではない(2026-10-11 に確認済み)。

## 決めたこと

| 項目 | 決定 |
| --- | --- |
| 元のタスク | 新種別`まとめ`として残す |
| 入力 | 名前と工数の行を足す。工数の初期値は元の工数の均等割り。合計が元と違えば警告(確定はできる) |
| 新しいセクション | オプション`新しいセクションにまとめる`(既定はオフ)。元のセクションのサブセクション(名前は元のタスク名)に子を入れる。まとめは元の場所に残す |
| 入れられないとき | 元が root にあるとき、元のセクションがすでに 3 階層目のときは、オプションを無効にして理由を出す |
| 入口 | 編集ダイアログの`分解…`ボタン(ガントチャートに行のメニューはない。保存済みの通常タスクで、実績がないときだけ。編集中の内容があるときは、先に保存を促す) |
| 元に戻す | 分解全体で 1 ステップ |
| まとめの折りたたみ | まとめの行の矢印か名前のクリックで、子の行をまとめて隠す・出す |

次の 3 点は、推奨の既定として置いた(レビューで変えてよい)。

- 実績のあるタスクは、分解を拒否する(履歴を偽らないため)。状態が未着手以外・進捗度のあるタスクも拒否する(分解で失われるため)。まとめの子も拒否する(入れ子にしない)。
- 締切は、最後の子に引き継ぐ。手指定の完了予定は、子に持たせない。
- 子の間は、順に先行で連結する(`順に連結する`チェック、既定はオン)。オフのときは、すべての子が元の先行を引き継ぐ。

## モデル

- `TaskKind.SUMMARY = "まとめ"`を足す。`Task.children: list[str]`(子のタスク id)を持つ。
- まとめは、開始予定・完了予定・工数・実績・進捗・担当を**保存しない**。表示のたびに子から算出する。
  - 開始 = 子の実効開始の最小、完了 = 子の完了の最大、工数 = 子の合計、実績 = 子の区間の範囲。
  - 進捗 = 工数で重みづけした子の進捗。状態 = 全員が終了なら`終了`、1 つでも着手済みなら`実行中`、それ以外は`未着手`。
- まとめの編集ダイアログは、名前・カテゴリ・優先度・リンクだけを出す(チェックポイントと同様に項目を絞る)。
- 子が 0 件になったまとめは、通常タスクに戻す。
- ファイルの`version`は 6。キーのない古いファイルは既定値(`children`なし)で読む。不正な値(存在しない id・自分自身・循環)は読込を拒否する。

## 分解の計算(`decompose.py`。NiceGUI に依存しない純粋関数)

入力は元のタスクと`[(名前, 工数)]`の行。出力は、まとめにした元のタスクと、子のタスク。

- 子には、元の担当者・カテゴリ・優先度・色・リンク・開始予定を引き継ぐ。実績・進捗は引き継がない。
- 先行・後続の付け替え:
  - 元の先行は、最初の子の先行にする。
  - 元を先行にしていた後続は、まとめを先行にし直す(まとめの完了は子の最大)。
  - `連結する`がオンなら、子の間を順に連結する。
- 元に実績があるときは、分解を拒否する。

## セクション

- オプションがオンのとき、元のセクションの末尾にサブセクション(名前は元のタスク名)を足し、子をそこへ入れる。まとめは元の場所に残す。
- 同名のサブセクションがすでにあるときは、足さずに`名前#2`とする。
- 絞り込み・折りたたみの規則は、サブセクションの既存の仕様に従う。

## まとめの折りたたみ

セクションの折りたたみ(要望 19)に合わせる。

- まとめの行の先頭に矢印を出す。矢印か名前のクリックで、子の行を隠す・出す。既定は開いた状態。
- 隠すのは行の表示だけで、子はセクションに残る。まとめと子が別のセクションにあるとき(`新しいセクションにまとめる`がオン)も、子の行を隠す。
- 折りたたんだまとめには、子の件数をチップで添える(`3件`)。帯は、子の期間を覆う細い帯のまま出す。
- 絞り込み中は、折りたたみを無視して、一致した子を出す。一致した子がいるまとめも出す(親のセクションと同じ扱い)。
- 先行の矢印は、子の行が隠れたとき出さない(既存の規則)。まとめを先行・後続にした矢印は、まとめの行から出す。
- 折りたたみの状態は保存しない。元に戻す・やり直しの対象にしない。
- 子が 0 件のまとめ(通常タスクに戻る)には、矢印を出さない。

## まとめの見た目

モックアップで確認済み(2026-10-18)。

| 項目 | 通常タスク | まとめ |
| --- | --- | --- |
| 棒 | 状態の色の太い棒(高さ 20px) | 状態の色の細い帯(高さ 9px)と、両端の下向きの三角 |
| 進捗 | 棒の中を暗く塗る | 帯の中を暗く塗る(子の重みづけ進捗) |
| 名前の欄 | 通常の太さ | 太字。先頭に折りたたみの矢印。子は一段インデント |
| チップ | カテゴリ・担当者・進捗 | カテゴリ・進捗。担当者はなし。折りたたみ中は件数(`3件`) |
| 超過の表示 | 縞・赤み | なし(子に出る) |

優先度の背景色(名前の欄)は、まとめにも付ける。

## 他の機能への影響

| 機能 | 扱い |
| --- | --- |
| ガントチャート | まとめは、子の期間を覆う細い帯で描く(見た目は「まとめの見た目」の節)。プレビュー・画像にも同じ帯が出る。折りたたみの状態はプレビューの表示にも使うが、画像の書き出しでは現在の状態のまま出す |
| 日程計算 | まとめを先行にした後続は、まとめの完了(子の最大)で押し出される |
| 割り当て超過の縞 | まとめは数えない(子が数える) |
| ダッシュボード | まとめを工数・進捗・負荷の集計から外す(二重計上を避ける)。期限は子のものを数える |
| 担当者へ書き出し | まとめは書き出さない(担当がないため) |
| PlantUML の出力 | 下記 |
| PlantUML の取り込み | まとめは作らない。出力した区切りは、通常のセクションとして読み戻す |
| 3 者マージ | `children`はリスト全体を 1 項目として比べる。削除された子は、`children`から外す |

### PlantUML の出力

- まとめは**帯を出さず**、`skipped`にも数えない。PlantUML には親子の構文がなく、帯を出すと子と二重になるため。
- 新しいセクションにまとめた分解は、サブセクションが`-- 親 / 子 --`の区切りとして出る。オフの分解は、子が並ぶだけで、まとめは出力から消える。
- まとめを先行にしていた後続の矢印は、まとめの子のうち**完了が最も遅いもの**から引き直す。子が出力されないとき(期間の外など)は、矢印を出さない。矢印は日付固定の添え物なので、見た目への影響は小さい。

## テスト

- 純粋関数: 均等割り・工数の合計が違う場合・先行/後続の付け替え・連結あり/なし・実績ありの拒否・root と 3 階層目でのセクション。
- 算出: まとめの期間・工数・進捗・状態。子の削除で通常タスクに戻ること。
- 保存・読込: `version` 6、古いファイルの読込、不正な`children`の拒否。
- 連携: ダッシュボードで二重計上がないこと、PlantUML の出力と矢印の引き直し、担当者への書き出しで除外されること、3 者マージ。
- 折りたたみ: 子の行が隠れること、別セクションの子も隠れること、絞り込み中は無視すること、件数のチップ。
- UI: 分解ダイアログ、行のメニュー、ガントチャートの帯、1 回の元に戻すで戻ること。

## 含まない

- 分解したタスクを、まとめへ戻す操作(統合)。
- 担当者・日付の、分解ダイアログでの行ごとの指定。
- まとめを、別のまとめの子にする入れ子(1 段のみ)。

## 実装で決めたこと(後の変更)

- まとめをコピーすると、子を持たない通常タスクになる。まとめを削除すると、子は通常タスクとして残る。子を削除すると、まとめの`children`から外れ、0 件になったまとめは通常タスクに戻る。
- 子の先行にその親のまとめは指定できない(循環)。読込・マージでは循環として拒否し、編集ダイアログの候補からは外す。
- 絞り込み中は、自分の名前が合うか、子のどれかが合うまとめを出す。
- 分解ダイアログの工数は小数点以下 2 桁まで(`forms.HOURS_DECIMALS`と同じ。`decompose.EFFORT_DECIMALS`は NiceGUI に依存しないよう別に持つ)。
