# タスクの週ごとの担当割り当ての設計(要望 54)

> **状態**: 設計(2026-10-24)— 要望 54 — `feature/weekly-crew`。未実装。

## 目的

担当者は今、`Task.assignees`(メンバーと割り当て率のリスト)で、タスクの全期間に一律で適用される。1 つのタスクの中で、週ごとに担当者の組み合わせを変えられるようにしたい。例(3 人で割り当てる場合):

| 週 | 担当 |
| --- | --- |
| 第1週 | A |
| 第2週 | A, B |
| 第3週 | B, C |
| 第4週 | A, B, C |
| 第5週 | A |

成功の目安は次のとおり。

- 上の例を、編集ダイアログで 5 週ぶん入力でき、ガントチャートの棒の上で週ごとの担当が読める。
- 完了予定は、工数を週ごとの換算率で消化して算出する。人数の多い週は早く進み、少ない週は遅く進む。
- 週ごとに分けないタスクと、キーのない古いファイルは、今までどおり動く(完了予定も変わらない)。

## 決めたこと(2026-10-24 に確認済み)

| 項目 | 決定 |
| --- | --- |
| 完了予定との関係 | 工数を週ごとの換算率(その週の担当者の `相対比率 × 割り当て率` の合計)で消化して算出する |
| 週の数え方 | 実際の開始(先行による押し出しを反映)の日から 7 日(暦日)ごとに、第1週・第2週…とする |
| 最後の週より後 | 最後の週の担当をそのまま続ける |
| 既存の担当との関係 | 追加機能。タスクごとに「週ごとに分ける」を選ぶ。オフのタスクは今のまま |
| 各週の担当者 | 最低 1 人(担当なしの週は作れない)。同じ週に同じメンバーは 1 回まで。週ごとに割り当て率(1〜100%)を持つ |
| 表示 | 名前の欄のチップは今までどおり和集合で出し、あわせて棒の上に週ごとのチップを出す |
| 担当の付け替え時の見直し(要望 32) | 週ごとのタスクは対象外 |
| タスクの分解 | 週ごとのタスクは分解できない |
| PlantUML | 近似で出す(和集合の担当者・各人の最大の割り当て率)。通知する |

## データ(`models.py`・`storage.py`・`merge.py`)

- `Task.weekly_crew: list[list[Assignee]]`(既定は空)。添字が週(0 番目が第1週)。空は「週ごとに分けない」で、`assignees` をそのまま使う。通常タスクだけが持つ(まとめ・チェックポイントは持たない。読込で空にする)。
- 週ごとに分けるタスクでも `assignees` は残し、**全週の担当者の和集合**(重複なし、初出の順。割り当て率は各人の最大値)に保つ。名前の欄のチップ・絞り込み・マージ・書き出しなど、時間を問わない箇所は `assignees` を読む。保存・読込のときに和集合へ整える(ファイルの `assignees` が和集合とずれていても、`weekly_crew` を正とする)。
- 保存は `tasks[].weekly_crew`(週の配列。各週は担当者の配列で、担当者はメンバーの `id` と `allocation`。`assignees` の保存と同じ形)。`FORMAT_VERSION` を 9 から 10 に上げる。キーのない古いファイルは空として読み(移行は要らない)、型が不正・週に担当者がいない・同じ週にメンバーが重複・存在しないメンバーの `id`・割り当て率が範囲外なら、読込を拒否する。
- 3 者マージ: `weekly_crew` はリスト全体を 1 項目として比べる(担当者・先行・リンクと同じ)。項目名の表(`merge.py` の日本語名)に`週ごとの担当`を足す。統合のあと、削除されたメンバーを指す担当者は外す(今の担当者と同じ)。外した結果、ある週の担当者が 0 人になるときは、その週を前の週(なければ次の週)と同じ担当にして通知する。すべての週が 0 人になるときは、週ごとの設定を外して `assignees` に戻す。

## 計算(`timeline.py`・`ratios.py`)

- 「ある日時の担当者」を返す純粋関数 `crew_on(task, day, start)` を足す。`weekly_crew` が空なら `task.assignees`。そうでなければ、`(day − start).days // 7` を週の添字とし、定義した週を超えたら最後の週を返す。`start` は実効の開始(先行の押し出しを反映した日)。
- `computed_end` は、日ごとに `crew_on` の担当者で稼働の枠を時刻で重ね、換算率の合計で工数を消化する(今のロジックの担当者の取り方だけを日ごとにする)。相対比率はパラメータを反映した値(`conversion_rate` の `only` の扱いは要望 51 のまま)。担当者のいないタスクの通常カレンダーの扱いは変えない。
- 押し出しで開始が変わったときは、変わった開始から週を数え直す(算出は表示のたびに行うので、追加の保存はない)。
- `overallocations`(割り当て超過)・ダッシュボードの負荷と予定工数・`handoff.py` の見積もりは、`crew_on` を通して日ごと(または週ごと)の担当者を得る。
  - 割り当て超過: 週の区間ごとに、その週の割り当て率で数える。縞はその区間だけに出る。
  - ダッシュボード: 予定工数と負荷は、日ごとの担当者と割り当て率で数える。
  - 担当者向けファイル: そのメンバーが各日に消化する工数を合計し、自分の相対比率で割った自分の時間を見積もりにする(担当が全期間に一律のタスクは、今の式と同じ値になる)。

## ダイアログ(`task_dialog.py`)

- `すべて`レイアウトの担当欄に、`週ごとに分ける`のスイッチを足す。オフが既定で、今の画面と同じ。`予定・実績`レイアウトでは隠し、値は保持する。
- オンにすると、`第N週`の行を縦に並べる。各行に、その週の担当者(メンバー選択と割り当て率。今の担当行と同じ部品)を置き、`週を追加`・`この週を削除`のボタンを付ける。追加する週の初期値は直前の週のコピー。オンにした直後は、現在の担当を第1週に入れる。オフに戻すと、第1週の担当を `assignees` に戻し、週の設定は捨てる。
- 保存の検証: 各週に担当者が最低 1 人。同じ週のメンバーの重複はエラー(今の担当と同じ文言の形式)。
- 換算率の内訳と日数換算は、週ごとに出す。例: `第2週: A 100%×100% + B 110%×50% = 155% → …`。最後の週は`第5週以降`と表す。
- 週ごとに分けるタスクでは、`分解…`は押せない(ヒントに理由を出す)。担当の付け替えの見直し確認(要望 32)は出さない。

## ガントチャートの表示(`gantt.py`・`preview.py`)

- 名前の欄のチップは今までどおり(`assignees` の和集合。ホバーに、週ごとの割り当て「第1週: A / 第2週: A, B…」を添える)。
- 棒の上に、週ごとのチップを重ねる。棒を 7 日ごとに区切り(実効の開始から。最後の週は、棒の右端まで)、各区間の上端寄りに、その週の担当者の頭文字を小さく並べる(4 人目以降は`+n`)。区間が狭くて入らないときは、頭文字を省き、区切りの目盛りだけにする。ホバーに、その週の担当者と割り当て率を出す。
- 日次では頭文字つき、週次・月次では区間が狭いので区切りだけ(ホバーは同じ)。
- 進捗の塗り・縞(割り当て超過)・締切の目印は今のまま。チップは操作を受けない(行・バーのクリックと同じ扱い)。
- プレビュー・画像に出す。プレビューの表示項目の`チップ`(担当者)のオンオフに従う。

## 周辺の挙動

- タスクのコピー・セクションのコピーは、`weekly_crew` も複製する。タスクのまとめの子・先行の扱いは変えない。
- 担当の付け替えの見直し(要望 32): `weekly_crew` を持つタスクは、確認を出さない(`reassign.py` で対象外にする)。完了予定は自動算出のままで、週の設定の変更にすぐ追従する。進捗のある週ごとのタスクの見直しは、後続の要望とする。
- タスクの分解: 週ごとのタスクは分解できない(`decompose.py` の分解できる条件に足す)。
- PlantUML の出力: 担当構文は、和集合の担当者を、各人の最大の割り当て率で出す。週ごとのタスクが 1 件でもあれば、保存のあとに`週ごとの担当は近似で出力しました(n 件)`と通知する。
- PlantUML の取り込み・担当者向けファイルの形式(`todos.json`)は、独自のキーを足さない。
- 元に戻す・やり直しの対象(タスクの編集の一部)。

## テスト

- `timeline`: `crew_on`(週の境界・最後の週より後・押し出し後の数え直し・空)。`computed_end` が例の 5 週で期待の日になること。担当が一律のタスクの完了予定が変わらないこと。
- `overallocations`・ダッシュボード・`handoff`: 週ごとの値。一律のタスクでは今と同じ。
- `storage`: 往復、`version` 10、キーのない古いファイル、不正(担当者 0 人の週・重複・存在しない id・範囲外)、`assignees` が和集合に整うこと、まとめ・チェックポイントの空。
- `merge`: 片側だけの変更・両側の衝突・メンバー削除で週が空になる場合・項目名。
- `task_dialog`: スイッチのオン・オフ、週の追加・削除、初期値、検証、換算率の内訳、`予定・実績`レイアウトでの値の保持、分解が押せないこと。
- `gantt`/`preview`: 棒の上のチップの区間と頭文字・`+n`・スケールごとの省略。
- `reassign`・`decompose`・`plantuml`: 対象外・不可・近似の通知。
- 全体のテストが通ること。実機確認はユーザーが行う。

## 含めないこと

- 担当なしの週(休止)。
- カレンダーの週(月曜始まり)での区切り。
- 進捗のある週ごとのタスクの、担当付け替え時の見直し。
- 週ごとの担当の PlantUML への正確な出力。
- ドラッグで週の担当を変える操作。
