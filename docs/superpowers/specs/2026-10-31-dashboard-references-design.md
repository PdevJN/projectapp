# ダッシュボードのプロジェクト参照行の進捗の設計

> **状態**: 完了(PR #135。実機確認済み。2026-10-31)。計画 [`plans/2026-10-31-dashboard-references.md`](../plans/2026-10-31-dashboard-references.md) — 要望 90。現在の仕様は [`CLAUDE.md`](../../../CLAUDE.md) に反映済み。

## 目的

タスクを子プロジェクトに切り出しても(要望 89)、親のダッシュボードの `チーム全体の進捗` と `進捗と遅れ` の数字が、切り出す前とほぼ同じになるようにする。今は参照行をどのカードでも数えないので、切り出すと親の進捗率・件数・遅れが減る。

## 決めたこと(会話で確認済み)

| 項目 | 決定 |
|---|---|
| 目的 | 切り出し前と同じ進捗の数字を戻す(進捗系のカード中心) |
| 数え方 | 参照先の通常タスクと節目を、親のタスクと同列に展開して数える(参照行そのものは数えない) |
| 対象のカード | `チーム全体の進捗`(円グラフ)と `進捗と遅れ`(進捗率・状態別の件数・予定超過の一覧・`メンバー別`・`チーム別`) |
| 対象外 | `人ごとの負荷`・`工数の予定と実績`・`残りの工数と必要人数`・`期限とマイルストーン`・`全プロジェクト`(負荷は `全プロジェクト` で重ねれば戻る) |
| スナップショット方式 | ダッシュボードは方式に関わらず、参照先のファイルを読んで展開する。保存形式は変えない(`version` 据え置き) |

## データの流れ

- `ReferenceResolver` に `project(name, now)` を足す。参照先の `Project` を返し、内容のハッシュと日付が同じ間はキャッシュする(`live` と同じ鍵)。見つからない・読めないときは `None` を返し、そのファイルは数えない(開いたときの通知で足りる)。
- 画面側(`views.py` の `refresh_dashboard`。参照先は `reference.load_children` が読む)が、開いているプロジェクトの参照行から参照先名を集め(重複は 1 回)、`children: Mapping[str, ChildProject]`(参照先の `Project` と、参照先自身のイベントを反映した休み)を作って `summarize` に渡す。`summarize` は NiceGUI にも読み込みにも依存しない。
- 集計の内部は、タスクだけでなく `Entry(task, project, schedule)` の組を扱う。期間の判定(`_touches`)と予定超過の判定(`is_overdue`)は、各タスクの属するプロジェクト自身の稼働設定・祝日・イベントで行う(祝日は `effective_holidays(project, holidays)`)。
- 参照先の中の参照行は展開しない(1 段のみ。循環を避ける。`reference.COUNTED_KINDS` と同じ規則)。まとめは従来どおり数えない。
- 同じ参照先を 2 つの参照行が指していても、1 回だけ数える。

## メンバーとチーム

- 参照先のメンバーは、名前で親のメンバーに当てる。`メンバー別`・`チーム別` の行と、プルダウンの絞り込みの両方がこの規則に従う。
- 親にいない名前だけが担当のタスク、担当なしのタスクは `未割り当て` に数える(`メンバー別`)。
- チームの所属の割合は、従来どおり親の名簿で掛ける。

## 表示

- `予定超過の一覧` の行は、参照先のタスクなら `タスク名(参照先名)` と出す。
- 円グラフの凡例のホバーのチップも、参照先のタスクは `タスク名(参照先名)`。
- 2 つのカードの対象を示す行に、参照先を数えたとき `参照先 n 件を含む`(n は数えた参照先のプロジェクト数)を足す。

## テスト

- 切り出し前と後で、進捗率・状態別の件数・状態別の工数が一致する(`extract.extract` で実際に切り出した結果で比べる)。
- 期間(`今週`)の判定が参照先自身の日程で行われる。
- メンバーとチームの絞り込み、名前の当てはめ、`未割り当て`。
- 読めない・見つからない参照先は数えない。同じ参照先の重複は 1 回。参照先の中の参照行は展開しない。
- 画面側は `children` の組み立てと、`参照先 n 件を含む` の表示。

## 含めないもの

- 負荷・工数・残りの工数・期限への反映(必要なら別要望)。
- `全プロジェクト` との関係(そのまま)。
- スナップショットにタスクごとの要約を保存すること(方式の意味より、実装の軽さを取った。ダッシュボードは常に最新を読む)。
