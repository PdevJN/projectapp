# 実績の入力 設計書

## 目的

タスクを実際に作業した日時(実績)を記録し、予定との差をガントチャートで見えるようにする。CLAUDE.md の次の項目に対応する。

- `開始`・`終了`は、実際に作業した日時(実績)のために空けた名前で、実績の入力は後続機能とする
- `予定`と`実績`管理ができ、完了予定は、見積もりの日程が予定として登録ができる(実績は後続機能)

ドラッグ&ドロップ(`2026-10-04-drag-and-drop-design.md`)の次の段階。

## 範囲

**含む**: `Actual` のデータと保存、タスク編集ダイアログの実績の入力、状態の提案、実績に基づく超過判定、ガントチャートでの実績の棒と予定の棒の半透明化。

**含まない**(後続の要望。`.claude/MEMORY.md` の「今後の要望」の番号):
- 進捗度(1)と、その棒への表現(14)
- 状態別のバーの色(12)
- 複数区間の入力と、記録方式(簡易/区間)の設定(15)
- ボタンで現在時刻を記録する入力
- 実績の外部インポートと API(5)
- 実績の合計時間の表示、実績に基づく再スケジュール

## 決定事項

- 実績は、方式にかかわらず「区間(開始〜終了)のリスト」で保存する。今回の画面は 0 件か 1 件だけを扱う。区間のリストで持つので、複数区間を足しても保存形式の移行は要らない。
- 区間は `Actual(start, end)`。`end` が `None` のときは進行中。`start` は必須で、開始なしの終了だけは持てない。
- 実績は実際の時刻なので、日付と時刻を両方入力する。予定のような「時刻を指定」のチェックと、補う時刻はない。
- タイムゾーン付きの日時は拒否する(予定と同じ)。`end ≥ start`。
- 古いファイル(`actuals` のキーがない)は、実績なしとして読む。移行は要らない。
- 入力方法は、タスク編集ダイアログの入力欄だけ。ボタンで現在時刻を記録する入力はしない。
- 状態(`Status`)は手で選ぶ値のまま。実績の入力に応じて、ダイアログ上で提案する(後述)。
- 超過判定は、実績の終了があればその時刻で行う。遅れて終わったタスクは赤いまま残る。
- ドラッグでの棒の横移動は予定だけを動かし、実績は動かさない。行のコピーは実績をコピーしない。

## データ(`models.py`、`storage.py`)

```python
@dataclass
class Actual:
    start: datetime
    end: datetime | None = None  # None は進行中

class Task:
    ...
    actuals: list[Actual] = field(default_factory=list)
```

保存形式:

```json
"actuals": [{"start": "2026-10-05T09:00:00", "end": "2026-10-05T17:30:00"}]
```

`end` は進行中のとき `null`。`actuals` が空のときも、キーは出す。

読込時の検証(不正は「開けませんでした」。既存の `load-validation` の方針に合わせる):
- `actuals` はリスト。各要素は `start`(必須。ISO 形式の日時)と `end`(`null` か ISO 形式の日時)を持つ。
- タイムゾーン付きは不正。`end` が `start` より前は不正。
- 今回の画面は 1 件までだが、読込は複数件を受け付ける(将来の複数区間のため)。2 件以上のときの画面の扱いは、後述の「2 件以上を読み込んだとき」に従う。

## 編集ダイアログ(`task_dialog.py`、検証は `forms.py` の `build_task`)

予定(開始予定・完了予定、締切と工数)の下に「実績」の段を足し、開始と終了を横並びで置く。日付(テキスト + `ui.date` のダイアログ)と時刻(テキスト + `ui.time` のダイアログ)は、予定と同じ部品を使う。

入力の規則(`build_task`):
- 開始・終了とも、日付と時刻のどちらかだけを入れたらエラー(「日付と時刻を両方入れてください」)。
- 開始が空で終了が入っていたらエラー(「開始を入れてください」)。
- 終了が開始より前ならエラー。
- 開始・終了とも空なら、実績なし(`actuals = []`)。開始だけなら進行中(`end = None`)。
- 保存時は、`actuals` を `[Actual(start, end)]` か `[]` に置き換える。

閉じるときの確認と、変更の判定(`current()`)には、実績の入力値も含める。

### 状態の提案

実績の入力が変わるたびに、状態のチップを次のように切り替えて見せる(純粋関数 `suggest_status(start, end)` に切り出す)。

| 開始 | 終了 | 提案 |
|---|---|---|
| なし | なし | 変えない |
| あり | なし | 実行中 |
| あり | あり | 終了 |

- 「一時停止」は提案しない。
- ユーザーが状態を手で選び直したあとは、そのダイアログを閉じるまで提案しない。
- 提案で状態が変わったときは、チップの近くに「実績に合わせて状態を変えました」の案内を出す(手で直せる)。
- 保存するまでは、タスクの `status` は変わらない。

### 2 件以上を読み込んだとき

ファイルに実績が 2 件以上あるタスクは、ダイアログの実績の段を読み取り専用にして「複数の区間があるため、このバージョンでは編集できません」と出す。保存しても、実績は書き換えない(要望 15 で編集できるようにするまでの安全策)。

## 超過判定(`timeline.py` の `is_overdue`)

```text
実績の終了がある  → その時刻が、締切か完了予定を過ぎていれば超過
実績の終了がない  → 従来どおり(状態が「終了」なら超過でない。それ以外は now と比べる)
```

- 実績が複数あるときは、最後の区間の終了を使う(終了のない区間があれば、実績の終了はなしとして扱う)。
- 「終了」の状態で実績の終了がないタスクは、従来どおり超過でない。

## ガントチャート(`gantt.py`)

- 予定の棒を半透明にする(濃度 40% 前後。定数にする)。
- 実績の棒は、同じ行の予定の棒の下半分の高さに、不透明で重ねる。色はタスクの色。
- 進行中(`end = None`)は、現在時刻までを実績の棒にする。現在時刻が開始より前なら、最小幅(`MIN_BAR_PX`)の細い棒で出す。
- 日次・週次・月次のどれでも、予定の棒と同じ位置計算(`timeline.py`)を使う。
- 割り当て超過の縞は、予定の棒に残す。半透明にしても見分けられるかは、実機で確認し、必要なら濃度か縞の色を調整する。
- 予定超過の行の赤い背景は、実績の有無にかかわらず、`is_overdue` の結果で決める。
- 実績の棒は、クリックでタスク編集ダイアログを開く(予定の棒と同じ)。ドラッグはできない。
- 絞り込み中は、一致した行の実績の棒も同じように出す。

## 既存機能との関係(`arrange.py`、`gantt_drag.py`)

- `copy_task`: コピー先の `actuals` は空にする(`predecessors` を空にするのと同じ扱い)。
- `shift_task`: `planned_start` など予定だけを動かす。`actuals` は変えない。
- `move_task`: 実績は変えない。

## エラー処理

- 実績の入力エラーは、予定と同じく、入力欄の下に出してダイアログを閉じない。
- 読込時の不正は「開けませんでした」の通知。現在のプロジェクトは変えない。

## テスト

- `storage`: 保存と読込の往復、`actuals` のない古いファイル、不正なファイル(`start` なし、`end < start`、タイムゾーン付き、リストでない)。
- `forms.build_task`: 空、開始だけ、開始と終了、日付だけ・時刻だけ、開始なしの終了、終了が開始より前、タイムゾーン付き。
- `suggest_status`: 上の表の 3 通り。
- `timeline.is_overdue`: 実績の終了が締切の前・後、終了なしで状態が「終了」、終了なしで現在時刻が予定を過ぎた場合、実績の終了があって現在時刻が予定を過ぎた場合。
- `gantt`: 実績の棒が出ること、進行中の棒が現在時刻まで伸びること、予定の棒が半透明であること。
- `arrange.copy_task` で実績が空になること。`shift_task` で実績が変わらないこと。
- 2 件以上の実績を持つファイルを、保存しても書き換えないこと。

## 影響するファイル

- `models.py`: `Actual`、`Task.actuals`
- `storage.py`: 保存と読込、検証
- `forms.py`: `build_task` の実績の検証、`suggest_status`
- `task_dialog.py`: 実績の段、状態の提案、変更の判定
- `timeline.py`: `is_overdue`
- `gantt.py`: 実績の棒、予定の棒の半透明化
- `arrange.py`: `copy_task`
- `docs/development.md`: 実績の保存形式と、古いファイルの扱い
