# 開始予定・完了予定・締切 設計書

## 目的

タスクの日付の意味を整理する。いまの「開始」「終了」は、予定の日程を表している。これを「開始予定」「完了予定」に改め、新たに「締切」(納期)を設定できるようにする。「開始」「終了」の名前は、実際に作業した日時(実績)のために空ける。

完了予定は、工数があれば開始予定・工数・稼働設定・祝日から、その都度計算する。保存した終了が、稼働設定や祝日の変更で古くなる問題を、構造ごとなくす。

## 範囲

**含む**: 項目の改名と追加(開始予定・完了予定・締切)、完了予定の決め方(`effective_end`)、予定超過の判定の変更、古いファイルの読み込み、編集ダイアログの並びと切り替え、ガントの棒と締切の目印、再計算まわり(`end_auto`、`fill_end`、`recalc_ends`)の削除、用語と文書の更新。

**含まない**(後続のサブプロジェクト):
- 実績の開始・終了(`CLAUDE.md` の後続機能に、別の項目として書く)と、実績に基づく超過判定
- 締切の通知、締切による並び替えや絞り込み
- 完了予定と締切の色分け(予定超過は1色のまま)

## 決定事項

- 完了予定は**保存せず、その都度計算する**値を基本にする。手で指定するときだけ、値を保存する。
- 工数がないタスクの完了予定は、直接編集できる。工数があるタスクは、算出値を読み取り専用で表示し、「手で指定」をオンにすると編集できる。
- 完了予定が空欄のとき(手入力もなく、工数からも算出できないとき)は、**締切があれば締切**、なければ**開始予定の1日後**(同じ時刻)にする。締切が開始予定より前でも、そのまま締切を使う(遅れている状態が見える)。
- 予定超過(赤い行)は、状態が「終了」でないタスクが、**締切か完了予定のどちらかを過ぎた**とき。色は今までの1色。
- 古いファイルの手入力の終了は、**締切**にする(依頼どおり「今までの終了時刻は締切時刻」)。自動算出の終了は捨てる。
- 実績の「開始」「終了」は、今回は項目を持たない。

## データ

`Task`(`models.py`):

| 項目 | 型 | 意味 |
|---|---|---|
| `planned_start` | `datetime \| None` | 開始予定(旧 `start`) |
| `planned_end` | `datetime \| None` | 完了予定の手入力値 |
| `planned_end_manual` | `bool` | 工数があるときに、完了予定を手で指定するか |
| `deadline` | `datetime \| None` | 締切(新規) |

`end` と `end_auto` は削除する。

### 完了予定(`effective_end`)

`timeline.py` の純粋関数 `effective_end(task, project, holidays) -> datetime | None`。上から順に当てはめる。

1. 工数が 0 以下で、`planned_end` があれば、`planned_end`。
2. 工数が 0 より大きく、`planned_end_manual` がオンで、`planned_end` があれば、`planned_end`。
3. 工数が 0 より大きく、開始予定があり、`calc_end` が値を返せば、その値。
4. 締切があれば、締切(開始予定より前でも、開始予定がなくても)。
5. 開始予定があれば、開始予定の1日後(同じ時刻)。
6. それ以外は `None`(棒を出さない)。

3 で `calc_end` が `None`(工数が上限超えなど)のときは、4 に進む。3 〜 6 は `computed_end(start, effort_hours, daily_hours, work_start, holidays, deadline=None)` にまとめる(ダイアログの算出値の表示も、これを使う)。算出できるときは、締切より算出値を優先する。

### 予定超過(`is_overdue`)

`is_overdue(task, project, holidays, now)`。状態が「終了」でなく、締切、または `effective_end` が、`now` より前なら `True`。

### 古いファイルの読み込み(`storage.py`)

読み込みだけで変換する。保存は新しい形式で行う。判定は項目の有無で行う(`planned_start` があれば新しい形式)。

- 旧 `start` → `planned_start`。
- 旧 `end` で、`end_auto` が `true` → 捨てる(完了予定は算出される)。
- 旧 `end` で、`end_auto` が `true` 以外 → `deadline`。
- `planned_end`、`planned_end_manual` は、既定値(`None`、`False`)。
- 新しい形式の `planned_end_manual` は、`true` のときだけ真として扱う(bool 以外は偽)。
- 新しい形式の日時は、今までと同じ検証を通す。

結果として、古い手入力の終了を持つタスクは、棒の長さが変わる(工数がなければ1日の棒)。

## 画面

### 編集ダイアログ(`task_dialog.py`)

- 並び: 名前 → 1行目(開始予定・完了予定を横並び) → 2行目(締切・工数) → 優先度 → 状態 → 色 → 担当者。
- 日付と時刻: 開始予定・完了予定・締切とも、今の開始・終了と同じ形(日付の入力 + 側ごとの「時刻を指定」のチェック)。時刻を指定しないときの時刻は、開始予定は始業、完了予定は始業 + 8h + 昼休憩 1h、締切は完了予定と同じ(終業)。
- 完了予定の欄:
  - 工数が 0 または空: 直接編集できる。空のときのヒントは「空なら締切(なければ開始予定の翌日)になります」。
  - 工数が 0 より大きい: 算出値を読み取り専用で表示する。横の「手で指定」をオンにすると編集でき、オフに戻すと算出値の表示に戻る(入力した値は保つ)。
  - 工数の入力に応じて、その場で切り替える。算出値の表示は、開始予定・工数の入力が変わるたびに更新する。
- 今の終了の保護(自動算出の終了で、時刻のチェックをオンに固定する処理)は、削除する。
- 閉じる確認(変更の判定)は、新しい3つの日付、「手で指定」のチェック、工数を含める。
- 保存: `build_task` が検証する(下記)。`planned_end_manual` は、工数が 0 より大きいときだけ保存し、それ以外は `False`。

### 検証(`forms.py` の `build_task`)

- 日時の形式、年の範囲(2000〜2100)、タイムゾーン付きと負の工数の拒否は、今までどおり。
- 完了予定は、開始予定以降(両方あるとき)。算出値には適用しない(算出値は常に開始予定以降)。
- 締切は、開始予定より前でもよい(納期を過ぎた着手もありうる)。締切に開始予定との前後の制約は置かない。

### ガントチャート(`gantt.py`)

- 棒は、開始予定から `effective_end` まで。開始予定がなければ出さない。幅 0 の細い棒の扱いは今までどおり(`MIN_BAR_PX`)。
- 締切の目印: 締切がある行に、締切の位置へ小さな「◆」を出す。位置は `timeline.py` の既存の位置計算を使う。表示範囲の外なら出さない。マーカーは、棒のクリックと同じく、編集ダイアログを開く。
- 行の赤い背景は、`is_overdue` の新しい判定に従う。

### 稼働時間の設定と祝日(`views.py`)

- 設定の適用時の再計算と、「N件の終了を再計算」の通知を削除する。適用すると、再描画だけ行う。値が同じなら何もしないのは今までどおり。
- 祝日の取得・更新後の再計算と、その通知、「再計算できなかった」通知を削除する。更新後は再描画だけ。
- 稼働時間の変更が「編集中」の判定に入るのは、今までどおり。

### 用語

画面の「開始」「終了」を、「開始予定」「完了予定」「締切」に改める。`CLAUDE.md` にこの3つの定義を書き、実績の「開始」「終了」を後続機能として書く。

## 削除するもの

`Task.end_auto`、`fill_end`、`recalc_ends`、`Recalc`、`needs_end_time` の自動算出の分岐、終了のロック(チェックの無効化とツールチップ)、再計算の通知、これらのテスト。保存時の終了の補完(`fill_end` の呼び出し)も削除する。

## テスト

先にテストを書く。

- `effective_end`: 5つの場合それぞれ(工数なしの手入力、工数ありの手で指定、工数ありの算出、開始予定のみで翌日、開始予定なしで `None`)。`calc_end` が `None` のときに翌日になること。稼働設定や祝日を変えると結果が変わること。
- `is_overdue`: 締切超過、完了予定超過、どちらも超えていない、状態が「終了」、締切も開始予定もない。
- 読み込み: 古い形式の変換(`end_auto` の true は捨てる、false と欠落は締切、`start` は開始予定)、新しい形式の往復、不正な `planned_end_manual`。
- `build_task`: 完了予定 < 開始予定の拒否、締切は開始予定より前でもよいこと、`planned_end_manual` を工数なしでは保存しないこと。
- ダイアログ: 工数の入力に応じた完了予定の欄の切り替え、「手で指定」のオン/オフ(値を保つ)、空のときのヒント、締切の時刻のチェック、閉じる確認が新しい項目を含むこと。
- ガント: 棒の位置(算出した完了予定)、締切の目印の位置と、範囲外で出ないこと、赤い行。
- 実機での確認: ダイアログの並びと幅、◆の表示、ライト/ダーク、小さなウィンドウでの切れ。

## 実装の順序

ブランチは `develop` から `feature/planned-dates` を切り、関心ごとに `feature/planned-dates-<関心ごと>` を切って、本体にマージする(`feature/planned-dates/…` は Git の参照名の制約で作れない)。

1. モデルと保存(項目、`effective_end`、`is_overdue`、読み込み)。算出まわりの削除と同じブランチに含める(中間で画面が壊れるため、1つにまとめる)。
2. フォームとダイアログ。
3. ガントと画面の用語。
4. 文書(`CLAUDE.md`、`README`、`docs/development.md`)。

## 先送りした点

- 締切の色分け、通知、並び替え・絞り込み。
- 実績の開始・終了と、実績に基づく超過判定。
- 古い手入力の終了を、締切ではなく完了予定として読み込む選択肢(棒の長さを保てる)。依頼の「終了時刻は締切時刻」を優先した。
