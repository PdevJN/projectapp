# ダッシュボードのメンバー絞り込みと内訳の設計(要望 43)

> **状態**: 実装済み・マージ済み — 要望 43 — PR #53(3a2cabf。2026-10-18)。要望 41〜46 の 3 番目。41(アイコン)・42(円グラフ)は実装済み。

## 目的

ダッシュボードを、メンバー 1 人に絞って見られるようにし、進捗にメンバー別の内訳を足す。
成功の目安は次のとおり。

- 期間の横のプルダウンで、`全員` かメンバー 1 人を選べる。選ぶと、ダッシュボードのすべてのカードが、その人の分だけになる。
- `全員` のとき、「進捗と遅れ」にメンバーごとの進捗の行(アイコン・名前・進捗率・件数)が出る。
- 絞り込んでも、日程の計算(先行による押し出し)は変わらない。

## 決めたこと

| 項目 | 決定 |
| --- | --- |
| 絞り込みの単位 | メンバー 1 人(複数の同時選択はしない) |
| 対象のタスク | 担当者に、そのメンバーが入っているタスク。担当がメンバーでない人だけのタスクと、担当なしのタスクは、どのメンバーでも対象にならない |
| 共同タスク | 1 件として丸ごと数える。進捗率・件数・円グラフは、チーム全体と同じ数え方のまま、対象のタスクだけが変わる |
| 工数の予定と実績 | 今までどおり、割り当て率(実績は割り当て率の比)で担当者に按分する。絞り込みは、その人の行だけにする |
| 操作 | 期間のトグルの横のプルダウン。全カードに効く |
| 保存 | しない。ダッシュボードを開くたびに`全員`に戻る。要望 40(カスタムビュー)で保存を検討する |
| ファイル形式 | 変えない(`version` は 7 のまま) |
| 実装方式 | 集計関数に`member`を通す。絞り込んだプロジェクトのコピーは作らない(先行を持つタスクの日程の押し出しが狂うため) |

## 集計(`dashboard.py`)

- `_tasks(project, member=None)`: まとめを外したタスクのうち、`member`があれば、`task.assignee_names`にその名前が入るものだけを返す。集計の入口はここ 1 か所に保つ。
- `summarize(project, period, now, holidays, kind=PeriodKind.ALL, member=None)`: `member`を各集計へ渡す。`Schedule`は絞り込まない元のプロジェクトで作る。
- 各カードへの効き方:
  - `summarize_progress`: 対象のタスクだけで、進捗率・状態別の件数・予定超過の一覧を作る。
  - `summarize_team_progress`: 対象のタスクだけ。期間の絞り込みと併用できる。
  - `summarize_due`: 対象のタスクだけ。
  - `summarize_loads`: `member`があれば、そのメンバーの行だけを返す。値は絞り込みなしの計算と同じ。
  - `summarize_workload`: `member`があれば、そのメンバーの行だけを返す(`未割り当て`の行は出さない)。値は絞り込みなしの計算と同じ。合計(`planned_total`・`actual_total`)はその行の合計になる。

### メンバー別の進捗(内訳)

- `MemberProgress(name, percent, counts)`: 名前、工数で重みづけした進捗率(対象のタスクがなければ`None`)、状態別の件数。
- `Progress.by_member: list[MemberProgress]`: `member`がないときだけ作る(絞り込み中は空)。
  - プロジェクトのメンバーの順に 1 行ずつ。その人が担当に入っているタスク(共同タスクは、入っている全員の行に数える)。
  - 最後に`未割り当て`。メンバーの担当が 1 人もいない(担当なし、または担当がメンバーでない人だけ)タスクがあるときだけ出す。節目(チェックポイント)は担当を持てず進捗の重みもないので、数えない。メンバーが 0 人のときは内訳ごと作らない(最終レビューで追加)。
  - 期間には影響されない(「進捗と遅れ」の既存の仕様と同じ)。
- 進捗率の計算は、既存の`_progress_weight`を共有する。まとめと節目を数えないのも同じ。

### ダッシュボード全体

- `Dashboard.member: str | None`: 絞り込み中のメンバー。
- `Dashboard.members: list[str]`: プルダウンの選択肢(プロジェクトのメンバーの順)。

## 画面(`dashboard_view.py`)

- ヘッダーの行: `ダッシュボード`・期間のトグル・**プルダウン**・`戻る`の順。プルダウンは`全員`とメンバー名(マーク`dashboard-member`)。
- 「進捗と遅れ」のカード: 状態別の件数の下、予定超過の上に、`メンバー別`の節を出す。1 行は、アイコン(あれば)・名前・`40% / 3 件`・進捗率の横棒。対象のタスクがない行は、`タスクなし`と出して棒は出さない。マーク`dashboard-member-progress-<名前>`。絞り込み中と、メンバーが 0 人のときは節ごと出さない。
- 「チーム全体の進捗」の対象の表示: 絞り込み中は、`田中・すべてのタスク`、`田中・10/05〜10/11 にかかるタスク`のように名前を前に付ける。ほかのカードには足さない(プルダウンが常に見えているため)。
- 絞り込んだ結果が空のカードは、今の`データがありません`を出す。

## 状態(`views.py`)

- `MainView.dashboard_member: str | None`。ダッシュボードを開くとき(`open_dashboard`)に`None`へ戻す。保存しない。元に戻す・やり直しの対象にしない。
- `change_dashboard_member(name)`: 値を更新して`refresh_dashboard`を呼ぶ。`refresh_dashboard`は、`dashboard_member`がプロジェクトのメンバーにないとき(削除・改名された)、`None`へ戻してから集計する。
- `DashboardView(on_back, on_change, on_member_change)`: プルダウンの変更を`on_member_change`へ渡す。`show`で、`data.members`と`data.member`からプルダウンの選択肢と値を合わせる(合わせるあいだは通知しない。期間のトグルの`syncing`と同じ)。

## テスト

- 集計(`test_dashboard.py`):
  - `_tasks`の絞り込み(共同タスクは丸ごと 1 件、メンバーでない担当者だけのタスクは対象外)。

  - 先行を持つタスクで、絞り込んでも日程(予定超過・負荷・工数)が変わらないこと。

  - 期間(`今週`)との併用。
- 画面(`test_dashboard_view.py`):
  - プルダウンの選択肢と、選んだときの`on_member_change`。
  - メンバー別の行(進捗率・件数・`タスクなし`)と、絞り込み中に節が出ないこと。
  - 円グラフのカードの対象の表示(名前つき)。
- 状態(`test_views.py`): 開き直すと`全員`に戻ること、メンバーが消えたときに`全員`へ戻ること。

## 含めないもの

- 絞り込みの保存、カードの出し入れ(要望 40)。
- 複数メンバーの同時選択。
- 担当なしのタスクの割り当て(要望 39)。
- 休暇・不在の反映(要望 44〜46)。
- `担当者向けファイル`・PlantUML・ガントチャートの担当者の絞り込みへの影響(別の機能。ガントチャートの絞り込みとは独立)。
