# ドラッグ&ドロップ 設計書

## 目的

ガントチャート上で、タスクの付け替え(セクション間の移動)と複製、開始予定の調整を、ドラッグ&ドロップでできるようにする。絞り込み(`2026-10-04-filtering-design.md`)の次の段階。

`projectapp/CLAUDE.md` の次の項目に対応する。
- `ガントチャート`の、アイテムは `コピーする`ことも`セクションごとに移動すること`も`ドラッグ`&ドロップでできる

## 範囲

**含む**: 行の縦移動(セクション内の並べ替え、セクション間、セクションなしとの往復)、行のコピー、バーの横移動(日次スケールのみ)、データ操作の純粋関数、画面側の JS、入力の検証。

**含まない**(後続、または対象外):
- 元に戻す(取り消し)。逆方向に動かせば戻せるので、最初は付けない
- セクション自体の並べ替え
- 週次・月次スケールでのバーの横移動
- バーの端をつかんで期間を伸ばし縮めること
- 複数のタスクをまとめて動かすこと
- 連結(矢印)を伴う移動と、コピーでの連結の引き継ぎ(連結の画面は未実装)

## 決定事項

- 行の縦移動は、セクションをまたぐ移動を含む。セクションなしの一覧と各セクションの間を、自由に動かせる。
- 行の縦移動とコピーは、どのスケールでも使える。バーの横移動は、日次スケールだけで使える。
- コピーは、Alt/Option を押しながら行をドロップする。元のタスクは動かさない。
- コピーしたタスクは、名前の末尾に「(コピー)」を付け、`predecessors` は空にする。それ以外(日程、工数、担当者、割り当て率、色、優先度、状態)は、すべて元のまま複製する。
- 絞り込み中は、行の移動とコピーを無効にする(非表示の行があると挿入位置が決まらないため)。バーの横移動は、絞り込み中も使える。
- 行の移動やバーの横移動は、その場で反映し、保存は自動では行わない。「編集中」の判定は、既存の `asdict(project)` と `snapshot` の比較にそのまま乗る。
- バーを動かして、同じ担当者の割り当て合計が100%を超えたときは、保存時と同じ通知(`warn_overallocation`)を出す。
- 実装方式は、行が HTML5 の drag、バーが pointer イベントの混成。

## データ操作(`arrange.py`、NiceGUI に依存しない)

位置は `(セクション番号 | None, 番号)` で表す。`None` はセクションなしの一覧。

```python
def move_task(project: Project, src: tuple[int | None, int], dst: tuple[int | None, int]) -> bool: ...
def copy_task(project: Project, src: tuple[int | None, int], dst: tuple[int | None, int]) -> Task: ...
def shift_task(task: Task, days: int) -> bool: ...
```

- `move_task`: `dst` の番号は挿入位置(取り除く前の番号)。同じ一覧の中で前から後ろへ動かすときは、取り除いた分だけ挿入位置を 1 つ戻す。位置が変わらない移動は、何もせず `False` を返す。挿入位置が範囲外のときは、末尾に丸める。
- `copy_task`: `dataclasses.replace` と、リストの複製で、別オブジェクトを作る。名前は `f"{name}(コピー)"`。`predecessors` は空にする。複製を `dst` に挿入して返す。
- `shift_task`: `planned_start` を `days` 日ずらす(時刻は保つ。暦の日で数える)。`planned_end` が `None` でなければ、同じ日数ずらす(使われていない古い値でも同様)。`deadline` は動かさない。`planned_start` が `None` なら何もせず `False` を返す。新しい `planned_start` と `planned_end` を先に両方計算し、どちらも範囲内(年が 2000〜2100)のときだけ書き込む。範囲外(`OverflowError` を含む)なら、何も書き換えず `False` を返す。
- 工数があって自動算出の完了予定は、保存値を持たないので、開始予定が動けば稼働日・祝日を反映して再計算される。土日をまたぐと、棒の長さが変わって見えることがあるが、意図した挙動とする。

## 画面

### 共通

- 行とバーに、`data-*` 属性(セクション番号・タスク番号・列幅)を付ける。JS は 1 つのスクリプト(定数)にまとめ、`render` を囲む外側の要素に、一度だけ委譲で取り付ける(`render` は再描画のたびに作り直されるため、各要素には付けない)。
- 結果は `emitEvent` で Python に返す(`chart_move`、`chart_shift`)。

### 行の縦移動とコピー(HTML5 の drag)

- つかむ場所はタスクの名前のラベル。クリックで編集する既存の動作とは共存する(動かさなければクリックのまま)。
- 落とせる場所: タスク行(上半分はその行の前、下半分は後ろ)、セクション見出しの行(そのセクションの末尾)、「タスク追加」の行(セクションなしの一覧の末尾)。空のセクションにも落とせる。
- 落とす位置に、細い線(行の前後)か枠(見出し)を出す。Alt/Option を押している間は `dropEffect` を `copy` にして、カーソルを複製の表示にする。離すか Esc で中止すると、線は消える。
- Python が受ける内容は `{src: [si, ti], dst: [si, 位置], copy: bool}`。
- コピーしたときは「『○○』をコピーしました」と通知する。移動は通知しない。
- 絞り込み中は、名前のラベルに `draggable` を付けない。

### バーの横移動(pointer イベント。日次のみ)

- 日次スケールで、開始予定があるタスクのバーだけが対象。カーソルは `grab`。週次・月次では、既存の動作(クリックで編集)のまま。
- 横に動かした量を 1 日分の列幅に吸着させて、バーを動かして見せる。放したとき、ずらした日数だけを `{si, ti, days}` で送る。0 日なら何も送らない。
- 4px 未満の動きはクリックとして扱い、既存の編集ダイアログを開く。実際に動かしたあとの `click` は打ち消す。
- 動かしている間の Esc で、元の位置に戻す。
- 締切の「◆」と、バーの縞は動かさない(再描画で新しい位置に出る)。

### `GanttActions` と `MainView`

- `GanttActions` に `move_task(src, dst, copy)` と `shift_task(si, ti, days)` を足す。
- `MainView` が実装する。`arrange.py` を呼び、成功したときだけ `render.refresh()` を呼ぶ。バーの横移動のあとは、`warn_overallocation` で割り当て超過を通知する。

## 入力の検証

- JS から届く番号は、整数で範囲内であること。`days` は整数で、±3650 日以内であること。満たさないものは、何もせず、通知もしない(再描画との行き違いで古い番号になりうるため)。
- `shift_task` が `False` を返したとき(範囲外の日付)は、「日付の範囲を超えるため動かせません」と通知する。

## テスト

- `arrange.py`(大部分をここで担保)
  - `move_task`: セクション内の前後、セクションをまたぐ、セクションなしとの往復、空のセクションへ、同じ位置への移動(変化なし)、前から後ろへ動かすときの位置の戻し、挿入位置が範囲外のとき。
  - `copy_task`: 名前に「(コピー)」、`predecessors` が空、全項目の複製、リストが別オブジェクト、元が変わらない、挿入位置。
  - `shift_task`: 開始予定のみ、完了予定を手指定、工数 0 で `planned_end` あり、締切が動かない、時刻が保たれる、`planned_start` なしは何もしない、範囲外は何も書き換えない、負の日数。
- `MainView` のハンドラ: 入力の検証(範囲外・型の誤り・巨大な日数)、通知、成功時のみ再描画、「編集中」になること、割り当て超過の通知、絞り込み中は行の移動とコピーを受け付けないこと。
- `GanttChart` の描画: 絞り込み中は `draggable` が付かないこと。日次だけバーに `data-*` と `grab` が付くこと。週次・月次では付かないこと。
- JS そのものは自動テストを書かない(ブラウザの drag イベントの再現に費用がかかるため)。実機の確認項目:
  - 行の移動(同じセクション内、セクション間、空のセクションへ、セクションなしとの往復)。
  - Option を押した行のコピー。
  - バーの 1 日・複数日の横移動と、Esc での中止。
  - 動かしたあとに編集ダイアログが開かないこと、クリックでは開くこと。
  - 日本語入力中でも干渉しないこと。
  - 狭いウィンドウでの横スクロールとの共存。

## リスクと最初にやること

macOS の WebView(pywebview の WKWebView)で、Option を押した drag の `altKey` が `drop` で取れるかを、実装の最初に小さな試作で、実機で確かめる。取れなければ、行の drag も pointer イベントに切り替える(設計の他の部分は変わらない)。
