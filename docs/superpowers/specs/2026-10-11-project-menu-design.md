# プロジェクトメニューの見直し 設計

日付: 2026-10-11

## 目的

ヘッダーの`プロジェクト`メニューを、項目の性質に沿って整理する。「新規プロジェクト作成」はファイル操作なのでファイルメニューへ、関連の深い「メンバー」と「パラメータ」は 1 つのダイアログにまとめる。あわせて、メニューの項目にアイコンを付けて表記をそろえる。

## 決めたこと(あなたの回答)

- 「新規プロジェクト作成」は`ファイル`メニューへ移す
- 「メンバー」と「パラメータ」は、1 つのダイアログのタブにする
- 「適用」はタブごと(未適用の編集は、もう一方のタブへ行き来しても残す)
- 全メニューの項目にアイコンを付ける

## 範囲外(変えない)

- 保存形式(`version` も変えない)。メンバー・パラメータの中身(表・検証・削除時の確認・適用で保存扱いにしない動き)
- `Ctrl/Cmd+N`(新規)・`Ctrl/Cmd+,`(設定)の割り当てと、保存前の確認ダイアログの動き
- 設定ダイアログ

## 1. メニューの構成

| メニュー | 項目(上から) |
|---|---|
| ファイル | 開く / 新規プロジェクト作成 / ─ / 上書き保存 / 名前をつけて保存 / ─ / 祝日を更新 |
| プロジェクト | 設定 / メンバーとパラメータ |
| エクスポート | チャートプレビュー / 担当者へ書き出し |
| ヘルプ | ショートカットヘルプ |

- 水平線は、「ファイルを開く・作る」「保存」「データの更新」の 3 つに分ける
- マーカー: `file-new`・`open-settings` は変えない。メンバーとパラメータは`open-members-parameters`にする(`open-members`・`open-parameters`は無くす)

## 2. アイコン

`header_menu` の項目を (文言・操作・マーカー) から (文言・アイコン・操作・マーカー) にし、`ui.menu_item` の左にアイコンを出す。

| 項目 | アイコン |
|---|---|
| 開く | `folder_open` |
| 新規プロジェクト作成 | `note_add` |
| 上書き保存 | `save` |
| 名前をつけて保存 | `save_as` |
| 祝日を更新 | `event_repeat` |
| 設定 | `settings` |
| メンバーとパラメータ | `groups` |
| チャートプレビュー | `visibility` |
| 担当者へ書き出し | `ios_share` |
| ショートカットヘルプ | `keyboard` |
| テーマ(自動・ライト・ダーク) | `brightness_auto`・`light_mode`・`dark_mode` |

テーマのメニューも、同じ作りで絵を付ける(ボタン自身の絵は、今のテーマのまま)。

## 3. メンバーとパラメータのダイアログ

- メニューの「メンバーとパラメータ」は、メンバーのタブを先に開く
- ダイアログのタイトルは`メンバーとパラメータ`。タブは`メンバー`・`パラメータ`の 2 つ(`ui.tabs` + `ui.tab_panels`)
- 各タブは、今のダイアログの中身(表・追加ボタン・エラー表示・キャンセル/適用)をそのまま持つ。適用してもダイアログは閉じない。タブを切り替えても、入力は残す(タブのパネルを作り直さない)
- **パラメータの適用**: 既存の確認(選択を外すメンバーがいるとき)を経て、`apply_parameters` に渡す。その後、メンバーのタブの表を、適用後のパラメータで作り直す(列が変わるため)。メンバーの未適用の編集のうち、名前・基本比率は残し、段階の選択は、残っている段階だけ残す(改名は、適用した改名に追従する)
- **メンバーの適用**: 今の`apply_members`。パラメータのタブの未適用の編集には触れない
- 未適用の編集があるタブには、タブの見出しに印(`●`)を出す
- キャンセルは、今のとおり、その時点のダイアログ全体を閉じる(未適用の編集は捨てる)。ESC も同じ
- メンバーのタブの`taken`(使用済みの id)・`assigned`(担当している件数)は、今のまま渡す

実装上は、`forms.py` の `open_members_dialog`・`open_parameters_dialog` の本体を、ダイアログの外へ出した「タブの中身を作る関数」に分け、`open_members_parameters_dialog` が 2 つを`ui.tab_panels`に並べる。既存の検証・組み立て(`build_members`・`build_parameter_edit`)と、表の作りは変えない。

## 4. ショートカット

- `Ctrl/Cmd+Shift+M`「メンバーとパラメータ」を足す(`Ctrl/Cmd+M`は、macOS でウィンドウを最小化するため避ける)
- `shortcuts.py` の `SHORTCUTS` と、ショートカットヘルプの一覧に載せる

## 5. テスト(`test/test_views.py` など)

- メニュー項目の順序とマーカー、水平線の位置、各項目のアイコン
- 「新規プロジェクト作成」がファイルメニューにあり、編集中は確認ダイアログが出る(既存のテストを移す)
- 統合ダイアログ: メンバーのタブが先に開く / パラメータの適用でメンバーの表の列が変わる / 未適用の編集がタブを行き来しても残る / 見出しの印 / パラメータの削除確認 / 適用してもダイアログは閉じない
- `Ctrl/Cmd+Shift+M` で開く、入力欄にフォーカスがあっても効く(修飾キー付きの扱いは既存の`save_as`と同じ)
- 既存の`open-members`・`open-parameters`を使うテストの置き換え

- `docs/development.md` のメニュー・ダイアログの記述があれば直す
