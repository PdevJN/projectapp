# イベントの期間を休みにする設計(要望 82)

> **状態**: 完了(PR #117。実機確認済み。2026-10-29)。実装計画 [`plans/2026-10-28-event-closed.md`](../plans/2026-10-28-event-closed.md) — 要望 82。現在の仕様は [`CLAUDE.md`](../../../CLAUDE.md) に反映済み。

## 目的

イベント(プロジェクト共通。`開始日`・`終了日`・`文字列`・`色`)ごとにチェックボックスを付け、チェックしたイベントの期間は、全員の稼働日を休みとして扱う。夏季休業・年末年始・全社の研修日のように、プロジェクト全体が止まる期間を、メンバー 1 人ずつの上書きではなく、1 件のイベントで表す。

## 決めたこと(2026-10-28 に確認済み)

| 項目 | 決定 |
| --- | --- |
| 優先順 | メンバーの稼働日の上書き(要望 30)が優先。上書きで稼働にした日は、全社休みでもその人だけ稼働する。上書きで休みにした日は、イベントがなくても休み |
| 方式 | 共通の関数 `effective_holidays(project, base)` を作り、祝日の辞書にイベントの休みを混ぜる(方式 C)。開いているプロジェクトは `MainView.holidays` を置き換え、他プロジェクトを読む経路は、そのプロジェクト自身のイベントで同じ関数に通す |
| 見せ方 | 休みの日の背景は、今のイベントの色のまま。祝日の緑は付けない。帯の文字の頭に `休 ` を付け、ホバーに `休み` と出す |
| 範囲外 | メンバー個別の休み(要望 44〜46 で対応済み)。期間の自動追加。ダッシュボードの注記の変更 |

## データ

- `models.Event` に `closed: bool = False` を足す。
- ファイル形式: `models.FORMAT_VERSION` を 15 にする。`events[].closed`(真偽値)を保存する。キーのない古いファイルは `false`。`null` と真偽値でない値(数値・文字列)は読込を拒否する。version 14 以下のファイルにある `closed` は無視する(`storage._events` に `ctx.version` を渡し、15 以上でだけ読む)。
- 3 者マージ: イベントは今のとおり `id` で突き合わせ、`closed` を別の項目(項目名 `休み`)として比べる。衝突ダイアログでは `休みにする` / `休みにしない` と出す。
- 元に戻す・やり直し: イベントの編集の一部として、他の項目と同じに扱う(追加の対応は要らない)。

## 休みの算出(`effective_holidays`)

- 場所: `events.py`。NiceGUI に依存しない純粋関数。

```python
def effective_holidays(project: Project, base: Mapping[date, str]) -> dict[date, str]:
    """祝日 base に、休みにしたイベント(closed)の期間の全日を足した辞書。祝日と重なる日は祝日の名前を残す。"""
```

- チェックしたイベントの `開始日`〜`終了日`(含む)の各日を、`{日付: イベントの文字列}` で足す。同じ日に複数のイベントが重なるときは、先に並ぶほう(開始日の昇順)の文字列を使う。値は表示に使うだけで、判定は「辞書にあるか」だけ。
- 祝日(`base`)にある日は、`base` の名前のまま変えない。
- 年は `MIN_YEAR`〜`MAX_YEAR` の範囲の日だけ足す(イベントの検証がすでに範囲を見ている。範囲外は無視する)。
- チェックしたイベントがなければ、`base` と等しい辞書を返す(呼び出し側は同じ結果になる)。

### どこで通すか

- 開いているプロジェクト: `MainView` が、祝日のキャッシュを `base_holidays` に持ち、`holidays` を、`effective_holidays(self.project, self.base_holidays)` を返すプロパティにする。プロジェクトを開く・イベントを編集する(元に戻す・やり直しを含む)・祝日を更新するたびに変わるので、イベントの並びと `closed` から作ったキーでキャッシュする。完了予定・割り当て超過・ダッシュボード・担当者向けファイル・PlantUML・チャートの再計算は、今の `self.holidays` をそのまま使えば、休みを反映する。
- 他プロジェクトを読む経路は、`base_holidays` を渡し、各プロジェクト自身のイベントで混ぜる。
  - `dashboard.summarize_cross_loads`: 全プロジェクトを重ねる集計(`_workdays` の列の和集合と `_member_spans`)で、プロジェクトごとに `effective_holidays(project, base)` を使う。引数は `base` の祝日にする。
  - `reference.ReferenceResolver`: 参照先を読んだら、`effective_holidays(参照先, base)` で値を計算する(`holidays` のコールバックは `base_holidays` を返す)。
- ガントチャートの背景(`day_kind`): 祝日の緑は、`base` の祝日だけで決める。そのため、`gantt` に `base_holidays` も渡す(`set_holidays` を `set_holidays(holidays, base)` にする)。計算は `holidays`(休み込み)を使う。

## 画面

- 設定ダイアログの `イベント` の節(`forms.EventRow`)の各行に、チェックボックス `稼働日を休みにする` を足す(マーカー `event-{n}-closed`)。既定はオフ。行の並びは `開始日 / 終了日 / 文字列 / 色 / 稼働日を休みにする / 削除`。
- ガントチャートのイベントの帯(`gantt`)は、`closed` のとき、文字の頭に `休 ` を付け、ホバーに `休み(全員の稼働日)` を足す。期間のセルの塗りは、今のイベントの色のまま。プレビュー・画像も同じ。
- 稼働日のダイアログの `期間で追加` の `土日祝を除く` は、祝日の辞書にイベントの休みを含めない(メンバー個別の上書きなので、`base` を使う。意味を変えない)。

## 他の出力への影響

- PlantUML: `effective_holidays` を通るので、休みの日は `closed` として出る(土日と期間内の祝日と同じ行)。イベントのセルの色と帯は今のまま。
- 担当者向けファイル(`build_todos`): 期間と見積もりの算出に `holidays` を使うので、休みを反映する。形式は変えない。
- TSV・CSV の書き出し・取り込み: 取り込みは新しいプロジェクトを作るのでイベントがなく、変わらない。書き出しは `期限`・`期間` が、休み込みの完了予定になる。

## テスト

- 純粋関数: `effective_holidays`(チェックなし・1 件・複数が重なる・祝日と重なる・年の範囲外・期間 1 日)。
- 保存・読込: version 15 の往復、キーのない古いファイル、version 14 の `closed` の無視、不正な型(`null` を含む)の拒否。
- マージ: `closed` が別の項目で、衝突ダイアログに `休み` と出る。
- 算出: 休みのイベント期間を、完了予定の算出が飛ばす。メンバーの上書き(稼働)がイベントより優先される。上書き(休み)は、イベントがなくても休みのまま。
- 割り当て超過・ダッシュボード: 休みの日が稼働日の数・負荷・予定工数から除かれる。
- 他プロジェクト: 全プロジェクトの負荷とプロジェクト参照が、それぞれのプロジェクト自身のイベントで休みになる。
- 画面: 設定ダイアログのチェックボックスで、イベントの `closed` が適用される。ガントチャートの背景に祝日の緑が付かない。帯に `休 ` が付く。

## Review Focus(計画で、テストを足す入力)

- 祝日と、休みのイベントが同じ日に重なるとき、背景は緑にならず(イベントの色のまま)、算出は休みになる。
- 休みのイベントの期間が長く(例: 年をまたぐ 2 か月)、`effective_holidays` の再計算が、操作のたびに遅くならない。キャッシュの無効化を、イベントの編集・元に戻す・プロジェクトの切り替えで確かめる。
- 他プロジェクトのイベントが、開いているプロジェクトに漏れない。逆に、開いているプロジェクトのイベントが、他プロジェクトの集計に混ざらない。
- 担当者全員が、イベントの休みの日に個別に稼働を上書きしているタスクで、完了予定が、その上書きの時間帯で進む。
