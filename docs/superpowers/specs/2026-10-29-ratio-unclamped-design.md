# 相対比率の丸めの対象外メンバーの設計(要望 76)

> **状態**: 実装済み(PR #122。実機確認済み。2026-10-29)。実装計画 [`plans/2026-10-29-ratio-unclamped.md`](../plans/2026-10-29-ratio-unclamped.md) — 要望 76。

## 目的

基本比率そのものが実態を表すメンバー(例: 基本 200% のベテラン、基本 30% の新人)を、入力した比率どおりに計算できるようにする。要望 75 の丸め(既定 50〜150%・設定で狭められる)を、メンバーごとに外せるようにする。

## 決めたこと(2026-10-29 に確認済み)

| 項目 | 決定 |
| --- | --- |
| 設定の単位 | メンバーごとのチェック(`丸めない`)。プロジェクトに名前の一覧は持たない |
| 「影響を受けない」の範囲 | 丸めを一切掛けない。`基本比率 + 判定値の合計`をそのまま使い、既定の 50〜150% も、設定の上限・下限(要望 75)も外す |
| 安全の止め | 対象外でも、固定の 10〜300%(基本比率の入力範囲と同じ。変更不可)だけは常に掛ける。判定値の合計が 0 以下になって `工数 ÷ 換算率` が壊れるのを防ぐ |
| 見直し確認 | 出さない。メンバーの表の基本比率の編集と同じ扱い(確認が出るのはタスクの担当変更と、上限・下限の変更のみ) |

## データ・ファイル

- `Member.ratio_unclamped: bool = False`(既定は「丸める」)。
- `FORMAT_VERSION` を 15 → 16 にする。`_dump` は`asdict`なので、キーは自動で保存される。
- 読込: `version >= 16` のときだけ`ratio_unclamped`を読む。真偽値以外は拒否。キーのない古いファイルは`False`。

## 計算(`ratios.py`)

- 固定の安全範囲を定数にする(`models.py`の`MIN_RATIO`・`MAX_RATIO`〔10〜300%〕を使う)。
- `ratio_detail`: `member.ratio_unclamped` が真なら、`raw` を安全範囲にだけ収める。`limits` は見ない。
- `RatioDetail` に `unclamped: bool` を足す。`limited` は、対象外では安全範囲に掛かったときに真にする。
- `limit_note`: 対象外で安全範囲に掛かったときは`相対比率 350% → 安全範囲の上限 300% に制限`(下限は`10%`)。対象外で掛からなければ注記なし。
- `effective_ratio` と全呼び出し元(完了予定・換算率・担当者向けファイル・見直し・分解・ダッシュボード・週ごとの担当)は`ratio_detail`を通るので、追従する。呼び出し側の変更は要らない。
- 上限・下限の変更時の見直し(`reassign.limit_reviews`)は、新旧の換算率を比べるので、対象外のメンバーの分は自然に「変わらない」になる。

## 画面

- `メンバーとパラメータ`のメンバーの表に、`丸めない`の列(チェック)を足す。ホバーに`50〜150%(設定の上限・下限)に丸めず、基本比率 + 判定値をそのまま使う。10〜300% は常に守る`を出す。
- 換算率の内訳(タスクの編集ダイアログ)とメンバーの画面に、対象外のときは`丸め対象外`を添える。安全範囲に掛かったときは上の注記を出す。
- 適用はタブごとの既存の流れのまま。未適用の編集は`●`に含める。

## 周辺

- 3 者マージ: メンバーの項目(`MEMBER_LABELS`・`_member_fields`・再構築)に`ratio_unclamped`を足す(表示名`丸め対象外`)。
- 設定の書き出し・取り込み: メンバーの項目に含める。上書きでは`ratio_unclamped`も置き換える(`settings_io`のメンバーの上書き)。
- 元に戻す・やり直し: メンバーの編集として既存の仕組みで対象になる。
- CSV・PlantUML・担当者向けファイル: 形式は変えない(担当者向けは、見積もりが換算率に追従するだけ)。
- `docs`: `CLAUDE.md`(メンバー・相対比率・バージョン)、`docs/development.md`のファイル形式、`docs/requests.md`の要望 76 を更新する。

## テスト

- `ratios`: 対象外で、基本 200%(丸めず 200%)・基本 30%・加算あり・10% 未満(10% に)・300% 超(300% に)・設定の上限/下限が効かないこと・対象でない人は従来どおり。
- `storage`: version 15 以前の読込(False)・往復・真偽値以外の拒否・`FORMAT_VERSION` 16。
- `merge`: 片側だけの変更・両側の衝突。`settings_io`: 取り込みの追加・上書き。
- 呼び出し元の結果: 完了予定の日数、`limit_reviews`が対象外の人を含むタスクを見直し対象にしないこと。
- UI: メンバー表の列が適用で保存されること(既存のテストの流儀に合わせる)。

## 範囲外

- メンバーごとの個別の上限・下限、安全範囲(10〜300%)を変える設定。
- 切り替え時の見直し確認。
