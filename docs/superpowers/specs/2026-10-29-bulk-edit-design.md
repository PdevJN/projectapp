# 複数タスクの一括編集・一括削除の設計(要望 35)

> **状態**: 完了(PR #123。cd2c4d3。2026-10-29)。要望 35。倍率での工数変更は要望 83(後続)。現在の仕様は [`CLAUDE.md`](../../../CLAUDE.md) に反映済み。

## 目的

ガントチャートで複数のタスクを選び、担当・カテゴリ・完了予定・工数をまとめて変え、まとめて削除できるようにする。1 件ずつ編集ダイアログを開く手間をなくす。

## 決めたこと(2026-10-29 に確認済み)

| 項目 | 決定 |
| --- | --- |
| 選択の操作 | 名前の欄の Cmd/Ctrl クリック(個別に追加・解除)と Shift クリック(最後に選んだ行との間の、見えている行の範囲)。行頭のチェックボックスは作らない |
| 修飾なしのクリック | 今と同じ(何も起きない)。選択中でも解除しない。解除は `Esc` か選択バーの`解除` |
| まとめを選んだとき | 子も選択に含める(折りたたみで隠れた子も含む)。子だけを Cmd/Ctrl クリックで外せる |
| 絞り込み中 | 見えている行だけが対象。選択済みでも隠れた行には適用しない |
| 担当 | モード 3 つ: 追加 / 削除 / 置き換え(第 N 週以降は要望 84 へ移した) |
| カテゴリ | 置き換え(登録済みのカテゴリか`未定`)。既定は変更しない |
| 完了予定 | 2 モード: 日付を指定 / 暦日で±N 日ずらす。どちらも`手で指定`にする |
| 工数 | 2 モード: 値にする(単位は時間・日・週・月)/ 増減(±N 時間相当)。倍率は要望 83 |
| 削除 | 単独削除と同じ規則(まとめを消すと子は残るが、一括ではまとめの子も選択に含まれるので一緒に消える)。確認に件数を出す |
| Undo | 適用 1 回 = 1 ステップ(`after_edit()`) |
| ファイル形式 | 変えない(`version` は据え置き) |

## 選択(`bulk_select.py`。NiceGUI に依存しない)

- 状態は `BulkSelection(ids: set[str], anchor: str | None)`。タスク `id` で持つ(行の位置は編集で変わるため)。
- `toggle(task_id)`: Cmd/Ctrl クリック。まとめなら子もまとめて入れる/外す。`anchor` を更新する。
- `extend(visible_ids, task_id)`: Shift クリック。`visible_ids`(描画順の、見えているタスク行の id)の中で `anchor` と `task_id` の間を追加する。`anchor` がなければ `toggle` と同じ。まとめが含まれたら子も入れる。
- `effective(visible_ids)`: 適用の対象。`ids` のうち見えている行だけ。絞り込み中に隠れた行は含めない。
- `prune(project)`: 削除や Undo でなくなった id を落とす。`ids` が空になれば選択なし。
- プレビューと読み取り専用では、選択の操作を受け付けない。

### 画面(`gantt.py`)

- 名前の欄のクリックを受けるのは、既存の「名前の欄のダブルクリック」と同じ要素。**行の要素は増やさない**。選択の見た目は、行に `data-task-id` を持たせ、クラス `task-selected` の付け外しをブラウザ側の JS で行う(`render.refresh()` はしない)。同じクリックでサーバーへ `emit` し、`BulkSelection` を更新する。
- 描き直し(`render`)では、集合からクラスを付けて出す。編集後も選択は残る。ただし、`prune` で消えた id は落とす。
- ボタン・リンク・折りたたみの矢印・入力行の上のクリックは、選択として扱わない(既存のダブルクリックと同じ除外)。
- 選択中は、ツールバーの下(検索欄の行)に選択バーを出す: `n 件選択中`・`編集…`・`削除`・`解除`。選択がなければ出さない(要素を増やさない)。
- 右クリックメニューに、選択が 1 件以上のときだけ `選択中 n 件を編集…`・`選択中 n 件を削除` を出す。選択に含まれない行を右クリックしたときは、選択をそのままにして、行に対する従来のメニューだけを出す。
- `Esc`: ダイアログが開いていなければ、選択を解除する。ダイアログ・プレビュー・ダッシュボードの `Esc` を優先する。
- 選択は保存せず、元に戻す・やり直しの対象にしない。プロジェクトを開き直す、`名前をつけて保存`、格納先の変更で解除する。

## 一括編集(`bulk_edit.py`。純粋関数)

```python
@dataclass(frozen=True)
class BulkChanges:
    crew: CrewChange | None        # 担当
    category: CategoryChange | None  # カテゴリ(id か None=未定)
    end: EndChange | None          # 完了予定(日付を指定 / ずらす)
    effort: EffortChange | None    # 工数(値にする / 増減)

def apply_bulk(project, ids, changes, schedule) -> BulkResult
```

- `BulkResult`: 変更後のタスクの一覧(`replace` した新しい `Task`)と、理由別のスキップ件数・注意の件数。画面側は結果を `project` に反映し、`after_edit()` を 1 回呼ぶ。
- `ids` は描画順に並べて処理する(結果の再現性のため)。
- 対象にできる種別は項目ごとに決める:

| 項目 | 通常 | まとめ | チェックポイント | プロジェクト参照 |
| --- | --- | --- | --- | --- |
| 担当 | ○ | スキップ | スキップ | スキップ |
| カテゴリ | ○ | ○ | ○ | スキップ |
| 完了予定 | ○ | スキップ | スキップ | スキップ |
| 工数 | ○ | スキップ | スキップ | スキップ |

  まとめ自身は、子を選択に含めるので、子で処理される。

### 担当(`CrewChange`)

- **追加**: メンバー 1 人と割り当て率(1〜100%)を指定。すでにいる人は、割り当て率を指定の値に更新する(同じメンバーは 1 回まで)。週ごとのタスクは、全週に適用する。`assignees` は和集合に整える。
- **削除**: メンバー 1 人を外す。週ごとのタスクで、外して空になる週は直前の週(なければ直後の週)と同じにして、件数を通知する(3 者マージと同じ規則)。外した結果、担当が 0 人になる通常タスクは担当なしになり、件数を通知する。週ごとのタスクで全週が空になるときは、週ごとをやめて担当なしにする。
- **置き換え**: 担当の一覧を指定の一覧に入れ替える(1 人以上。メンバーは重複不可、割り当て率は 1〜100%)。週ごとのタスクは週ごとをやめる。**事前に、週ごとが解除される件数を確認ダイアログに出す**(0 件なら出さない)。
- 担当の変更で換算率が変わり、工数があり、状態が`終了`でなく、実績か進捗度(1% 以上)があるタスクの件数は、`完了予定の見直しが要るタスクが n 件あります`と通知する(見直しの確認は、一括では出さない。ダイアログの単独の編集で見直す)。

### カテゴリ

- 指定のカテゴリ id(`None` は`未定`)にする。プロジェクト参照はスキップ。

### 完了予定

- **日付を指定**: 指定した日の終業時刻(CSV の取り込みの完了予定と同じ算出を使う)を `planned_end` に入れ、`planned_end_manual = True` にする。工数のないタスクも同じ。開始予定より前になるときは、そのタスクをスキップして件数を通知する(検証は単独の編集と同じ)。
- **ずらす**: 暦日で ±N 日(1〜365)。現在の実効の完了予定(自動算出を含む)を基準に、`planned_end` を ±N 日ずらして手で指定にする。実効の完了予定が読めないタスクはスキップ。結果が開始予定より前になるときもスキップ。
- 工数があって自動算出のタスクが手で指定に変わる件数は、`自動算出から手で指定に変わったタスク n 件(設定を変えても追従しません)`と、確認ダイアログとダイアログの注意書きに出す。

### 工数

- **値にする**: 単位(時間・日・週・月)と値を指定し、時間に換算して小数点以下 2 桁まで(`effortunits`)にする。0 以上。
- **増減**: ±N(時間・日・週・月の単位つき)。工数のないタスク(0)はスキップして件数を通知する。結果が 0 未満になるタスクはスキップして件数を通知する。
- 工数が変わって自動算出の完了予定が動くことは、仕様どおり(通知しない)。

## ダイアログ(`bulk_dialog.py`)

- タイトル `n 件を一括編集`。項目ごとの節(担当・カテゴリ・完了予定・工数)を持ち、**各節は「変更しない」が既定**。節の見出しに、設定の要約を出す。変更が 1 つもなければ`適用`は押せない。
- 担当の節: モードのトグル(追加 / 削除 / 置き換え)。モードごとに入力欄が変わる(メンバーの選択・割り当て率)。メンバーの選択肢は、プロジェクトのメンバーのみ。
- 下部に、**適用前の見込み**を出す: `対象 n 件 / スキップ m 件(理由別)`。入力のたびに`apply_bulk`をドライランして更新する(プロジェクトは変えない)。
- `適用`で`MainView.apply_bulk`を呼ぶ。注意の通知(見直しが要る件数、自動算出から手で指定に変わる件数)は、確認ダイアログではなく適用後の通知に出す。確認ダイアログを出すのは、置き換えで週ごとが解除されるときだけ。
- 適用後、`warn_overallocation`と同じ判定で、割り当て超過になったタスクの通知を出す(保存時と同じ文言。件数が多いときは先頭 3 件+`ほか n 件`)。
- 適用して閉じたら、選択は残す(続けて別の項目を直せる)。

## 一括削除

- `削除`で確認ダイアログを出す: `n 件のタスクを削除します(うちまとめ k 件・子 j 件)`。実行中の記録(終了のない実績区間)があるタスクの件数も添える。
- 実行: 各タスクを、既存の単独削除と同じ関数で削除し、先行リンクを `drop_task_links` で整理する。子を選択に含めるので、まとめと子は一緒に消える。まとめだけが消えて子が残るのは、子を選択から外したときのみ(子は通常タスクとして残る)。
- `after_edit()` を 1 回呼ぶ。削除後は選択を解除する。

## 影響しないもの

- 単独の編集ダイアログ、チップのダイアログ、`週ごとに分ける`/`週ごとをやめる`、右クリックの従来の項目。
- ファイル形式、3 者マージ、PlantUML・CSV・担当者向けファイル。
- 絞り込み・折りたたみ・スクロールの状態(選択は別に持ち、描き直しでも位置は動かさない)。

## テスト

- `bulk_select`: toggle・extend(範囲・anchor なし・まとめの子・見えている行だけ)・effective・prune。
- `bulk_edit`: 項目ごとに、種別ごとの対象とスキップ、担当 4 モード(週ごと・空の週・全週が空・上限 52・開始予定なし)、完了予定 2 モード(終業時刻・開始予定より前・手で指定への切り替え)、工数 2 モード(換算・0 未満・工数なし)、ドライランが元を変えないこと、`ids` の順序。
- 画面: 選択バーの出し入れ、右クリックのメニュー、`Esc`、ダイアログの適用前の見込み、確認ダイアログ(置き換えで週ごと解除)、Undo 1 ステップ、一括削除(まとめと子・リンクの整理)。
- JS: 選択のクリック処理の状態機械(Cmd/Ctrl・Shift・除外する要素)を、`gantt_drag` と同じく Node で。
- 実機確認(ネイティブ): Shift の範囲選択、折りたたみとまとめ、選択の見た目、ダイアログの見込み。
