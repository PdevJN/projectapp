# 日程計算 設計書

## 目的

開始日時と工数(時間)から、完了予定の終了日時を算出する。予定を超えたタスクを赤系の背景で表示する。ガントチャート基本表示(`2026-10-02-gantt-basic-design.md`)の次の段階。

## 範囲

**含む**: 終了日時の算出、保存時の自動補完、予定超過の判定と赤表示。

**含まない**(後続のサブプロジェクト):
- 実績の開始・終了の入力と、実績に基づく超過判定
- 稼働可能時間・始業時刻の設定画面(既定値を使う)
- 見積もりのバッファ換算、リソース割り当て比率
- ドラッグ&ドロップ、検索・絞り込み、矢印連結、添付ファイル

## 決定事項

- 日の数え方は稼働日のみ(土日と祝日を飛ばす)。
- 終了日時は、空のときだけ自動算出する。手で入れた終了は上書きしない。
- 予定超過は「今日が終了予定を過ぎていて未完了」とする。

## 算出ルール

- **稼働日**: 月〜金で、祝日でない日。祝日は `calendar.py` の祝日辞書(`dict[date, str]`)を使う。祝日データがなければ土日だけを除く。
- **1日の稼働枠**: 始業時刻から `Project.daily_hours`(既定 6.5h)時間。連続とし、昼休みは考慮しない。始業時刻は `Project.work_start`(新規、既定 9:00)。
- **開始日時の扱い**:
  - 稼働日の稼働枠の中なら、その時刻から数える。
  - 稼働日の始業前なら、始業時刻から数える。
  - 稼働枠の終了後や非稼働日なら、次の稼働日の始業時刻から数える。
- **工数の消費**: 稼働日ごとにその日の残り枠を使い、使い切ったら次の稼働日の始業時刻へ進む。工数がちょうど枠を使い切る場合、終了はその日の枠の終端とする(翌日の始業にはしない)。
- **工数が 0 または未設定**: 終了は算出しない。
- **`daily_hours` が 0 以下、または 24 超**: 算出しない(エラーにせず終了は空のまま)。無限ループにしない。24 超は、1日の稼働枠が日をまたぐため対象外とする。
- 例: 金曜 9:00 開始・工数 15h・6.5h/日 → 金 6.5h、月 6.5h、火 2.0h で、終了は火曜 11:00。

## 構成

| ファイル | 変更 |
|---|---|
| `models.py` | `Project.work_start: time = time(9, 0)` を追加 |
| `storage.py` | `work_start` を `isoformat` で保存・復元。ないファイルは 9:00 で読む |
| `timeline.py` | 純粋関数を追加(下記) |
| `views.py` | タスクの保存前に終了を補完する。チャートに現在日時の取得関数を渡す |
| `gantt.py` | 予定超過のタスク行を赤系の背景にする。現在日時の取得関数を差し替え可能にする |
| `forms.py` | 変更なし。入力検証は従来どおりで、補完は保存後に `views` が行う |

`timeline.py` に追加する純粋関数(NiceGUI に依存しない):
- `is_workday(day, holidays) -> bool`
- `calc_end(start, effort_hours, daily_hours, work_start, holidays) -> datetime | None`(算出しない場合は `None`)
- `fill_end(task, project, holidays) -> Task`(開始あり・終了なし・工数 > 0 のときだけ終了を入れた新しい Task を返す。それ以外は同じ Task を返す)
- `is_overdue(task, now) -> bool`(終了あり・状態が `Status.DONE` でなく・`now` が終了より後)

## データの流れ

1. ダイアログで保存された Task を、`MainView` が `fill_end` に通してからプロジェクトに入れる。
2. 補完に使う祝日は、`MainView` が持つ現在の祝日辞書。祝日が後から取得されても、保存済みの終了は自動では変えない。終了が入っているタスクは、工数を編集しても終了を自動では変えない。終了を空にして保存すると再計算される。
3. チャートは、再描画のたびに現在日時を取得して `is_overdue` を判定する。定期的な自動更新はしない。

## 表示

- 予定超過のタスク行(名前の列とチャート側の行全体)に、薄い赤の背景(`rgba(239, 83, 80, 0.18)` 程度)を付ける。
- バーの色(利用者が指定した色)は変えない。
- 状態が「終了」のタスクは赤にしない。

## エラー処理

- 算出できない場合(工数なし、`daily_hours` が 0 以下、開始なし)は終了を空のままにし、通知は出さない。
- 終了が手入力されているタスクは変更しない。

## テスト

- `timeline`: `is_workday`、`calc_end`(上の例、枠ちょうど、始業前・終業後・土日祝の開始、連休と年またぎ、工数 0、`daily_hours` が 0 以下、祝日データなし)、`fill_end`(手入力の終了を上書きしない)、`is_overdue`(終了状態、終了なし、境界)を、純粋関数のユニットテストで確認する。
- `gantt`: 現在日時を固定して、予定超過の行だけが赤背景になり、状態が「終了」の行は赤にならないことを確認する。
- `views`: 開始と工数だけでタスクを保存すると終了が補完されてバーが出ること、終了を手入力した場合は変わらないことを確認する。
- `storage`: `work_start` の保存・復元と、`work_start` のない古いファイルの読込を確認する。
