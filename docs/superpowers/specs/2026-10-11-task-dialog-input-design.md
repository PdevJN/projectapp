# タスクの追加・編集ダイアログの入力の見直し 設計

日付: 2026-10-11

## 目的

タスクの追加・編集ダイアログを、登録しやすくする。課題は、(1) 項目が多くて縦に長い、(2) 日付・時刻の入力が手間、(3) 担当・工数の入力が手間、の 3 つ。

## 決めたこと(あなたの回答)

- レイアウトを 2 種類にし、ダイアログ内で切り替える。選んだものは`config.json`に保存し、次回も使う
  - `予定・実績`: 名前・開始予定・完了予定・工数・締切・実績・状態
  - `すべて`: 今のダイアログと同じ(種別・カテゴリ・担当・先行・優先度・リンク・色を含む)
- 日付: ショートカット(今日・明日・来週月)、省略形の入力(`10/15`・`1015`)、開始予定・完了予定を横並びのコンパクトに
- 時刻: 省略形の入力(`9`・`930`・`9:30`)
- 工数: プリセット(0.5・1・2・4・8h)、単位(時間・日・週・月)の選択。参考値として、1 月の稼働可能時間の合計と、標準稼働時間(8h)での合計を並べて出す
- 担当者: メンバーを選んだときだけ、割り当て率を出す
- アプローチ A: 同じ入力の部品を、表示・非表示で切り替える(別々のフォームは作らない)

## 前提(変えない)

- 保存形式(`version`)。工数は時間で保存し、単位は入力の換算だけ
- 種別(通常・チェックポイント)は、どちらのレイアウトでも出す(項目の構成が変わるため)。チェックポイントの欄の出し入れ・状態の選択肢は今のまま
- 隠した項目の値は保持し、保存でも失わない。変更の判定(`current()`)・保存・閉じる確認は、隠した項目も含めて今のまま
- 「時刻を指定」のチェックは残す
- マーカー: 既存の`task-*`は変えない

## 1. レイアウトの切り替え

- ダイアログのタイトルの下に、`予定・実績` / `すべて` の切り替え(`ui.toggle`、マーカー`task-layout`)を置く
- 初回(設定がないか、不正な値)は`すべて`。選ぶと`config.json`の`task_layout`(`"all"` か `"schedule"`)に保存する。保存できなければ、画面には反映して、通知だけ出す(倍率の保存と同じ)
- `予定・実績`で隠す: カテゴリ・担当者・換算の表示・先行タスク(とそのヒント)・優先度・リンク・色。出す: 種別・名前・開始予定・完了予定・工数・締切・実績・状態
- 可視性は 1 か所(`refresh_visibility`)で決める。`欄が見える = レイアウトが出す ∧ 種別が出す`。チェックポイントのときに隠す欄(開始予定・完了予定・工数・担当・実績)は、レイアウトに関わらず隠す
- 途中で切り替えても、入力は残る

## 2. 日付・時刻の入力

純粋関数のモジュール`dateinput.py`(日付と時刻の入力の整形。NiceGUI に依存しない)を足す。

- `parse_date_input(text, today, roll_forward) -> str | None`: 次の形を`YYYY-MM-DD`に直す。読めないとき、または存在しない日付のときは None
  - `YYYY-MM-DD`・`YYYY/M/D`・`YYYYMMDD`
  - `M/D`・`MMDD`(4 桁): 年は`today`の年。`roll_forward`が真で、その日が`today`より前なら、翌年にする
- `shortcut_dates(today) -> dict[str, date]`: `今日`・`明日`・`来週月`(今日が属する週の次の週の月曜。今日が月曜でも +7 日)
- `parse_time_input(text) -> str | None`: 次の形を`HH:MM`に直す。読めないとき、または範囲外(時は 0〜23、分は 0〜59)のときは None
  - `H`・`HH`(→ `HH:00`)、`HMM`・`HHMM`(3〜4 桁。下 2 桁が分)、`H:MM`・`HH:MM`
- 入力欄を離れたとき(`blur`)、読めたら正式な形に直す(日付も時刻も)。読めないときは、そのまま(エラーは、今の保存時の検証が出す)。時刻は、開始予定・完了予定・締切・実績のすべての欄に使う
- `roll_forward`: 開始予定・完了予定・締切は真(予定は先のことなので)。実績は偽(過去の日付が普通)
- ショートカットのチップ(マーカー`task-{key}-shortcut-{today|tomorrow|next-monday}`)を、開始予定・締切の日付の下に、完了予定は「手で指定」のときだけ出す。押すと、日付の欄にその日を入れる(時刻は変えない)

## 3. コンパクトな並び

- ダイアログの幅を 36rem から 44rem にする(`max-w-full`のまま)
- 開始予定と完了予定は横に並べる(今のまま)。各列の中は、`[日付][時刻]`を 1 行にする(時刻は「時刻を指定」がオンのときだけ並ぶ)。「時刻を指定」のチェックは、列の見出しの右に置く(マーカーは変えない)
- 締切は、次の行に、同じ作りで出す(今のまま)

## 4. 工数

`EffortField`(`task_dialog.py`)にまとめる。ダイアログは、`effort.value`(時間。`float | None`)と`on_value_change`で使い、今の`ui.number`と同じ扱いにする。

- 数値の入力(マーカー`task-effort`)・単位の選択(`task-effort-unit`。`時間`・`日`・`週`・`月`。初期値は`時間`)・プリセットのチップ(`task-effort-preset-0.5`・`-1`・`-2`・`-4`・`-8`。時間で入る)
- 換算(純粋関数。`effortunits.py`): `1日 = 稼働可能時間`、`1週 = 5日`、`1月 = 20日`(`WORKDAYS_PER_WEEK = 5`、`WORKDAYS_PER_MONTH = 20`)。`to_hours(value, unit, daily_hours)`・`from_hours(hours, unit, daily_hours)`。時間は`HOURS_DECIMALS`(2 桁)に丸める。稼働可能時間が使えない値(0 以下・非有限)のときは、既定の 6.5h を使う
- 時間が正本: 数値を編集すると、時間 = 数値 × 換算 を保持する。単位だけを切り替えたときは、時間を変えず、数値の表示だけを新しい単位へ直す(丸めのずれを溜めない)。プリセットは、時間を直接入れて、数値を今の単位へ直す
- 参考値(マーカー`task-effort-reference`): 単位が`時間`以外のとき、換算後の時間を出す(`= 130h`)。単位が`月`のときは、次も出す: `1月 = 20日 × 6.5h = 130h / 参考: 標準 8h × 20日 = 160h`(8h は`STANDARD_WORK_HOURS`)
- 編集で開いたときは、保存した時間を`時間`で出す

## 5. 担当者

- 割り当て率の欄は、メンバーを選んだ行だけ出す(今は、選ぶまで無効)。メンバーを「(なし)」に戻したら、また隠す
- 割り当て率の値は、隠しても保持する。保存・換算の計算は今のまま(メンバーなしの行は、数えない)
