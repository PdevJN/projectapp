# 設定値のエクスポート・インポートの設計(要望 78)

> **状態**: 実装済み(PR #120。2026-10-29)。実装計画 [`plans/2026-10-29-settings-export-import.md`](../plans/2026-10-29-settings-export-import.md)— 要望 78。

## 目的

プロジェクトの設定値とメンバーの設定値を、専用のファイルに書き出し(エクスポート)、別のプロジェクトへ取り込める(インポート)ようにする。

- 使う場面は 3 つ: 新規プロジェクトの雛形、稼働中のプロジェクトへの反映、別の人・別のマシンへの受け渡し(git を使わない)。
- 要望 77(既存プロジェクトからの引き継ぎ)は、この仕組みの突き合わせと検証を呼ぶ形で、後から足せるようにする。77 の入口とタスクの取り込みは、この設計に含めない。

## 決めたこと(2026-10-29 に確認済み)

| 項目 | 決定 |
| --- | --- |
| 書き出しの範囲 | 全部入りで書き出し、取り込み時に区分ごとに選ぶ |
| 形式 | 専用の設定ファイル(`kind` と `version` つきの JSON)。タスクの空のプロジェクトファイルにはしない |
| 重複の扱い | 取り込み時に、項目ごとに「上書き」か「スキップ」を選ばせる |
| 入口 | `ファイル`メニューに`設定を取り込む`、`エクスポート`メニューに`設定を書き出す` |
| 編集の扱い | 取り込みは未保存の編集で、元に戻す 1 ステップ。書き出しはプロジェクトを変えず、変更扱いにもしない |

## ファイル

- `{"kind": "projectapp-settings", "version": 1, ...}` の JSON(UTF-8)。拡張子は`.json`。
- 中身:
  - プロジェクト設定: `daily_hours`・`work_start`・`base_date`・`reference_mode`・`ratio_limit_upper`・`ratio_limit_lower`・`plantuml_overload_notice`・`actual_mode`。
  - `members`(名前・基本比率・稼働日の上書き〔メモを含む〕・アイコン・段階の選択)、`parameters`、`categories`、`url_templates`、`events`。
- 含めない: タスク・セクション・実績・先行・プロジェクト参照。
- 各要素の変換は、保存・読込の既存の関数(`storage`)を使う。要素の形式が変わったとき、設定ファイルも追従する。
- `version` は設定ファイル自身のもの(1)。キーのない区分は空として読む。このアプリより新しい`version`、`kind`の違い、JSON でないファイル、不正な値は拒否する(通知して何も変えない)。

## 書き出し

- `エクスポート`メニューの`設定を書き出す`。保存先はファイル保存ダイアログ(`export.ask_path`を流用。ネイティブのみ。Web モードでは項目を出さない)。既定のファイル名は`settings.json`。
- 書き出しは一時ファイル経由。メンバーが 0 人でも書き出せる。

## 取り込み

1. `ファイル`メニューの`設定を取り込む`でファイルを選ぶ(ネイティブのみ。Web モードでは項目を出さない)。読み込んで検証し、失敗なら通知して終わる。
2. 取り込みのダイアログを開く。区分は「プロジェクト設定」「メンバー」「パラメータ」「カテゴリ」「URL テンプレート」「イベント」。区分ごとにチェックがあり、既定はすべてオン(中身のない区分は出さない)。
3. 項目ごとの扱い:
   - 突き合わせの鍵: メンバー・パラメータ・カテゴリ・URL テンプレートは名前。イベントは`文字列・開始日・終了日`。
   - 開いているプロジェクトにない項目は「追加」(新しい`id`を振る)。
   - ある項目は「上書き」か「スキップ」(既定はスキップ)。イベントは、同じ鍵のものを重複とみなし、取り込まない(上書きの対象になる値がない)。
   - プロジェクト設定は、取り込む値と今の値を並べて示し、まとめて反映するか、しないかを選ぶ。
4. 上書きは、既存の`id`を保つ(タスクの担当・カテゴリの参照が切れない)。メンバーの稼働日の上書きとアイコンは、取り込んだ内容で置き換える。

### 整合

- メンバーの段階の選択は、取り込み後のパラメータと段階に合うものだけ残す(合わないものは外し、件数を通知する)。パラメータを取り込まない選択でも同じ。
- 名前の重複は作らない(スキップか上書きなので、追加は新しい名前だけ)。追加と上書きの後の結果は、`ratios.validate_parameters`・`categories.validate_categories`・`urls.validate_templates`・`events.validate_events`・`workdays.validate_work_days`で検証する。
- 相対比率の上限・下限が変わるときは、設定ダイアログと同じ「見直して適用」の確認(要望 75)を通す。`キャンセル`ならプロジェクト設定の反映だけを取り消し、その旨を通知する。稼働可能時間の変更に見直しの確認はない(換算率が変わらず、設定ダイアログにもない)。
- 全体の結果を`dumps_project` → `parse_project`で検証する。通らなければ取り込まず、理由を通知する。
- 成功したら`after_edit`を 1 回呼ぶ(未保存の扱い、元に戻す 1 ステップ)。通知は`取り込みました(メンバー 2 件、パラメータ 1 件、…)`に、スキップ・外した選択の件数を添える。

## 構成

| モジュール | 役割 |
| --- | --- |
| `settings_io.py`(新規) | 純粋関数(NiceGUI に依存しない)。`build_settings`(`Project` → ファイルの辞書)、`dumps_settings`・`write_settings`(一時ファイル経由)、`parse_settings`(検証つきの読み込み)、`plan_import`(取り込み内容と今のプロジェクトから、項目ごとの追加・重複を求める)、`apply_import`(選択に従って`Project`を変える。不正なら`ValueError`で何も変えない)、`summary`(通知文) |
| `settings_dialog.py`(新規) | 取り込みのダイアログ(区分のチェック・項目ごとの上書き/スキップ・プロジェクト設定の比較) |
| `views.py` | メニューの項目 2 つと、`MainView`の取り込み・書き出しの流れ(`after_edit`) |
| `docs/development.md`・`CLAUDE.md` | 仕様とモジュール構成を追記 |

## テスト

- 往復: 書き出し → 取り込みで、全区分が同じになる(空のプロジェクトへ)。
- 重複: 追加・上書き(`id`を保つ)・スキップ。イベントの重複。
- 整合: 段階の選択の外れ、パラメータを取り込まないとき、検証エラーのときは何も変わらない。
- 拒否: `kind`違い・新しい`version`・JSON でない・不正な値。
- 取り込みが元に戻す 1 ステップであること、書き出しがプロジェクトを変えないこと。
- メニューの出し分け(Web モードでは出さない)。

## 含めないもの

- 要望 77(既存プロジェクトからの引き継ぎ)の入口、タスク・実績・セクションの書き出し・取り込み。
- 区分の中の項目単位の選択(区分ごとのチェックと、重複の項目ごとの選択まで)。
- 設定ファイルの 3 者マージ(プロジェクトファイルではないので、git の対象外)。
