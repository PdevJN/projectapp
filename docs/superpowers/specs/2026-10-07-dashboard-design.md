# ダッシュボード 設計書

要望 6(2026-10-04 に受領)。

## 目的

プロジェクト全体の状況を、1 つの画面で確かめられるようにする。ガントチャートでは、タスクを 1 つずつ見ないとわからない次の 4 点を、まとめて出す。

1. 進捗と遅れ(全体は順調か。何が遅れているか)
2. 人ごとの負荷(誰に仕事が集中しているか)
3. 工数の予定と実績(予定どおりの時間を使っているか)
4. 期限とマイルストーン(これから何がいつ締切か)

## 範囲

**含む**:
- メイン画面の、ガントチャートとダッシュボードの切り替え(ヘッダーのボタン。ESC か「戻る」で戻る)。
- 期間の選択(`今週`・`今月`・`全期間`)。
- 4 つの柱の集計(NiceGUI に依存しない純粋関数)と、表示。

**含まない**:
- ダッシュボードの画像・ファイルへの書き出し(エクスポートはガントチャートだけ)。
- 一覧の行をクリックして、タスクの編集ダイアログやガントチャートの位置へ移ること。
- 時系列の推移のグラフ(バーンダウンなど)。保存している実績から作れるが、別の要望にする。
- 残り工数の表示、セクションごとの集計、プロジェクトをまたぐ集計。
- 期間・表示の保存(絞り込みやプレビューの設定と同じく保存しない)。

## 決定事項(確認済み)

- **表示の場所**: メイン画面の切り替え(プレビューの出入りと同じ作り)。広い面積が使え、4 つの柱を並べられる。
- **4 つの柱**: 進捗と遅れ、人ごとの負荷、工数の予定と実績、期限とマイルストーン。
- **期間**: `今週`・`今月`・`全期間` から選ぶ(今日を基準にする)。
- **負荷と予定の数え方は、既存の割り当て超過(縞)と同じ前提**(案 A)。タスクは、開始予定から完了予定までの稼働日に、毎日 `稼働可能時間 × 割り当て率` を使うものとして数える。画面の縞とダッシュボードが同じ数字を指すようにする。工数の日割り(案 B)は、縞と数字がずれるので採らない。
- **保存データは増やさない**。集計は、開くたび・期間を変えるたびに、プロジェクトから計算する(完了予定を保存しない方針と同じ)。
- **描画は NiceGUI の要素と CSS**(外部のチャートライブラリは使わない。`CLAUDE.md` の実装上の注意)。

## 期間

`PeriodKind`(`今週`・`今月`・`全期間`)と、`Period(start: date, end: date)`(両端を含む)。`period_for(kind, today, project, holidays)` で決める。

- `今週`: 今日を含む、月曜から日曜。
- `今月`: 今日を含む月の、1 日から月末。
- `全期間`: 全タスクの、開始予定・完了予定・締切・実績の、最も早い日から最も遅い日まで。日付をもつタスクがなければ、今日の 1 日。

期間の初期値は `今週`。

## 集計

`dashboard.py`(新規。NiceGUI に依存しない)の `summarize(project, period, now, holidays) -> Dashboard`。`now` は、現在時刻(テストで固定できるよう、引数にする)。

### 1. 進捗と遅れ(期間に影響されない。現在の状態)

- **全体の進捗率**: タスクごとの進捗を、重みつきで平均する。進捗は、状態が「終了」なら 100、そうでなければ `current_progress`(未入力は 0)。重みは、`effort_hours`(0 以下なら 1.0)。タスクがなければ `None`。
- **状態別の件数**: `未着手`・`実行中`・`一時停止`・`終了`。
- **予定超過のタスク**: `is_overdue(task, project, holidays, now)` が真のもの。行は、タスク名・担当者・超過の基準(締切と完了予定のうち、過ぎているもので早いほう)。基準が早い順に並べる。

### 2. 人ごとの負荷(期間に影響される)

数えるタスクは、割り当て超過と同じ(`timeline.counted_span`。担当者がメンバーにいて、状態が「終了」でなく、開始予定と完了予定があるもの)。`_counted_span` を、`counted_span` へ公開する(名前を変えるだけ)。

- 期間内の、稼働日(`is_workday`)ごとに、そのメンバーの割り当て率の合計を出す。タスクは、期間(`[開始予定, 完了予定)`)がその日に重なれば、その日に数える。
- メンバーごとの値(`LoadStats`): `average`(稼働日の平均。割り当て率の合計。タスクのない日は 0)、`peak`(最大の日)、`overload_days`(100% を超えた稼働日の数。`OVERLOAD_EPSILON` を使う)。期間に稼働日がなければ、すべて 0。
- 表示は割合(%)。100% を超える日があれば、強調する。

### 3. 工数の予定と実績(期間に影響される)

- **予定時間**: タスクごとに、`稼働可能時間 × 割り当て率 × 期間と重なる稼働日の数` を、担当者の合計にする。数えるタスクは、開始予定と完了予定があるもの。**状態が「終了」のタスクも数える**(実績と比べるため。負荷とは違う)。担当者がメンバーにいない(または担当者なし)ものは、`未割り当て` にまとめる。
- **実績時間**: 実績の各区間と、期間(その日の 0 時から、終了日の翌日の 0 時まで)の重なりの長さ(時間)を、担当者ごとに合計する。実行中(`end` なし)の区間は、`now` までとする。
- 行は、メンバーの順に、最後に `未割り当て`(予定・実績のどちらかがあるときだけ)。全体の合計も出す。

### 4. 期限とマイルストーン(期間に影響される)

- 状態が「終了」でないタスクの、**締切**(`deadline`)と**完了予定**(`effective_end`)のうち、期間の日に入るもの。1 つのタスクが両方入れば、2 行にする。
- 行は、日時・種別(`締切`・`完了予定`)・タスク名・担当者・予定超過か。日時の順に並べる。

## 画面

### 切り替え

- ヘッダーに「ダッシュボード」ボタン(`icon="dashboard"`、マーカー `open-dashboard`)を足す。
- 押すと、ヘッダーとガントチャート(ツールバーとチャート)を隠し、ダッシュボードを出す。ダッシュボードの上部に、タイトル・期間の切り替え(トグル)・「戻る」ボタンを置く。ESC でも戻る(`MainView.on_key`)。
- 戻ると、ヘッダーとガントチャートを元に戻す。ガントチャートは作り直さない(絞り込み・折りたたみ・スケールは変えない)。非表示で、スクロール位置が失われる場合は、戻るときに復元する(要望 16 と同じ種類の問題。実装で確かめる)。
- プレビューとは同時に開かない(どちらもヘッダーを隠すので、ボタンが押せない)。
- 読み取り専用。プロジェクトは変えない(保存・編集中の判定に影響しない)。

### レイアウト

- 4 つの柱を、2 列 × 2 行のカードで並べる(狭いウィンドウでは 1 列)。
  1. 進捗と遅れ: 進捗率(数字と横棒)、状態別の件数、予定超過の一覧。
  2. 人ごとの負荷: メンバーごとの横棒(平均)とピークの印、100% 超の日数。
  3. 工数の予定と実績: メンバーごとの、予定と実績の 2 本の横棒と時間。
  4. 期限とマイルストーン: 日時順の一覧。予定超過は赤。
- 横棒は、div の幅(%)で描く。色は、テーマに追従する(ライト・ダーク)。超過は、既存の予定超過の赤みと同じ系統の色にする。色の選び方・凡例・数値の見せ方は、`dataviz` の指針に従う。
- タスクがない、またはデータがない柱は、「データがありません」と出す。

### モジュールと責務

- `dashboard.py`: `PeriodKind`・`Period`・`period_for`・`summarize` と、結果の型(`Dashboard`・`Progress`・`OverdueRow`・`WorkloadRow`・`LoadStats`・`DueRow`)。NiceGUI に依存しない。
- `dashboard_view.py`(新規): `Dashboard` を受け取って、カードと棒を描く(`DashboardView.show(project, kind)` / `hide()`)。
- `views.py`: ボタン・ESC・出入り(`open_dashboard` / `close_dashboard`)・`now` と祝日の受け渡しだけ。
- `gantt.py`: ツールバーとチャートの表示・非表示の切り替え(`set_visible`)を足す。
- `timeline.py`: `_counted_span` を `counted_span` へ公開する。

## エラーと注意

- 日付の範囲外・不正な値(NaN の工数・割り当て率など)は、読込が検査済み。集計は、使えない値(`effective_end` が `None` など)のタスクを、その柱から外して、落とさない。
- 稼働可能時間が 0 以下の値は、設定が検査済み(0 超 24 以下)。
- 稼働日が 0 日の期間(祝日・土日だけ)は、負荷と予定をすべて 0 とし、割り算をしない。
- 実績の区間が期間外だけのとき、実績時間は 0。
- 担当者名がメンバーにいないタスクは、負荷には数えず(`counted_span` の仕様)、工数には `未割り当て` に入れる。

## テスト

- `period_for`: 今週(月曜・日曜をまたぐ日)、今月(月末・年末)、全期間(日付なし・実績だけ)。
- 進捗: 重み(工数あり・なし・0)、状態「終了」の 100%、未入力の 0%、タスクなし。
- 予定超過の行: 締切だけ・完了予定だけ・両方・基準の選び方・並び順・終了タスクの除外。
- 負荷: 1 人・複数のタスクの重なり(100% 超)・終了タスクの除外・期間外・稼働日 0・祝日・ちょうど 100%(超過にしない)。割り当て超過(`overallocations`)の期間と、`overload_days` が一致すること。
- 工数: 終了タスクの予定への算入、実績の期間との重なり(期間をまたぐ区間)、実行中(`now` まで)、未割り当て、合計。
- 期限: 締切と完了予定の両方、期間の端、終了タスクの除外、超過の印、並び順。
- 画面: ボタンで出る・戻る・ESC で戻る、期間の切り替えで描き直す、戻ったあとガントチャートの状態(絞り込み・スケール)が変わらない、プロジェクトが変更扱いにならない、データなしの表示。
- `counted_span` の公開で、既存の割り当て超過のテストが変わらないこと。
- チャートの見た目(ライト・ダーク、ウィンドウ幅)は、ネイティブでの実機確認で見る。
