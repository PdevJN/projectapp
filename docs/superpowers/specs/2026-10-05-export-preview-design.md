# エクスポートとプレビュー 設計書

## 目的

ガントチャートを、資料に貼ったり、印刷したりできるように、PNG 画像として保存する。保存の前に、プレビューで、期間・スケール・表示項目を選んで、出力する見た目を確認できるようにする。`.claude/MEMORY.md` の要望 2 に対応する。

- 要望 2: ガントチャートのエクスポートと、プレビューモード

## 範囲

**含む**: メイン画面のプレビューモード(読み取り専用の表示、期間・スケール・表示項目の選択)、PNG への画像化と、保存先を選ぶ保存。

**含まない**:
- PNG 以外の形式(PDF、SVG、CSV、Excel)
- 画像の分割保存(タイル)
- プレビューの設定の保存(ファイル・`config.json`)
- 色やフォントの変更、タイトルや凡例の付加
- 絞り込み(担当者・検索)の、プレビュー内での変更

## 決定事項

- 使い道は、資料への貼り付けと印刷。見た目を、そのまま出力する。
- 形式は PNG を、画面内で画像化して、直接保存する(spike で、WKWebView 上の動作を確認した。下記)。
- プレビューは、メイン画面を、プレビューモードに切り替える形にする(ダイアログや別ウィンドウにはしない)。
- プレビューで切り替える表示項目は、次の 2 つ。ほかの項目は、常に表示する。
  - 名前欄のチップと進捗(ProjectCode、担当、進捗)
  - 予定超過の赤みと、割り当て超過の縞
- 期間・スケールは、プレビューで選ぶ。担当者と検索の絞り込みは、メイン画面の今の条件を使い、プレビューでは変えない。
- プレビューの設定は、保存しない。開くたびに、初期値に戻る。

## spike の結果(2026-10-05。使い捨ての試作。コミットしていない)

- html-to-image(1.11.11、MIT、約 19KB)で、WKWebView 内のガントチャートの DOM を PNG にできた。保存は、画像を base64 で Python に渡して書き込んだ。
- ライト・ダーク、日次・週次・月次のすべてで、色・チップ・進捗・優先度の背景・点線・縞・土日の背景・予定超過の赤み・取り消し線が、画面どおりに出た。
- 時間は約 0.5〜0.9 秒、サイズは約 200〜330KB。
- アイコン(Material のフォント)は、画像に埋め込まれず、`add` のような文字で出た。
- Safari 系のキャンバスは、幅が約 16,384px まで。1 年分を日次(幅約 15,240px)にして、倍率 1 では出力できた(約 3.2 秒)。倍率 2(幅約 30,480px)では、16,384px に縮小されて出た(空白にはならない)。

## 画面(`views.py`、`gantt.py`)

### 切り替え

- メイン画面のヘッダーに「エクスポート」ボタンを足す(「メンバー」の隣)。押すと、プレビューモードに入る。
- プレビューモードでは、次のようにする。
  - ヘッダー(プロジェクト名、ファイル選択、開く・保存・設定・メンバー)と、ガントチャートのツールバー(スケール、セクション追加、検索、担当者)を隠し、プレビュー用のバーを出す。
  - ガントチャートは、読み取り専用で、描き直す(後述)。
  - テーマの FAB、ヘルプのボタンは、そのまま出す。
- 戻るのは、「戻る」ボタンか ESC。戻ったときは、通常のヘッダーとツールバーを出し、ガントチャートを通常の設定で描き直す。スクロール位置と絞り込みは、プレビューに入る前のままにする(絞り込みは変えないので、スクロール位置だけを保つ)。
- プレビュー中は、プロジェクトの切り替えや保存はできない(ヘッダーを隠すため)。

### プレビュー用のバー

| 項目 | 内容 |
|---|---|
| 期間 | 開始日・終了日の入力(日付の選択)。初期値は、今の表示範囲(`visible_range`)。 |
| スケール | 日次・週次・月次。初期値は、メイン画面の今の値。メイン画面には戻さない。 |
| チップと進捗 | チェック(既定オン) |
| 予定超過の赤みと割り当て超過の縞 | チェック(既定オン) |
| 戻る | ボタン |
| 画像として保存 | ボタン |

- 開始日が終了日より後のときは、「画像として保存」を無効にして、「期間は、開始日が終了日以前になるように入れてください」を出す。
- 画像の幅が、倍率 1 でも 16,384px を超えるとき(日次で約 1 年以上)は、「画像が大きいため、縮小して保存されます」の警告を出す(保存はできる)。

### 描画の設定(`gantt.py`)

`GanttChart` に、表示の設定 `ViewOptions` を持たせる。通常の画面は、既定値(今までと同じ)を使う。

```python
@dataclass(frozen=True)
class ViewOptions:
    period: tuple[date, date] | None = None  # 表示する期間 [開始日, 終了日]。None は visible_range
    show_chips: bool = True      # 名前欄のチップと進捗
    show_alerts: bool = True     # 予定超過の赤みと、割り当て超過の縞
    read_only: bool = False      # 編集の部品・クリック・ドラッグをなくす
```

- 期間: `build_columns` に、開始日・終了日を渡せるようにする(`visible_range` の代わり)。終了日は含む(`[開始日, 終了日 + 1 日)`)。列の数の下限(`MIN_COLUMNS`)は、そのまま守る。
- 期間と重ならない棒(予定・実績・区間の点線・進捗の塗り)は、描かない(端に、最小幅の細い棒が出ないようにする)。重なる棒は、列の端で切る(今の `_position` の挙動)。締切の ◆ は、期間外なら出ない(今の挙動)。行(タスク名)は、棒がなくても出す。
- `show_chips` が偽のとき、名前欄に、ProjectCode・担当・進捗のチップを出さない(名前は、その分、長く見える)。
- `show_alerts` が偽のとき、予定超過の行の赤い背景と名前欄の赤み(`OVERDUE_COLOR`)、割り当て超過の縞を出さない。
- `read_only` が真のとき、次を出さない・無効にする。
  - ツールバー、各セクションの追加ボタン、「タスク追加」の行(アイコン付きの編集部品はすべて)。
  - タスク名・棒・実績・締切のクリックと、ドラッグ(`draggable` などの属性)。
- 優先度の背景色、状態の色、進捗の枠線・印は、常に出す。

## 画像化と保存

### 画像化(JS)

- 同梱する html-to-image を、プレビューモードに入ったときに読み込む(`src/projectapp/static/html-to-image.js`。NiceGUI の静的ファイルとして配る。配布物に含める)。
- 対象は、プレビューのガントチャートの中身(`chart-scroll` の中の、`position: relative` で幅が `px` の要素)。スクロールの外へはみ出す幅と高さの全体(`scrollWidth`、`scrollHeight`)を撮る。
- 背景色は、ライトは白、ダークは `body` の背景色(`--q-dark-page`)。
- 倍率は `min(2, 16384 / 幅)`(純粋関数 `export_pixel_ratio(width) -> float`)。
- 結果は、PNG の base64(`data:image/png;base64,…`)の文字列として、Python に返す。画像化の失敗は、JS 側で捕まえて、エラーの文字列を返す。タイムアウトは 90 秒。

### 保存(Python)

- 「画像として保存」を押すと、次の順で進む。
  1. JS で画像化し、base64 を受け取る。
  2. 保存先を、pywebview のファイル保存ダイアログ(`app.native.main_window.create_file_dialog(dialog_type=FileDialog.SAVE, save_filename=…, file_types=("PNG 画像 (*.png)",))`)で選ぶ。
  3. 選ばれたパスに、デコードした PNG を書き込む。拡張子がなければ `.png` を付ける。
- 既定のファイル名は `<プロジェクト名>_<YYYYMMDD>.png`。ファイル名に使えない文字は、既存の名前の検証(`validate_name` と同じ規則)に合わせて置き換える。
- 保存できたら「保存しました」を通知する。ダイアログをキャンセルしたら、何もしない。
- 画像化と保存先の選択は、差し替えられる部品(`ImageExporter`)に切り出す(テストでは、画像のバイト列と保存先を返す偽物に差し替える)。

## エラー処理

- 画像化に失敗したとき(JS の例外、タイムアウト)は、「画像を作れませんでした」を通知して、プレビューに留まる。
- 書き込みに失敗したとき(権限、ディスクの空きなど)は、理由を通知して、プレビューに留まる。書きかけのファイルは、一時ファイル経由で書き、失敗したら残さない。
- 保存中は、ボタンを無効にして、二重に押せないようにする。
- ネイティブウィンドウでない環境(`app.native.main_window` が使えない)では、「画像として保存」を無効にして、理由を出す。

## 既存機能との関係

- 通常の画面の描画は変えない(`ViewOptions` の既定値が、今までと同じ)。
- 絞り込み(`task_filter`)は、プレビューでも、メイン画面の今の条件で効く。
- 点線・チップ・優先度の背景・状態の色は、そのまま画像に出る。
- 保存形式(プロジェクトファイル)は変えない。

## テスト

- `timeline`: 期間つきの `build_columns`(日次・週次・月次、下限、終了日を含む)。
- `gantt`: `ViewOptions` ごとの描画(チップの有無、赤み・縞の有無、読み取り専用で編集部品・クリック・ドラッグ属性がないこと)、期間と重ならない棒を描かないこと(予定・実績・点線)、期間の端で切ること、既定値で今までの描画と同じこと。
- `views`: プレビューへの出入り(ヘッダーとツールバーの切り替え、ESC、戻ったときに絞り込みが保たれること)、期間の検証(開始が後なら保存が無効)、幅が大きいときの警告、ネイティブでないときの無効化。
- 保存の流れ: 偽の `ImageExporter` で、成功(通知、書き込み)、キャンセル(何もしない)、画像化の失敗、書き込みの失敗、拡張子の補完、既定のファイル名。
- `export_pixel_ratio` の純粋関数のテスト(幅が小さい・ちょうど 8,192・大きい)。
- 実際の画像化は、自動テストでは確かめられない(WKWebView が要る)。実機で、ライト・ダーク、日次・週次・月次、長い期間を確認する。
- `docs/development.md` と `CLAUDE.md` に、プレビューと保存の説明を足す。

## 保留

- 期間を狭めたとき、期間にタスクがない行を隠すか(今回は、行は残す)。
- 画像に、プロジェクト名や日付の見出しを足すか(今回は足さない)。
- 画像化のライブラリのバージョンの更新方法(同梱ファイルの差し替え。更新の頻度は低い)。
- 倍率 1 でも 16,384px を超えるときの、タイルへの分割保存(今回は、縮小して保存)。
