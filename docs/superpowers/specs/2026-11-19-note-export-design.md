# 要望 153: メモを含んだタスクの書き出し・取り込み(設計)

## 目的

タスクのメモ(要望 150)は端末ごとのローカルで、プロジェクトのファイルとは別(`~/.projectapp/notes/`・git 管理外)に持つ。別の端末へ渡すために、CSV/TSV の`メモ`列として書き出し、取り込みでタスクのメモに戻せるようにする(往復)。

## 決定(利用者の回答)

- 主な用途: 別の端末へ渡す(往復)
- メモの形: プレーンテキスト(書式は往復で失われる)
- 出すかどうか: 書き出しダイアログの列の選択(`メモ`を選んだときだけ出す。既定は出さない)。列の位置は、他の列と同じ方法で並べ替えられる
- メモの改行は、すべて文字の`\n`に置き換える(1 セル 1 行)
- `メモ`列がない CSV は、これまでと同じく、メモなしで取り込む

## 構成

### 列

- `csv_profile.CsvField.NOTE`(表示名`メモ`)を追加する。`EXPORT_FIELDS`・`IMPORT_FIELDS`の両方に含める
- 別名(`ALIASES`): `メモ`・`ノート`・`note`・`notes`
- 既定のプロファイル・Smartsheet のプロファイルには入れない
- 書き出しダイアログで`メモ`の列を選んでいる間は、「メモを含みます(git 管理外の内容が出ます)」の注意書きを出す

### 変換(`notes.py`に純粋関数)

- `to_cell(html) -> str`: `sanitize`したあと、`<br>`・段落・リスト項目の境目を改行にし、タグを落とし、実体参照を戻す。末尾の空白行は落とす。`\`は`\\`に、改行は`\n`(2 文字)に置き換える。空のメモ(`is_blank`)は空文字
- `from_cell(text) -> str`: `\\`と`\n`を戻し、各行を`html.escape`して`<p>`で包む(空行は`<p><br></p>`)。HTML のタグとしては読まない。最後に`sanitize`を通す。空文字は空文字
- 取り込みの上限: メモ 1 件は`notes.MAX_NOTE_TEXT`(10000 文字)で切り詰める

### 書き出し(`csv_export.build_table`)

- `NOTE`の列は、通常タスクの行にだけ値を入れる(セクション行・参照行は空)
- 引数に、タスク id → メモの HTML を返す関数(`note_for`)を足す。なければ`NOTE`の列は空にする。呼び出し側(`views`)は`notes.load(project.name, task_id)`を渡す

### 取り込み(`csv_import`)

- `CsvImport`に`notes: dict[str, str]`(新しいタスク id → メモの HTML)を足す。`from_cell`が空でない行だけ入れる
- `メモ`列がなければ、空の辞書

### 取り込んだあとの扱い(`views`)

- 保存前の新規プロジェクトのメモは、今もすぐ`notes/<名前>/`へ書き、`save_as_new`が`notes.copy_project`で新しい名前へコピーする。取り込んだメモも同じ流れに乗せる(`apply_csv_import`が、`show_project`の前に`notes.save`で書く)
- 同名の既存プロジェクトのメモは、ファイル名がタスク id(ランダム)なので、上書きされない
- 保存せずに捨てたとき、`notes/<CSV のファイル名>/`に使われないメモが残る(害はない)

## 対象外

- PlantUML・担当者向けファイルは、メモを出さない(今のまま)
- `version`は 23 のまま。ファイルの形式は変わらない
- 取り込みの列の対応の保存(プロファイル)は、`NOTE`を含んでもよい(既存の仕組みのまま)

## テスト

- `to_cell`/`from_cell`: 往復(改行・`\`・`\n`の文字・`<`や`&`・空のメモ・`<script>`の混入・長さの上限)
- `build_table`: `NOTE`を選んだときの列の位置・値、選ばないときは列が出ない、セクション・参照行は空
- `parse_csv`: `メモ`列があるとき`notes`に入る、ないとき空、別名の対応
- `views`: `apply_csv_import`が、取り込んだメモを`notes/<名前>/`に書く
- smoke のタグは`docs/development.md`の基準に従う
