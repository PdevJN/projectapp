# 実績の複数区間と記録方式の設定 設計書

## 目的

実績を、複数の区間(開始〜終了)で記録できるようにする。休んでいた期間をはさむ作業を、ひとつのタスクの実績として残し、ガントチャートでも途切れた形で見えるようにする。`.claude/MEMORY.md` の要望 15 に対応する。

実績の入力(`2026-10-04-actuals-design.md`)と進捗度(`2026-10-04-progress-design.md`)で「後続」とした部分。

## 範囲

**含む**: プロジェクトの記録方式(簡易/区間)の設定、タスク編集ダイアログでの複数区間の入力、区間の間の点線、複数区間のときの状態の提案。

**含まない**:
- ボタンで現在時刻を記録する入力
- 実績の外部インポートと API(5)
- 実績の合計時間の表示
- 区間の途中で状態が変わる履歴(状態は、今までどおりタスクにひとつ)

## 決定事項

- 記録方式はプロジェクトごと。`Project.actual_mode` は `"simple"`(既定)か `"intervals"`。
- 簡易は、今の画面のまま(区間は 0〜1 件)。区間は、行を足して複数の区間を入力する。
- 区間から簡易へは、2 区間以上のタスクがあるあいだは戻せない。区間のまま使い続けるか、先に区間を消す。
- 保存形式は変えない(実績は、方式にかかわらず区間のリスト)。方式は、入力の画面だけを決める。
- 区間の間(休み)は、別々の棒と、間をつなぐ細い点線で見せる。

## データ(`models.py`、`storage.py`)

```python
class Project:
    ...
    actual_mode: ActualMode = ActualMode.SIMPLE

class ActualMode(StrEnum):
    SIMPLE = "simple"
    INTERVALS = "intervals"
```

保存形式: プロジェクトの先頭の階層に `"actual_mode": "simple"` を出す。

読込:
- キーがない古いファイルは `simple`。
- 値が `simple` と `intervals` 以外は不正(「開けませんでした」)。
- 実績の検証は変えない。重なりと並び順は、読込では検証しない(手で編集した既存のファイルを開けなくしないため)。
- `simple` のまま 2 区間以上のタスクがあるファイルも開ける。このときのダイアログは、読み取り専用にする(今までどおり)。

## 設定ダイアログ(`forms.py` の `open_settings_dialog`、`views.py` の `apply_settings`)

- 稼働時間の下に、「実績の記録方式」の選択(簡易 / 区間)を足す。
- 2 区間以上のタスクがあるときは、「簡易」を選べなくし、「N 件のタスクに複数の区間があるため、簡易には戻せません」と出す。
- 適用は、稼働時間と同じ(確認なし。保存は自動ではせず、変更は「編集中」の判定に入る。同じ値なら何もしない)。
- 方式を `intervals` に変えたとき、既存の 0〜1 区間のタスクは、そのまま使える(変換は要らない)。
- 適用の関数 `apply_settings` は、方式も受ける。

## 編集ダイアログ(`task_dialog.py`、検証は `forms.py` の `build_task`)

**簡易**(`simple`): 今のとおり。

**区間**(`intervals`): 実績の段に、区間の行を縦に並べる。

- 1 行は「開始の日付・時刻」「終了の日付・時刻」「進捗度」と、行の削除ボタン。部品は簡易と同じ(`add_picker` など)。
- 段の下に「区間を追加」ボタン。押すと空の行を末尾に足す。
- 区間が 0 件のときは、行を出さず、ボタンだけを出す。
- 既存の実績が 2 件以上ある `intervals` のタスクも、そのまま編集できる(読み取り専用にしない)。
- `simple` で 2 件以上のタスクは、今までどおり読み取り専用。保存しても実績は書き換えない。

入力の規則(`build_actuals` を、行のリストを受ける形に広げる):

- 各行の規則は、今の簡易と同じ(日付と時刻は両方、開始なしの終了だけは不可、終了は開始以後、進捗度は 0〜100 の整数)。
- 開始・終了・進捗度がすべて空の行は、無視する。
- 区間は、開始の昇順に並んでいること。順序が違えばエラー(「区間は開始の早い順に入れてください」)。
- 区間は、重ならないこと(次の開始は、前の終了以後)。
- 終了のない(進行中の)区間は、最後の 1 つだけ。
- 進捗度は、入力のある値が、前の入力のある値以上(読込の規則と同じ)。
- エラーは、予定と同じく、入力欄の下に出してダイアログを閉じない。どの行かが分かる文にする(「区間 2: 終了が開始より前です」)。

閉じるときの確認と、変更の判定(`current()`)には、すべての行の入力値と、行の数を含める。

### 状態の提案(`forms.py` の `suggest_status`)

実績の入力が変わるたびに、最後の区間で判定する。

| 条件(最後の区間) | 提案 |
|---|---|
| 区間がない、または開始がそろっていない | 変えない |
| 終了がなく、進捗度が 100 | 変えない |
| 終了がなく、それ以外 | 実行中 |
| 終了があり、進捗度が 100 | 終了 |
| 終了があり、それ以外(`intervals` のとき) | 一時停止 |
| 終了があり(`simple` のとき) | 終了 |

- 簡易の提案は、今までのまま(終了があれば「終了」)。
- ユーザーが状態を手で選び直したあとは、そのダイアログを閉じるまで提案しない。提案で状態が変わったときの案内も、今までどおり。

## ガントチャート(`gantt.py`)

- 実績の棒は、区間ごとに今のまま描く(色は状態の色)。
- 隣り合う 2 区間のあいだ(前の終了から次の開始まで)に、細い点線を引く。
  - 高さは、実績の棒の中央。太さは 1px、`dashed`。色は状態の色(`--scolor`)。
  - 前の終了が次の開始と同じか後のとき(隙間がないとき)は引かない。
  - 進行中の区間は最後の 1 つなので、その後ろには点線を引かない。
  - 要素に `actual-gap-<key>-<ti>-<n>` の目印を付ける(`n` は、前側の区間の番号)。クリックで編集ダイアログを開く(実績の棒と同じ)。
  - 日次・週次・月次のどれでも、棒と同じ位置計算を使う。
- 超過判定と進捗度は、今までどおり(最後の区間の終了、入力のある最後の進捗度)。

## 既存機能との関係

- `copy_task`: 実績は空にする(今までどおり)。
- `shift_task`、`move_task`: 実績は変えない(今までどおり)。
- 絞り込み: 点線も、一致した行に同じように出す。

## エラー処理

- 読込の不正(`actual_mode` の値)は、「開けませんでした」の通知。現在のプロジェクトは変えない。
- 設定で簡易へ戻せないときは、選択肢を無効にして理由を出す。保存や適用の失敗は起きない。

## テスト

- `storage`: `actual_mode` の保存・読込、キーなし、不正な値、複数区間を持つ `simple` のファイル。
- `forms`: 区間の検証(順序、重なり、進行中は最後だけ、空の行の無視、進捗度の単調増加、エラーの文)、`suggest_status` の表、設定の適用(同じ値は何もしない、簡易へ戻せない条件)。
- `task_dialog`: 区間の行の追加と削除、変更の判定、`simple` で 2 件以上のときの読み取り専用、`intervals` で 2 件以上の編集。
- `gantt`: 点線の位置・太さ・色、隙間がないとき出ない、進行中の区間の前後、スケールごとの位置。
- `docs/development.md` と `CLAUDE.md` に、記録方式と点線の説明を足す。

## 保留

- 区間が多いタスクのダイアログの縦の長さ(スクロールにするか)は、実機で見てから決める。
- 区間ごとの進捗度の入力を、簡易では 1 件だけにしている現状と、区間のときの見た目の差は、実機で見てから決める。
