# プロジェクト参照の設計(要望 56)

> **状態**: 実装済み(実機確認待ち)— 要望 56。現在の仕様は実装後に [`CLAUDE.md`](../../../CLAUDE.md) へ反映する。

## 目的

タスクとして、他のプロジェクト(別のプロジェクトファイル)を参照できるようにする。参照した行は、参照先全体の予定・実績・進捗・遅延・負荷を、細かなタスクを見せずに、ガントチャートに載せる。クリックで参照先のプロジェクトへ切り替えられる。成功の目安は次のとおり。

- 編集ダイアログで種別`プロジェクト参照`を選び、参照先のファイルを選べる。
- ガントチャートに、参照先全体の予定(開始〜終了)・実績・進捗・遅延・負荷が出る。参照先の細かなタスクは出ない。
- 参照の方式を、プロジェクトの設定で`常に最新`(表示のたびに参照先を読む)と`スナップショット`(参照値を保存する)から選べる。
- 参照先のファイルが見つからなくても、画面は壊れない。通知を出し、行は残す。
- PNG・PlantUML に出る。

## 参照の方式

| | 内容 |
|---|---|
| `常に最新`(既定) | 表示のたびに、参照先のファイルを読んで算出する。値は保存しない。読み込みの結果は、ファイルの内容のハッシュでキャッシュする。 |
| `スナップショット` | 参照行ごとに、算出した参照値と取得日時を、このプロジェクトのファイルに保存する。表示は保存した値を使う。 |

- 設定ダイアログに`参照の方式`を足す(プロジェクトごと)。
- `スナップショット`へ変えると、全参照行のスナップショットをそのとき取る。`常に最新`へ戻すと、スナップショットは捨てる。
- `スナップショット`のとき、参照行の右クリックメニューの`更新`で、その行のスナップショットを今の参照先の値に取り直す。`常に最新`のときは押せない(理由はホバーに出す)。元に戻す・未保存の扱いは、ほかの編集と同じ。
- 見送り: 参照先をファイル名ではなく id で指す(ファイル名の変更に追従する)。全ファイルの形式に id を足す必要があり、今回の範囲を超える。

## データ(version 11)

- `TaskKind.REFERENCE`(`プロジェクト参照`)を足す。
- `Task.ref_project`: 参照先のファイル名(拡張子なし)。参照行だけが持つ。
- `Task.ref_snapshot`: スナップショット(参照値と取得日時)。参照行で、方式が`スナップショット`のときだけ持つ。
- `Project.reference_mode`: `live`(既定)・`snapshot`。
- 参照行が持つのは、名前・色・先行・締切・`ref_project`・`ref_snapshot`だけ。工数・担当・実績・進捗度・状態・種別以外の日程は持たない(カテゴリ・優先度・リンクも持たない)。
- キーのない古いファイルは、既定値(`live`・参照なし)で読む。このアプリより新しい`version`は拒否する。不正な種別・空の`ref_project`・自分自身を指す`ref_project`・不正なスナップショットは、読込を拒否する。

## 参照値の算出(`reference.py`)

NiceGUI に依存しない純粋関数。入力は、参照先の`Project`・祝日・今の日時。

- 数える対象は、参照先の通常タスクとチェックポイント。参照行は数えない(参照が循環しても再帰しない)。まとめは数えない。
- 予定の開始・終了: 全タスクの実効の開始の最小と、完了予定の最大(チェックポイントは締切)。実績の開始・終了: 実績の区間の最小と最大(進行中なら終了なし)。
- 進捗: 工数で重みづけした進捗率(ダッシュボードの`進捗と遅れ`と同じ規則)。
- 遅延: 予定超過のタスク数。
- 負荷: 参照先の中だけで数えた、割り当て超過の期間と、ピークの率・担当者(`timeline.overallocations`)。
- 数えるタスクがないときは、日程なしの参照値にする。
- `ReferenceValue`(frozen dataclass)で返し、スナップショットはこれと取得日時を JSON にしたもの。

## ガントチャート

- **行**: 帯は参照先全体の予定(開始〜終了)。進捗の塗りと、実績の線を重ねる。名前の欄には、`遅延 3件`・`負荷 130%` のチップを出す。遅延は帯の赤み、負荷は割り当て超過と同じ縞を、超過の期間に重ねる。細かなタスク名は出さない。
- **ホバー**: `基盤開発 9/7〜11/20 / 遅延 3 件 / ピーク負荷 130%(田中) / クリックすると開く`。スナップショットのときは取得日時も出す。
- **クリックで開く**: 名前と帯にマウスを乗せると下線が付き、クリックで参照先のプロジェクトを開く(`プロジェクトファイル`のコンボと表示を更新する)。プレビュー(読み取り専用)では開かない。
  - 未保存の編集があるときは、既存の`保存して開く`・`保存せず開く`・`キャンセル`。
  - スナップショットで、保存した値が今の参照先と違う(未更新の)ときは、`更新して開く`・`更新せず開く`・`キャンセル`。`更新して開く`は、取り直して保存の対象にしてから開く。
  - 順序: スナップショットが古いときは、先に更新の確認を出す。`更新して開く`で更新すると未保存になるので、続けて未保存の確認(`保存して開く`・`保存せず開く`・`キャンセル`)が出る。古くないときは、未保存の編集があれば、未保存の確認だけが出る。
- **見つからないとき**: プロジェクトを開いたときに通知を出す(まとめて 1 回)。`常に最新`は、帯・チップ・縞を出さず、名前の欄に`参照先が見つかりません`を出す。`スナップショット`は、保存した値で出し、見つからないことも示す。行は残すので、`編集`で参照先を直す・`削除`で消せる。
- **追加・編集**: ダイアログの種別トグルに`プロジェクト参照`を足す。入力は、参照先(格納先のプロジェクトから、自分を除いて選ぶ)・名前・色・先行・締切。ほかの項目は隠す。
- **右クリックメニュー**: `編集`・`コピー`・`名前の変更`・`削除`・`更新`。`分解…`・`週ごとに分ける`は押せない。
- **先行**: 参照行を先行にできる(完了は、参照先の完了予定。参照先が全部終了していれば、実績の終了)。参照行を後続にはできない(開始が参照先の値のため)。
- **検索・件数**: 検索は名前で当たる。セクション見出しのタスク数には数える。

## 出力

- **PNG**: プレビューと同じ描画。ホバー・下線は出ない。
- **PlantUML**: 参照行を 1 本の帯(開始〜終了)で出し、名前の後ろに`(参照)`を付ける。遅延があれば、予定超過の赤みがオンのとき赤にする。担当者・進捗は出さない。日程のない参照行は、日程のないタスクと同じく、出さずに件数に数える。

## ほかの機能との関わり

- ダッシュボード・担当者向けファイル・割り当て超過・PlantUML の取り込み: 参照行は数えない(中身は参照先のプロジェクトで数える)。
- 3 者マージ: `ref_project`と`ref_snapshot`は、それぞれ 1 項目として比べる。
- コピー: 参照行のコピーは、参照先とスナップショットを引き継ぐ。
- セクションの削除・移動・折りたたみ: 通常のタスクと同じ。

## テスト

算出(`reference.py`)・保存の往復と読込の拒否・3 者マージ・ガントチャートの表示(帯・チップ・縞・ホバー・見つからないとき)・ダイアログ(種別・参照先の選択)・右クリックメニュー(`更新`・押せない理由)・クリックの 2 種類の確認ダイアログ・設定の切り替え(スナップショットを取る・捨てる)・PlantUML・PNG を、種類ごとに足す。

## 見送り

- 参照先の id での参照(ファイル名の変更への追従)。
- 参照先の一部(セクション・期間)だけの参照。
- 参照行を後続にすること、参照行への工数・担当・実績の入力。
- 他のプロジェクトとの負荷の重ね合わせ(ダッシュボードの`全プロジェクト`が引き続き担う)。
