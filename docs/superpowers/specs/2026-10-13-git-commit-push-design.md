# git のコミットとプッシュ 設計書

要望 10(git / GitHub 連携)の 4 番目の子の作業。分割は`docs/request-history.md`の「要望 10 の分割」。

## 目的

格納先が`git clone`したフォルダのとき、自分が変えたプロジェクトファイルを、アプリの中でコミットし、プッシュして、共有できるようにする。3 番目の子(git の状態表示。PR #13)のチップが見せる`●`(未コミット)と`↑`(未プッシュ)を、解消する操作にあたる。

## 範囲

**含む**:
- 変更のあるプロジェクトファイルを選んでコミットする(`gitops.py`、コミットのダイアログ)
- 上流へプッシュする
- ヘッダーの 5 つ目のメニュー「Git」、ショートカット、ショートカットヘルプ
- `CLAUDE.md`・`docs/development.md`・`docs/request-history.md`の更新

**含まない**(後続、または扱わない):
- プル・`fetch`・マージ(5 番目の子)
- ブランチの切り替え・作成・一覧(必要になったら別の子。ブランチはチップの表示だけ)
- 差分の表示、amend、リバート、署名、タグ
- `user.name`・`user.email`・認証・リモートの設定(各自の環境に任せる。足りなければ`git`のエラーを出す)
- 定期的な自動更新、プロジェクトファイル以外のファイルのコミット

## 決定事項(確認済み)

- **コミットの単位は、コミット前に一覧から選ぶ**。変更のあるプロジェクトファイルを、状態(変更・追加・削除)つきで並べ、既定はすべてチェック済み。「プロジェクトファイル」は、3 番目の子と同じ範囲(格納先直下の`*.json`で、`config`・`holidays`を除く)。
- **コミットメッセージは、自動の案を入れておき、編集できる**。空では確定できない。
- **コミットとプッシュの分け方**: メニューは「コミット…」と「プッシュ」の 2 項目。ダイアログのボタンは「コミット」と「コミットしてプッシュ」。コミット済みで未プッシュのときは、プッシュだけを単独でできる。
- **ブランチの切り替えは入れない**。
- **入口は、ヘッダーの 5 つ目のメニュー「Git」**。項目は「コミット…」「プッシュ」「状態を読み直す」。作業ツリーでないときは押せない。
- **次の既定は、設計の案として置く**(違えば直す): 認証の入力待ちで止まらない(`GIT_TERMINAL_PROMPT=0`)・プッシュのタイムアウトは長め(60 秒)・拒否されたら`git`のメッセージに「先にプルが必要」と添える・上流のないブランチではプッシュを押せない。

## 設計

### `gitops.py`(NiceGUI に依存しない)

- `FileChange`(`frozen`): `name: str`(ファイル名。例`甲.json`)・`status: ChangeStatus`(`MODIFIED`=変更・`ADDED`=追加(未追跡)・`DELETED`=削除)。
- `GitResult`(`frozen`): `ok: bool`・`message: str`(成功時は短い文言、失敗時は`git`の理由)・`detail: str = ""`(成功時のコミットの短いハッシュなど)。
- `list_changes(project_dir, run=_run, timeout=...) -> list[FileChange] | GitResult`: `git -C <dir> status --porcelain=v2 -z --untracked-files=all -- <固定のパス指定>`(3 番目の子と同じ`PATHSPEC`)を解く。`-z`は NUL 区切りで、日本語名に引用符が付かない。`1 `行の XY の`D`を削除、`?`を追加、それ以外を変更とする。`2 `(改名)は、新しい名前を追加、元の名前(次の NUL 区切り)を削除の 2 件にする(選んでコミットできるように)。`u `(衝突)は変更とする。`-z`のパスは、作業フォルダ基準でなくリポジトリのルート基準(`sub/甲.json`)なので、パス指定が直下の`*.json`だけに絞っていることを使い、最後の`/`以降を名前にする(実機で確認、2026-10-13)。読めなければ`GitResult(ok=False, ...)`。名前順に並べる。
- `default_message(names: list[str]) -> str`: ファイル名から拡張子を除き、`プロジェクトを更新: 甲, 乙`。4 件以上は`プロジェクトを更新: 甲, 乙, 丙 ほか N 件`(N は 4 件目以降の数)。
- `commit(project_dir, names, message, run=_run) -> GitResult`:
  1. 名前の検査: 空、`/`・`\`・NUL を含む、`.json`でない、予約名(`config`・`holidays`)は拒否する(画面から来る値だが、パス指定に使うため)。
  2. `list_changes`で現在の変更を読み直し、`names`のすべてが変更の一覧にあることを確かめる(なければ「変更がありません」で、`git commit`は呼ばない)。
  3. `git --literal-pathspecs -C <dir> add -A -- <names>`。
  4. `git --literal-pathspecs -C <dir> commit --only -m <message> -- <names>`。`--only`は、利用者が別に stage したファイルをコミットに入れず、その stage も変えない(実機で確認)。
  5. 成功したら`git -C <dir> rev-parse --short HEAD`で短いハッシュを`detail`に入れる。
  - メッセージは、前後の空白を除いて空なら拒否する。
- `push(project_dir, run=_run) -> GitResult`: `git -C <dir> push`(上流へ。リモート・ブランチは設定に従う)。失敗の出力に、拒否を示す語(`rejected`・`non-fast-forward`・`fetch first`)があれば、`message`の末尾に「先にプルが必要です(プルは後続機能)」を添える。
- 共通: `gitstate._run`を使い(環境変数の除去・`GIT_OPTIONAL_LOCKS=0`・`LC_ALL=C`・標準入力なし・Windows の窓なしは共通)、書き込み用に`GIT_TERMINAL_PROMPT=0`を足す。`_run`の環境を作る部分を、`gitstate.py`の関数(`git_env(extra)`)に分けて共有する。タイムアウトは、`list_changes`が 5 秒、`commit`が 30 秒、`push`が 60 秒。`run`は差し替えられる(`Runner`)。例外は外へ出さず、`GitResult`の`message`に理由を入れる(`git`がない・タイムアウトを含む)。

### 画面(`views.py`・`forms.py`・`shortcuts.py`)

- **メニュー「Git」**: ヘッダーの左から 4 つ目に置く(順は「ファイル」「プロジェクト」「エクスポート」「Git」「ヘルプ」)。マーカー`menu-git`。項目(左にアイコン、右端にキー):
  - 「コミット…」(`commit`・`git-commit`・`Ctrl/Cmd+K`)
  - 「プッシュ」(`cloud_upload`・`git-push`・`Ctrl/Cmd+Shift+K`)
  - 「状態を読み直す」(`refresh`・`git-refresh`)。チップのクリックと同じ`request_git_refresh`
  - `NOT_REPO`・`NO_GIT`のときは、3 項目とも押せない(`disable`)。「プッシュ」はさらに、上流がない・`ahead`が 0 のときも押せない。理由は、メニュー項目のマウスオーバーに出す(`git の作業ツリーではありません`・`上流がありません`・`未プッシュのコミットがありません`)。押せるかどうかは、`git_state`が変わるたびに更新する。
- **コミットのダイアログ(`open_commit_dialog`)**:
  - 開くときに`list_changes`を`run.io_bound`で読む(読む間は、読み込み中の表示)。変更が 0 件なら、ダイアログは開かず「コミットする変更がありません」を通知する。読めなければ、理由を通知する。
  - 行: チェックボックス・名前・状態。既定は全チェック。チェックを変えると、メッセージの自動の案も更新する(利用者が編集していなければ)。編集後は、案で上書きしない。
  - メッセージ欄(1 行)。ボタン: 「キャンセル」「コミット」「コミットしてプッシュ」。チェックが 0 件、またはメッセージが空のときは、2 つの確定ボタンを押せない。上流がないときは、「コミットしてプッシュ」を押せない(理由をマウスオーバーに出す)。`ahead`が 0 でも、今回のコミットで増えるので、押せる。
  - 開いているプロジェクトに未保存の編集(`is_dirty()`)があるときは、上に「保存されていない編集は、コミットされません」を出す(コミットはディスクのファイルが対象)。
  - ダイアログは、確定ボタンを押したら閉じ、実行中は`git_busy`を立てて、メニューを押せなくする。
- **実行**: `commit`・`push`は`run.io_bound`で待つ。結果の通知: 成功は「コミットしました(abc1234)」「プッシュしました」、失敗は`message`(`negative`)。「コミットしてプッシュ」でコミットが成功しプッシュが失敗したときは、「コミットしました。プッシュに失敗しました: 〈理由〉」(`warning`)。どの結果のあとも、`request_git_refresh`を呼ぶ。
- **ショートカット**(`shortcuts.py`): `Shortcut("k", "git_commit", "コミット", ctrl=True)`・`Shortcut("k", "git_push", "プッシュ", ctrl=True, shift=True)`。メニューと同じメソッドへ振り分ける(`MainView.on_key`)。作業ツリーでないとき、またはプッシュできないときに押されたら、押せない理由を通知する(何も起きないのを避ける)。`ctrl_keys`に`k`が増えるので、ブラウザの既定(`Ctrl+K`で検索欄へ)が止まる。ショートカットヘルプにも載る。
- **`git_busy`**: コミット・プッシュの実行中は、新しい実行を始めない(二重送信を防ぐ)。実行が終わったら下ろす(例外でも`finally`)。

### 外部変更の検知との関係

コミットは、プロジェクトファイルの内容を変えないので、`digest`(読み込み時のハッシュ)は変わらない。保存前の外部変更の検知(PR #12)には影響しない。

## テスト

- `gitops`(`tmp_path`に実際の`git init`。`user.name`・`user.email`は`-c`で与える):
  - `list_changes`: 変更・追加・削除・日本語名が、それぞれの状態で返る。名前順。プロジェクトファイル以外(`README.md`・`config.json`)は含まれない。サブフォルダの格納先では、そのフォルダの`*.json`だけ。改名(`git mv`で stage 済み)は、新しい名前の追加と、元の名前の削除の 2 件。名前は、サブフォルダの格納先でも、ファイル名だけ(`sub/`を含まない)。変更がなければ空のリスト。作業ツリーでなければ失敗。
  - `commit`: 選んだファイルだけがコミットされ、選ばなかった変更は残る。削除と未追跡がコミットされる。別に stage した`other.txt`が、コミットに入らず、stage のまま残る。変更のない名前を含むと拒否され、`git commit`が呼ばれない。メッセージが空・名前が不正(`/`・`.json`でない・予約名)は拒否される。`user.name`が未設定の環境(`-c user.name=`)で失敗し、理由が返る。成功時の`detail`が短いハッシュ。
  - `push`: 上流(ローカルの bare リモート)へ成功する。別のクローンが先にプッシュしていると拒否され、「先にプルが必要」が添えられる。上流がないブランチで失敗する。
  - `default_message`: 1〜3 件、4 件以上、日本語名。
  - 差し替えた`run`で: `git`がない・タイムアウト・想定外の終了コードで、例外を出さず`ok=False`。
- 画面(`git_state`は`read_git`の差し替え、`gitops`は`MainView`が持つ関数の差し替えで、本物の`git`を呼ばない):
  - メニュー「Git」の 3 項目が、作業ツリーのときだけ押せる。プッシュは、上流なし・`ahead == 0`で押せず、理由が出る。
  - コミットのダイアログ: 全チェックと自動の案が入る。チェックを外すと案が更新され、編集後は更新されない。0 件チェック・空のメッセージで確定できない。変更が 0 件ならダイアログが開かない。未保存の編集の警告が出る。
  - 「コミット」で`commit`が選んだ名前とメッセージで呼ばれ、成功の通知のあとにチップが読み直される。「コミットしてプッシュ」で、コミットのあとに`push`が呼ばれる。コミットが失敗したら、プッシュは呼ばれない。プッシュだけ失敗したら、警告の通知。
  - `git_busy`の間は、メニューとショートカットが新しい実行を始めない。例外のあとも下りる。
  - ショートカット: `Ctrl/Cmd+K`でダイアログ、`Ctrl/Cmd+Shift+K`でプッシュ。押せないときは理由が通知される。ダイアログが開いている間は効かない。ヘルプに載る。
- 既存のテストが、変更なしで通ること(`conftest.py`の差し替えで、本物の`git`は呼ばれない)。

## 未確認・リスク

- `status -z`の改名の形(`2 `行のあとに元の名前が NUL 区切りで続く)と、パスがルート基準であることは、実機で確かめた(2026-10-13)。
- Windows の`git`の見つけ方・改行コード(`autocrlf`)で、コミットしたファイルの改行が変わる可能性は、この子では扱わない(3 番目の子と同じ)。
- プッシュに時間がかかる(60 秒まで)間、画面は止まらないが、結果が出るまで再実行できない。長い場合は、タイムアウトの「git が応答しません」になる。
- 認証が必要で、`git`の資格情報の保管(キーチェーンなど)が使えない環境では、プッシュが失敗する。メッセージは`git`のものをそのまま出す。
- ヘッダーのメニューが 4 つから 5 つに増える。`CLAUDE.md`の「メニュー 4 つ」の記述と、ヘッダーの順序のテストを直す。
