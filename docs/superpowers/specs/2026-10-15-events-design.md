## 背景と目的

休暇・リリース・繁忙期などの期間を、ガントチャート上で一目で分かるようにする。祝日と土日は日付の種別として塗られるが、プロジェクト固有の期間を文字つきで示す手段がない。

目的は、**プロジェクトごとに、期間・文字列・色を持つイベントを登録し、日付ヘッダーの下に文字の帯として、期間のセルを色で表示すること**。

## 決定事項

- イベントは `開始日`〜`終了日`(終了日を含む)・`文字列`・`色`を持つ。時刻は持たない。
- 期間が重なるイベントは、日付の下に段(レーン)を重ねて表示する。セルの色は、リストの後ろのイベントを優先する。
- 色は CSS の色名(約 148 種。大文字小文字は区別しない。保存は小文字)。`#RRGGBB` は受け付けない。ダークテーマでは、同じ色名をより低い不透明度で塗る。
- 日次・週次・月次のすべてのスケールで出す。
- 登録は設定ダイアログの「イベント」の節(カテゴリ・URL テンプレートと同じ置き場)。
- プレビュー・画像保存にも同じ見た目で出す。プレビューの表示項目に「イベント」のオン・オフを足す(既定はオン)。
- ファイル形式を version 4 に上げる。古いアプリがイベントを知らずに保存して消すのを防ぐため。
- 絞り込み・折りたたみの影響は受けない(常に出す)。

対象外: ダッシュボード、担当者向けの書き出し、ドラッグでの帯の編集、時刻つきのイベント、件数の上限、`#RRGGBB`。

## モデル(`models.py`)

```python
@dataclass
class Event:
    start: date
    end: date                  # 終了日(含む)。start 以降
    text: str                  # 1〜MAX_EVENT_TEXT_LENGTH(30)文字。制御文字は使えない
    color: str = "gray"        # events.CSS_COLORS のどれか(小文字)
    id: str = field(default_factory=new_id, compare=False)
```

- `Project.events: list[Event]`。順序が優先順(後ろが勝つ)。保存時に、開始日の昇順(同じなら終了日の昇順、さらに元の順)に並べ替える。
- `id` は、カテゴリと同じ `new_id(taken)`。`Project.used_ids()` に含める。
- `FORMAT_VERSION = 4`。

## ファイル形式(version 4)

```json
"events": [
  {"id": "...", "start": "2026-10-20", "end": "2026-10-24", "text": "リリース", "color": "red"}
]
```

- キーのない version 3 以前のファイルは `events = []` で読む(移行は要らない)。version 4 でキーがなければ空。
- 読込は `events.validate_events` で検証し、不正な値(日付の形式・`start > end`・文字列の長さと文字種・色名・id の重複)は拒否する。色名は小文字にそろえて読む。
- 保存は一時ファイル経由(既存の仕組み)。

## 純粋関数(`events.py`。NiceGUI に依存しない)

- `CSS_COLORS: dict[str, str]`: 色名 → `#rrggbb`(CSS Color Module の名前付き色)。
- `normalize_color(name) -> str | None`: 前後の空白を除き小文字にして、色名なら返す。そうでなければ None。
- `validate_events(events)`: 文字列(1〜30 文字・`Cc`/`Cf`/`Zl`/`Zp` なし)、`start ≤ end`、色名、id の重複を検査し、不正なら `ValueError`(理由つき)。
- `sort_events(events)`: 開始日・終了日・元の順で並べる(安定)。
- `assign_lanes(events) -> list[int]`: 開始の早い順に、空いた最小の段へ詰める貪欲法。イベントごとの段番号を返す(入力と同じ順)。期間が接するだけ(前の終了日の翌日が開始)なら同じ段に置ける。重なれば別の段。
- `column_span(event, columns) -> tuple[int, int] | None`: 期間に 1 日でも重なる列の、先頭の添字と列数。重ならなければ None。列は `[start, end)`(終端を含まない)なので、`event.end` の翌日と比べる。
- `cell_colors(events, columns) -> list[str | None]`: 列ごとの色名。重なる列には、リストの後ろのイベントの色を入れる。
- `count_lanes(events) -> int`: 段の数(帯の高さの計算用)。

## 表示(`gantt.py`)

- **帯**: `header()` の `label_row` の下に、段の数だけの行(`event-row`、高さ `EVENT_ROW_HEIGHT_PX` = 16)を足す。イベントがなければ行を作らない。行は `header_spacer` + 絶対配置の帯(`event-bar-<id>`)。帯の位置は `column_span` から、`left = 添字 × 列幅`、`width = 列数 × 列幅`。帯の背景は色の `#rrggbb` を `EVENT_BAND_ALPHA`(ライト 0.45・ダーク 0.35)で重ね、文字は `position: sticky; left: var(--name-w)` で名前の列の右端に残す(年・月の帯と同じ)。はみ出す文字は省略し、全文は `title` に出す。利用者の文字列は `ui.label` で出す(HTML に埋め込まない)。
- **セルの色**: `stripes` の直後に `event_tints()` を足す。`cell_colors` の結果を 1 つの `ui.html`(`event-tints`)にまとめ、列ごとの `<div>` に色名の `#rrggbb` と透明度を `background` に入れる。内容は定数と検証済みの色だけで、利用者の文字列を含まない。格子線・縞の下、棒の下に置く。
- **スケール**: 日次・週次・月次とも、同じ `column_span` で幅を決める。月次スケールでは月の帯がないが、段の行は同じく足す。
- **更新**: 設定の適用後は、既存の再描画(`render`)を通る。
- **プレビュー**: `ViewOptions.show_events`(既定 True)。プレビューの表示項目に「イベント」のチェックを足し、オフなら帯もセルの色も出さない。画像保存は、チャートの見た目をそのまま使う。

## 登録(`forms.py` の設定ダイアログ)

- 稼働時間・カテゴリ・URL テンプレートと同じダイアログに、「イベント」の節を足す。
- 行ごとに、開始日・終了日(`parse_date_input`。`roll_forward` はしない)・文字列(30 文字)・色(入力欄。色の見本を横に出す。不正な名前は見本を出さず、赤くする)を入れる。行の「削除」と節の「追加」。
- 適用時に `validate_events` で検証し、エラーは既存の設定ダイアログと同じ作り(通知と、該当の行を赤くする)で出す。保存済みの並びは `sort_events` にそろえる。
- 変更したら、プロジェクトを編集中(未保存)にする。
- 開始日・終了日が空の行、文字列が空の行は、適用時にエラー。

## git のマージ(`merge.py`)

- イベントを `id` で突き合わせる。項目は `start`・`end`・`text`・`color`。片側だけが変えた項目は採り、両側が違えば衝突にする。片側の削除と、もう片側の変更も衝突にする(`削除する`か`残す`)。
- 衝突の `kind` は `event`。表示は `format_value` で日付・文字列・色名にする。
- 統合の結果は、`validate_events` を通す(通らなければ取り込まない)。統合のあと、`sort_events` でそろえる。

## テスト

- `events.py`: 検証(文字数・制御文字・日付・色名・重複)、`normalize_color`、`assign_lanes`(重なり・接する・包含)、`column_span`・`cell_colors`(日次・週次・月次の列、期間の外、後ろ優先)。
- `storage`: 往復、version 3 以前のファイルの読込、不正な値の拒否、色名の小文字化、version 4 のキーなし。
- `merge`: 追加・片側の変更・両側の変更・削除と変更・id の重複。
- `forms`・設定ダイアログ: 追加・削除・適用・検証エラー・未保存の印。
- 描画: 帯の位置と幅(各スケール)、段の重なり、セルの色、プレビューのオン・オフ、ダーク用の不透明度。
