# 稼働日の上書き(土日の稼働・休み)の設計(要望 30)

> **状態**: 実装済み(2026-10-22。実機確認待ち)— 要望 30 — `feature/work-days`。現在の仕様は [`CLAUDE.md`](../../../CLAUDE.md) に反映済み。
>
> 実装での差分: 保存の時刻は`time.isoformat()`の形(`"13:00:00"`)。平日を休みにした日の背景(`DayKind.REST`)は、土日と同じではなく灰色(`rgba(158, 158, 158, 0.25)`)にした。

## 目的

遅延が出たとき、土日のどちらかを稼働に使うことがある。たとえば「土曜は 13:00〜16:00 だけ稼働する」を、完了予定の算出に反映したい。
今の稼働日は「月〜金で祝日でない日」の 2 値で、始業から稼働可能時間の枠だけを使う。日ごとに稼働の時間帯を上書きできるようにする。成功の目安は次のとおり。

- 設定ダイアログで登録した日が、完了予定の算出に効く(土日祝の稼働、平日の半休、休み)。
- ダッシュボードの「工数の予定」と負荷の稼働日に、登録が反映される。
- ガントチャート(日次)で、上書きした日を見分けられる。
- 古いファイルはそのまま読める(上書きなし)。

## 決めたこと(2026-10-22 に確認済み)

| 項目 | 決定 |
| --- | --- |
| 登録の単位 | プロジェクトのカレンダー(全員・全タスクに効く)。メンバー別・タスク別は含めない |
| 時間の置き方 | 日付ごとに`開始時刻`と`終了時刻`を指定する(1 日 1 つの枠) |
| 休み | 同じ仕組みで扱う(`休み`にした日は枠なし)。祝日・平日も休みにできる |
| 登録のしかた | 1 日ずつ。期間・繰り返しは含めない |
| 終了時刻 | 同じ日の 23:59 まで。24:00 は扱わない |
| 上書きの強さ | 上書きした日は、その日の枠を丸ごと置き換える(祝日・土日の判定より優先) |

## データ(`models.py`・`storage.py`)

- `WorkDay(day: date, start: time | None, end: time | None)` を足す。`start`・`end` が`None`のときは休み(両方`None`か、両方が時刻)。
- `Project.work_days: list[WorkDay]` を足す(既定は空)。保存時と取り込み時に、日付の昇順に並べる。
- 検査: 日付は重複しない・年は 2000〜2100。休みでないときは`start < end`。
- `FORMAT_VERSION` を 8 に上げる(`8: 稼働日の上書き`)。`work_days`のないファイル(version 7 以前)は空として読む。version 8 で型が不正(日付・時刻の形式、片方だけ`None`、重複、`start >= end`)なら読込を拒否する。
- ファイルには`{"day": "2026-10-17", "start": "13:00", "end": "16:00"}`の形で、休みは`start`・`end`を`null`で保存する。
- 要望 44(休暇・不在)の`version`は 9 になる(`requests.md`・`MEMORY.md`の記述を直す)。

## 算出(`timeline.py`)

- `day_window(day, daily_hours, work_start, holidays, work_days) -> tuple[datetime, datetime] | None` を足す。その日の稼働の枠(開始と終了の日時)を返し、枠がなければ`None`。
  1. `work_days`に日付があれば、その枠(休みなら`None`)。
  2. なければ今までどおり。月〜金で祝日でなければ、始業から`daily_hours`。それ以外は`None`。
- `work_days`は、日付から`WorkDay`への辞書で渡す(`work_day_map(project)`)。
- `is_workday`・`_next_workday`・`_calc_end`を、この枠で回すように直す。
  - 開始がその日の枠の途中なら、そこから使う。枠の前なら枠の開始から。枠の後なら次に枠のある日から。
  - 枠に収まりきらない工数は、次に枠のある日の開始へ繰り越す。
  - 枠がまったくない日(土日祝・休み)は飛ばす。
- `calc_end`・`computed_end`に`work_days`引数を足す(既定は空の辞書。引数の最後に置き、今の呼び出しを壊さない)。`MAX_WORKDAYS`による工数の上限(`daily_hours × MAX_WORKDAYS`)は変えない。
- 呼び出し元: `Schedule._own_end`(`timeline.py`)、`task_dialog.py`の参考値(`_computed_end`)、`reassign.py`。いずれも`project.work_days`から作った辞書を渡す。`holidays`の経路は変えない。
- 工数の単位(日・週・月)の換算は、カレンダーを見ない固定値のまま(影響を受けない)。

## ダッシュボード(`dashboard.py`)

- `_workdays(period, holidays)`を、`work_days`を反映した稼働日(`day_window`が枠を返す日)の一覧にする。
- `工数の予定と実績`の予定は、稼働日ごとの実際の時間(平日の通常日は`daily_hours`、上書きした日は終了−開始)に割り当て率をかけて足す。今の「稼働可能時間 × 割り当て率 × 稼働日」を、日ごとの時間の合計に一般化する(上書きがなければ同じ値)。
- 全プロジェクトの`人ごとの負荷`と`負荷の日ごとの推移`の列は、「どれかのプロジェクトが稼働日である日」の和集合にする。1 つのプロジェクトだけで土曜を稼働にした日も、負荷として見える。各プロジェクトの負荷は、そのプロジェクト自身の稼働設定で求める(今までどおり)。
- 1 つのプロジェクトだけの`人ごとの負荷`は、そのプロジェクトの`work_days`を使う。

## 表示(`gantt.py`・`calendar.py`)

日次スケールだけが対象。週・月では変えない。

- 土日祝を稼働に上書きした日は、土日祝の背景色をやめて平日と同じにし、日付ヘッダーの下端に小さな橙の印を付ける。マウスオーバーに`稼働 13:00〜16:00`(祝日は祝日名も添える)を出す。
- 平日を休みにした日は、土日と同じ背景にする。マウスオーバーは`休み`。
- 平日の半休など、枠だけ変えた日(平日を稼働に上書き)は、背景は変えず、同じ橙の印とマウスオーバーを付ける。
- プレビュー・画像にも出す(背景と印は、同じ描画を使う)。
- 色は定数(`calendar.py`の`KIND_COLORS`の仲間)に置く。ダークテーマでも見える色にする。

## 設定ダイアログ

- `イベント`の節の次に、`稼働日の上書き`の節を足す。表の行は`日付 / 開始 / 終了 / 休み / 削除`。
- 日付・時刻は既存の入力補正(`10/17`・`1017`・`9`・`930`・`9:30`)を使う。日付は、離れたときに`YYYY-MM-DD`に整える。
- `休み`にチェックを入れると、開始・終了は入力できなくなる(値は保持しない)。
- 適用時の検査: 日付の重複・不正な日付・不正な時刻・`開始 >= 終了`は、行の横にエラーを出して適用しない。保存時に日付の昇順に並べる。
- 適用すると、完了予定の算出がすぐ変わる(手で指定した完了予定と締切は変わらない)。

## そのほか

- **PlantUML の出力**: 期間内の上書きを反映する。稼働にした土日祝は`YYYY-MM-DD is open`、休みにした平日は`YYYY-MM-DD is closed`を足す(祝日の`is closed`は、稼働に上書きした日では出さない)。時間帯は出さない(日単位)。
- **3 者マージ**(`merge.py`): `work_days`を日付をキーにして突き合わせる(パラメータ・URL テンプレートと同じ名前引きの扱い)。同じ日付を両側が違う値に変えたときは、画面で選ぶ。
- **元に戻す・やり直し**: `Project`の複製に入るので、そのまま効く。設定ダイアログの適用は 1 ステップ。
- **担当者向けファイル(`todos.json`)・PlantUML の取り込み**: 変えない。
- **`CLAUDE.md`**: 稼働可能時間・設定ダイアログ・ガントチャートの節に、上書きの仕様を足す。「ファイル形式」の`version`を 8 にする。

## 含まないもの

期間や曜日の繰り返しでの登録、メンバー別・タスク別の稼働、1 日に複数の枠、24:00 までの枠、上書きした日への実績の突き合わせ、週・月スケールの印。

## テスト

- 算出(`test_timeline.py`):
  - 土曜に 13:00〜16:00 を登録すると、金曜の枠に収まらない工数が土曜の 13:00 から 3 時間分に繰り越される。
  - 平日を半休(9:00〜12:00)にすると、その日の枠が短くなる。祝日を稼働にすると算出に使われる。休みにした平日は飛ばす。
  - 開始が枠の前・途中・後のとき。枠の終了ちょうどから始まるとき。
  - 上書きがなければ、今までの結果と同じ(既存のテストが通る)。
  - 工数が不正・日付が範囲を超えるときは`None`のまま。
- ダッシュボード(`test_dashboard.py`): 予定が日ごとの時間の合計になる。上書きなしでは同じ値。全プロジェクトの列が和集合になる。
- 保存・読込(`test_storage.py`): version 7 のファイルを空で読む。往復で同じ。休みを`null`で保存・読込。不正(重複・`start >= end`・片方だけ`null`・形式)は拒否。
- 設定ダイアログ(`test_forms.py`・設定ダイアログのテスト): 行の追加・削除・休み・エラー・並べ替え。
- ガントチャート(`test_gantt.py`): 印とマウスオーバー、背景。週・月では出さない。プレビューにも出る。
- PlantUML(`test_plantuml.py`): `is open`・`is closed`が出る。jar で描画できる(既存の描画テストの方式)。
- マージ(`test_merge.py`): 片側だけの変更・両側の衝突。
- 実機(ネイティブ): 設定で土曜を登録して完了予定が変わること、背景の印、ダークテーマ、ダッシュボードの予定工数、PlantUML の出力。
