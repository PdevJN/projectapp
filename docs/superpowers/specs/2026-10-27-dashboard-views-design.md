# ダッシュボードのカスタムビュー 設計書(要望 40)

作成: 2026-10-27 / 状態: 設計(レビュー待ち) / 経路: architectural

## 目的

ダッシュボードの見せ方(期間・メンバー・`全プロジェクト`・どのカードを出すか・カードの順)を、名前を付けた「ビュー」として保存し、切り替えられるようにする。今は条件が保存されず(開き直すと`今週`・`全員`・オフ)、カードの出し入れと順番は固定である。

### 決定済み(利用者の回答)

- `指定`の期間は、日付そのもの(`2026-10-01 〜 2026-10-31`)をビューに保存する。相対的な指定(「今日から過去 14 日」など)は別の要望で扱う。
- 保存するもの: 条件(期間・メンバー・`全プロジェクト`)、カードの出し入れ、カードの並べ替え。
- 保存先: `~/.projectapp/config.json`(全プロジェクト共通・自分だけ)。プロジェクトのファイル(`version`・3 者マージ・元に戻す履歴)には触れない。チームでの共有は対象外。
- 編集は、ダッシュボード上のドラッグで行う。
- ダッシュボードを開いたときは、最後に使ったビューを出す。

### 既定の判断(こちらの案。レビューで直す)

- 組み込みの`標準`ビューを置く(消せない・改名できない)。中身は今の動き(`今週`・`全員`・オフ・全カード・既定の順)。
- 名前は 30 文字まで(タスク名と同じ制御文字・ゼロ幅文字の制限)、ビューは`標準`を除いて 20 件まで。
- `全プロジェクト`のスイッチは保存するが、プロジェクトごとの除外は保存しない(プロジェクトは増減し、消えた名前が残るため)。
- 保存したメンバーが開いているプロジェクトにいないときは、`全員`に戻す(画面だけ。ビューは書き換えない)。

## 対象外

チームでの共有、プロジェクトごとのビュー、`指定`の相対的な期間(別の要望)、ビューの並べ替え、ダッシュボードの定期更新、スマホ向けの専用レイアウト。

## 構成

### 新しいモジュール `dashboard_views.py`(純粋関数。NiceGUI に依存しない)

- `CardId`(`StrEnum`): `TEAM`・`PROGRESS`・`LOAD`・`HEATMAP`・`HOURS`・`DUE`。現在の`DashboardView.cards`が描く 6 枚に対応する(`HEATMAP`は`負荷の日ごとの推移`。`全プロジェクト`がオンのときだけ描く条件は、今の描画側に残す)。`DEFAULT_ORDER`で既定の順を持つ。
- `ViewSpec`(frozen dataclass): `name: str`・`period: PeriodKind`・`member: str | None`・`cross: bool`・`cards: tuple[CardId, ...]`(表示するカードを、並び順に)。`custom: tuple[date, date] | None`(`period`が`指定`のときの期間。開始日・終了日を含む。`指定`以外のビューでは常に`None`)。
- `STANDARD`: 組み込みの`標準`。`standard_view()`で返す。
- `validate_custom(start, end)`: 保存・読込の両方で使う。年は`MIN_YEAR`〜`MAX_YEAR`、開始日は終了日以前、`dashboard.MAX_CUSTOM_DAYS`(400 日)以内を確かめ、理由つきで拒否する(`periodfield.validate_period`と`dashboard.custom_period_error`の規則を再利用し、重複させない)。
- `normalize_cards(cards)`: 未知の ID と重複を捨てる(順は保つ)。空は許す(全部隠したビュー)。足りないカードは「隠した」扱いで補わない。
- `validate_name(name, existing)`: 空・制御文字・30 文字超・`標準`と同名・既存と重複を、理由つきで拒否する。
- `move_card(cards, card_id, before_id)`: `card_id`を`before_id`の手前へ(`before_id`が`None`なら末尾へ)移す。隠れているカードを渡すと、その位置へ出す。
- `hide_card(cards, card_id)`・`show_card(cards, card_id)`(末尾へ)。
- `views_from_config(raw)` / `views_to_config(views)`: `config.json`の値との変換。1 件ずつ検証し、不正な件は捨てる。同名の重複は最初の 1 件を残す。上限(20 件)を超えた分は捨てる。

### `config.py`

- `load_dashboard_views(base_dir)` → `list[ViewSpec]`(`標準`を含まない)、`save_dashboard_views(views, base_dir)`。キーは`dashboard_views`(リスト)。
- `load_dashboard_view_last(base_dir)` → `str | None`、`save_dashboard_view_last(name, base_dir)`。キーは`dashboard_view_last`。
- どちらも`update_config`を使い、ほかのキーを壊さない。読めない・型が違うときは空(`None`)を返し、通知しない。

### `dashboard_view.py`

- `cards()`の固定の呼び出し列を、「`CardId` → 描画メソッド」の表と、現在のビューの`cards`の順に置き換える。
- ツールバーに、ビューの選択・作業中の印・操作ボタン・`カードを編集`ボタンを足す(下記)。
- 作業中の状態(`current: ViewSpec`・`dirty: bool`・`edit_mode: bool`)を`DashboardView`が持つ。条件の変更(期間・メンバー・`全プロジェクト`)は、今の経路(`on_change`など)で集計し直したうえで、`current`にも反映して`dirty`にする。

## 操作

### ビューの選択と状態

- ツールバーの見出しの右に、ビューのプルダウン(`標準`とカスタムビュー)を置く。選ぶと、期間(`指定`なら日付も)・メンバー・`全プロジェクト`・カードの並びを`current`に取り込み、集計し直す。`指定`のビューは、期間欄にその日付が入った状態で開く。選んだ名前は`dashboard_view_last`に保存する。
- 条件の変更、カードの移動、非表示は、保存するまで作業中の状態とする。選択の横に`●`を出し、`保存`・`名前をつけて保存`・`元に戻す`を出す。
  - `保存`: 今のビューを上書きする。`標準`では押せない。期間が`指定`で、欄の日付にエラー(不正・400 日超)があるとき、または欄が空のときは、押せず、理由を出す(ビューに不正な日付を保存しない)。
  - `名前をつけて保存`: 常に出す(`標準` のままでも新しいビューを作れるように。`保存`・`元に戻す` は `●` のときだけ)。名前の入力ダイアログ(`validate_name`)。成功すると、そのビューに切り替える。`指定` の欄にエラーがあるときは開かず、理由を通知する。
  - `元に戻す`: 選択中のビューの保存された内容に戻す。
- 別のビューへ切り替えるときは、作業中の変更を確認なしで捨てる。
- メニュー(`名前の変更`・`削除`): `標準`では押せない。削除は確認を出し、削除後は`標準`に切り替える。
- ダッシュボードを開くときは、`dashboard_view_last`のビューを出す(なければ`標準`)。開き直しても、作業中の変更は持ち越さない。

### ドラッグ編集

- `カードを編集`ボタンで編集モードに入り、`完了`で抜ける。ふだんはドラッグできない。
- 編集モードでは、各カードに取っ手(`drag_indicator`)と非表示ボタン(×)を出す。カードを別のカードの上へ落とすと、その手前に入る。グリッドの末尾に最後尾用の落とし場所を出す。
- 隠したカードは、グリッドの下の「隠したカード」の一覧に並べ、`+`で末尾へ戻す。`負荷の日ごとの推移`は、`全プロジェクト`がオフの間は一覧に出さない(カードも出ない)。順と出し入れだけをビューに保存する。
- ドラッグのブラウザ側は、`gantt_drag.py`と同じく document の`dragstart`・`drop`を拾い、掴んだカードと落とした先の ID を Python へ送る。判定は`move_card`に任せる。
- プレビューと同様、1 列に折り返す幅でも順番は入れ替えられる。

## エラー処理

- `指定`のビューの日付が不正(読めない・開始日が終了日より後・年の範囲外・400 日超)、または`指定`以外のビューに日付がある: そのビューは捨てずに日付だけ無視する。`指定`のビューは、`指定` を選んだときと同じく、直前の期間から始める(欄は空にしない)。
- `config.json`が読めない、またはビューのキーが不正: ビューは`標準`だけにして、通知なしで起動する。ほかのキー(テーマなど)は触らない。
- 1 件ずつ検証し、不正な件だけ捨てる。`dashboard_view_last`の名前が存在しなければ`標準`に戻す。
- メンバーがいないビュー: `全員`に戻す(画面だけ。ビューは書き換えない)。
- `config.json`を書けない: 通知を出し、画面上のビューはメモリ上で使い続ける。
- 名前・上限の違反: 入力ダイアログの横に理由を出し、保存しない。

## テスト

実行方法と置き場所は`docs/development.md`と`test/`に合わせる。`config.json`は`tmp_path`を使い、実際のホームを読み書きしない。

- `test/test_dashboard_views.py`(純粋関数): `validate_custom`(正常・逆順・年の範囲外・400 日超・ちょうど 400 日)・`normalize_cards`・`validate_name`・`move_card`・`hide_card`・`show_card`・`views_from_config`(不正な件・重複・上限・往復。`custom`は`指定`のときだけ持ち、`YYYY-MM-DD`で往復する)・`standard_view`。
- `test/test_config.py`への追加: `load/save_dashboard_views`・`load/save_dashboard_view_last`、ほかのキーを壊さないこと、読めない値で空を返すこと。
- `DashboardView`の UI テスト(既存の`User`のシミュレーション): ビューの切り替えでカードの順が変わる、カードの非表示と復帰、`●`の出入り、`保存`・`名前をつけて保存`・削除、`標準`で`保存`・削除が押せないこと、開いたときに最後のビューが出ること。
- ドラッグのブラウザ側の JS は自動テストしない(`move_card`で位置の判定を確かめ、イベントの受け口は Python から直接呼ぶ)。

## 未決・リスク

- ドラッグ編集のブラウザ側は、実機(ネイティブウィンドウ)で確かめる。`gantt_drag.py`のイベント処理との干渉(同じ document の`dragstart`を拾う)は、編集モードのときだけ有効にして避ける。
- `config.json`の`custom`は`{"start": "YYYY-MM-DD", "end": "YYYY-MM-DD"}`で保存する(相対的な指定を別の要望で足すとき、同じキーを広げられるよう、1 つの項目にまとめる)。
- 既定の判断(除外プロジェクト・上限)は、レビューで変えてよい。変える場合は、この節と`ViewSpec`を直す。
