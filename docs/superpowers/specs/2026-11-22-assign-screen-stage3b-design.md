# 要望 168 段階 3b: アサイン専用画面の範囲を選んでの集中増員(設計)

## 目的

割り当ての行で範囲(週・日のセル)を選び、メンバーをまとめて足して、完了予定がどう変わるかを確定する前に見られるようにする(例: 後半の 2 週間だけ人数を増やす)。段階 3 は 3a(割り当て率のスライダー。マージ済み)と、この 3b(集中増員)に分けた。視点(段階 4)・負荷のヒストグラム(段階 5)は含めない。

## 決定(利用者の回答)

- 範囲は、割り当ての行のセルをドラッグして選び、そこへメンバーのチップを落とす(既存のドラッグでの割り当てと同じ操作で済ませる)
- 選べるのは、表示中のセル単位だけ。週のセルは週ごと、日ごとにした週は日ごと。週の途中から選びたいときは、先にその週を`日ごと`にする(勝手に週を分けない)
- 持ち方は`Task.weekly_crew`・`Task.daily_crew`。割り当て率は 100%(変えるのは 3a のポップアップ)。ファイル形式は変えない(`version`は 24 のまま)。試算・確定・キャンセルは段階 1〜3a のとおり

## 担当の操作(`daily_crew.py`に追加。NiceGUI に依存しない)

- `add_member_range(task, name, first, last, *, weeks=1) -> Task | None`
  - `first`・`last`は`(week, day | None)`(`day`は日ごとの週のときだけ)。`first`が`last`と同じかそれより前になるよう、内部で並べ替える
  - 範囲のセルを、日付の順に`add_member`で 1 つずつ足す。そのメンバーがすでにいるセルは飛ばす。定義済みの週より先・週ごとでないタスク・担当者のいないタスクの扱いは`add_member`と同じ
  - 範囲の週は、日ごとの週なら`day`の範囲(`first`の週は`first`の日から、`last`の週は`last`の日まで。途中の週は 7 日すべて)、日ごとでない週なら週全体。日ごとでない週の`day`は無視する
  - `None`(何も変えない): すべてのセルにすでにいる・`week`が 0 未満か`MAX_WEEKS`以上・通常でないタスク・範囲に含まれるセルがない
- 整理(挙動は変えない): `add_member`・`remove_member`の「週ごとの担当を複製して直前の担当で埋める」「日ごとの週の対象日を数える」を、3a で足した`_padded`・`_cell_crews`に寄せる。既存のテストで守る

## 画面(`assign_screen.py`・`assign_drag.py`の拡張)

- 範囲の選択(JS): 割り当ての行のセル(`data-assign-cell`)の上で mousedown し、別のセルまで mouseover して mouseup すると、始点と終点のセルを`emitEvent("assign_select_range", {first: {week, day}, last: {week, day}})`で Python に返す。始点がチップ・`×`ボタン・`日ごと`ボタンの上のときは始めない。同じセルのクリックだけ(動かさない)では選ばない。ドラッグ中は、なぞったセルを色付けする(CSS クラス)。HTML5 のドラッグ(メンバーのチップ)とは別の操作で、`dataTransfer`の種類も別なので衝突しない
- 選択の状態(Python): `AssignScreen.selection: tuple[Cell, Cell] | None`。選んだ範囲のセルに、薄い色の枠と背景を付ける(割り当ての行の再描画のたびに付け直す)。行の左に`選択を解除`のボタンを出す(選択があるときだけ)。選択はタスクが変わっても残るが、日ごとの切り替え(`日ごと`/`週に戻す`)・セルの数が変わる操作では解除する(セルの並びが変わるため)
- ドロップ: 落とし先が選択の範囲に含まれていれば、`add_member_range`で範囲のすべてのセルに足す。範囲の外なら、今までどおりそのセルだけ(`add_member`)。成功したら選択を解除する。すべてのセルにすでにいるときは`すでに割り当てています`と通知する
- 反映: 操作のたびに、試算のタスクを更新して棒・完了予定・警告を描き直す(3a までと同じ)。確定するまでメインは変えない
- 確定・キャンセル・Esc: 段階 1〜3a のとおり。選択は試算に含めない(`is_dirty`は変えない)

## 確かめること(実装の最初)

- mouseover でなぞったセルを、日ごとの週と週のセルが混ざる行で正しく並べられるか(`data-week`・`data-day`の並びで比べる)
- 範囲の選択の mousedown が、行のスクロール(チャートの横スクロール)・既存の`dragstart`と干渉しないか
- 倍率(`zoom`)中のマウス位置は、要素への`mouseover`(座標を使わない)で取るので影響しない見込み

足りないときは、この設計書を直して利用者に確認する。

## テスト

- 純粋関数: 週・日・またぎ(週→日ごとの週)・重複(一部だけ・すべて)・先の週・52 週・担当者のいないタスク・通常でないタスク・始点と終点の逆順・`add_member`・`remove_member`の整理後も既存のテストが通る
- 画面: 範囲の選択と解除・範囲内へのドロップで全セルに足す・範囲外へのドロップは 1 セルだけ・解除ボタン・日ごとの切り替えで解除・完了予定が増員で早まる
- JS: node で、なぞる動作(mousedown→mouseover→mouseup)と、チップ・ボタンの上から始めない動作をシミュレーションする(`test_assign_drag.py`の方式)
