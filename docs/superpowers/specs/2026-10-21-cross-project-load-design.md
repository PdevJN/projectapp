# 複数プロジェクトの並行稼働による負荷の設計(要望 31)

> **状態**: 実装済み(2026-10-21)— 要望 31。現在の仕様は実装後に [`CLAUDE.md`](../../../CLAUDE.md) へ反映する。

## 目的

複数のプロジェクトを兼務する人が、全プロジェクトを合わせるとどれだけの負荷になるかを、ダッシュボードで見られるようにする。
1 プロジェクトの中では 100% 以内でも、重なって超過する日を見つけられるようにする。
成功の目安は次のとおり。

- 「人ごとの負荷」カードで、全プロジェクトを重ねた `平均 / 最大 / 超過 n 日` が人ごとに出る。
- 行を開くと、プロジェクト別の内訳が出る。
- 横断をオフにすると、今までと同じ表示になる。
- ファイル形式(`version`)は変えない。

## 決めたこと(2026-10-21 に確認済み)

| 項目 | 決定 |
| --- | --- |
| 同一人物の判定 | メンバー名の完全一致。対応表は持たない(必要になったら別の要望) |
| 対象のプロジェクト | 格納先のすべてを既定にし、チェックで外せる(保存しない。開き直すと「すべて」) |
| 稼働可能時間・始業が違うとき | 各タスクの期間をそのプロジェクト自身の設定で計算し、日時のまま重ねる。割り当て率は「その人の時間の割合」なので足せる。祝日は全プロジェクト共通 |
| 開いているプロジェクトの未保存の編集 | 開いているものはメモリ上の内容、ほかはディスクの内容 |
| 見せ方 | 「人ごとの負荷」カードの拡張。日ごとのヒートマップは要望 47 |

## 集計(`dashboard.py`。純粋関数)

`summarize_cross_loads(projects, period, holidays, member=None) -> dict[str, CrossLoad]` を足す。

- 各プロジェクトについて、既存の `Schedule`・`counted_span`・`counted_assignees` で期間を求める。
- 担当者名をキーに `(開始, 終了, 割り当て率, プロジェクト名)` を集める。
- 日ごとの値は、既存の `_day_peak` と同じ「その日の同時刻の割り当て率の合計の最大」を、全プロジェクト分で計算する。稼働日は期間と祝日から求める(`_workdays`)。
- `CrossLoad` は、合計の `LoadStats` と、プロジェクトごとの内訳(その人について、そのプロジェクトだけで見た平均・最大)を持つ。その人がいないプロジェクトは内訳に出さない。
- `member` による絞り込みは、名前の一致で効かせる。
- 既存の `summarize_loads` は残す。プロジェクトが 1 件のとき、両者の合計の結果は一致する。
- 終了したタスク・担当者なし・日程なしを数えない前提は、既存の負荷と同じ。

## 読込(新規 `portfolio.py`。NiceGUI から切り離す)

`load_others(project_dir, current_path) -> tuple[list[Project], list[LoadFailure]]`

- `storage.list_project_files` で格納先の `*.json` を走査する(`config`・`holidays` は除外済み)。
- 開いているプロジェクトのファイル(`current_path`)は除く。メモリ上の内容を使うため。
- 開いているプロジェクトが保存前の新規(ファイルなし)のときは、格納先の全ファイルがほかのプロジェクトになる。
- 各ファイルを `storage.load_project` で読む。読めないもの(壊れた JSON・新しすぎる`version`・検証エラー)は `LoadFailure(名前, 理由)` に集め、残りを読む。
- 読むのは、横断を使う表示のたびに行う。キャッシュはしない(保存しない方針)。

## 画面

`dashboard_view.py` の「人ごとの負荷」カードと、`views.py` の `refresh_dashboard`。

- 期間の横に `全プロジェクト` のスイッチ(既定オフ。保存せず、ダッシュボードを開き直すとオフ)。
- オフのとき: 今のまま。
- オンのとき:
  - 各人の行を、全プロジェクト合計の `平均 / 最大 / 超過 n 日` にする。行を開くと、プロジェクト別の `平均 / 最大` を出す。
  - スイッチの下に、プロジェクトごとのチェックを並べる。外したプロジェクトは合計に入らない。開いているプロジェクトも外せる。
  - カードに注記を一行出す: 名前の完全一致で同一人物とみなすこと、開いているプロジェクト以外は保存済みの内容であること。
  - 読めなかったファイルは、`読み込めなかったファイル: 名前(理由)` としてカード内に出す(通知は出さない)。
  - メンバーのプルダウンは、全プロジェクトのメンバー名の和集合にする。
- 格納先を読めないときは、開いているプロジェクト 1 件で集計し、その旨をカードに出す。

## 含まないもの

同一人物の対応表、日ごとのヒートマップ(要望 47)、横断の「工数の予定と実績」・進捗の集計、キャッシュ、メンバー以外の絞り込み。

## テスト

- `summarize_cross_loads`:
  - 1 件のとき `summarize_loads` と一致する。
  - 2 件で同じ人の期間が重なると、割り当て率が足されて 100% 超の日が数えられる。重ならなければ足されない。
  - 終了したタスクは数えない。
  - プロジェクトごとに稼働可能時間が違っても、日時で重なれば足される。
  - 内訳の最大が合計の最大を超えない。
  - 人が 1 つのプロジェクトにしかいないとき、メンバーの絞り込みが効く。
- `portfolio.load_others`: 開いているファイルを除く。壊れたファイルは `LoadFailure` に集めて残りを読む。`config.json`・`holidays.json` を読まない。保存前の新規でも動く。
- 画面: オフなら今と同じ。オンで合計と内訳が出る。チェックを外すと合計が変わる。読めないファイルの表示が出る。開き直すとオフに戻る。
- 実行: `uv run pytest --cov=projectapp -q`、型チェックは `uvx ty check src`。
