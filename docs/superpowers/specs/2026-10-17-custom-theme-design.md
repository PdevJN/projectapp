# カスタムテーマの設計(要望 28)

> **状態**: 実装済み — 要望 28 — マージ PR #26(ef8ade3。2026-10-18)。当時の記録で、現在の仕様は [`CLAUDE.md`](../../../CLAUDE.md) を正とする。

## 目的

見た目の好みや環境に合わせて、アプリの色合いを自分で変えられるようにする。
成功の目安は次のとおり。

- テーマのメニューに`カスタム`が加わり、primary・ヘッダーの背景・画面の背景・文字の色・基調(ライト / ダーク)を設定できる。
- 色を変えると、その場で画面に反映する(プレビュー)。適用で保存し、キャンセルで元に戻す。
- 自動・ライト・ダークの見た目は変わらない。
- 読みにくい組み合わせは、コントラスト比で警告する(適用はできる)。

## 決めたこと

| 項目 | 決定 |
| --- | --- |
| 変えられる色 | primary、ヘッダーの背景、画面の背景、文字の色。あわせて基調(ライト / ダーク)を選ぶ |
| 変えない色 | 状態色・優先度の背景・土日祝の背景・予定超過の赤(基調で既存の値を選ぶ)。secondary / accent は対象外 |
| 設定の画面 | 専用ダイアログ(全プロジェクト共通。プロジェクトごとの`設定`とは分ける) |
| コントラスト | 比を表示し、WCAG AA(4.5:1)を下回ったら警告。適用はできる |
| 方式 | CSS 変数に集約する(案 A) |
| 保存先 | `~/.projectapp/config.json`(全プロジェクト共通) |
| Undo | 対象外(プロジェクトの内容ではないため、履歴にも「未保存」の判定にも入れない) |

## 方式の比較(採用理由)

- **CSS 変数に集約(採用)**: `カスタム`のときだけ`body`に変数を設定し、背景・文字・ヘッダーの指定を変数経由にする。ライト・ダークの値は変数の既定値として残るので、見た目は変わらない。PNG・プレビューは`body`の実際の値を見るだけで反映される。
- 上書き用の`<style>`を丸ごと注入(不採用): 既存の CSS を触らずに済むが、`!important`で詳細度の競合を押さえることになる。固定列・スクロールバーなどの個別の指定を漏らすと色が混ざり、保守しにくい。

## 保存形式(`config.json`)

```json
"theme": "custom",
"custom_theme": {
  "base": "dark",
  "primary": "#7e57c2",
  "header": null,
  "background": "#1e1e2e",
  "foreground": "#e6e6f0"
}
```

- `theme`は`auto`・`light`・`dark`・`custom`。不正な値は`auto`。
- `custom_theme`は`theme`とは別のキー。`カスタム`以外を選んでいる間も色は残る。
- `base`: `light`か`dark`。不正な値は`light`。
- `primary`・`background`・`foreground`: `#RRGGBB`のみ(大文字小文字は区別せず、保存は小文字)。不正な値は、そのキーだけ既定に戻す。
- `header`: `null`(primary に追従)か`#RRGGBB`。追従で基調がダークなら、今と同じく primary を 55% 暗くする。色を指定したときはそのまま使う。
- 既定値は、基調ごとに今の見た目にそろえる。キーのない古いファイルは既定値で読む。ほかのキーは壊さない(`name_width`と同じ扱い)。
- 既定値: ライトは primary `#5898d4`・背景 `#ffffff`・文字 `#000000`、ダークは primary `#5898d4`・背景 `#121212`・文字 `#ffffff`。primary は NiceGUI の既定(`app.config.quasar_config['brand']['primary']`)で、テストで一致を固定する。ダークの背景は Quasar の`--q-dark-page`(`#121212`)、ダークの文字は`#ffffff`で、スタイルシートで確認済み。ライトの文字色は未確認なので、ネイティブの実機確認で、ライトの`body`の実際の文字色(計算済みの値)と一致することを確かめ、違えばこの値を直す。

## 構成

### `theme.py`(新規。NiceGUI に依存しない純粋関数)

```python
@dataclass(frozen=True)
class CustomTheme:
    base: str              # "light" | "dark"
    primary: str           # "#rrggbb"
    header: str | None     # None = primary に追従
    background: str
    foreground: str

DEFAULTS: dict[str, CustomTheme]            # 基調ごとの既定
def parse_custom_theme(value: object) -> CustomTheme   # 不正なキーだけ既定に戻す
def normalize_hex(text: str) -> str | None             # "#RRGGBB" の検証と小文字化。不正は None
def contrast_ratio(fg: str, bg: str) -> float          # WCAG の相対輝度から求める
def on_color(bg: str) -> str                           # 背景に対して、白か黒のうち比の高いほう
def header_color(theme: CustomTheme) -> str            # 実際のヘッダーの背景(追従・暗くする規則を含む)
def css_variables(theme: CustomTheme) -> dict[str, str]  # body に設定する変数(--q-primary を含む)
def theme_js(theme: CustomTheme | None) -> str         # 変数とクラスを設定する JS。None は全部外す
def warnings(theme: CustomTheme) -> list[str]          # 警告の文言(4.5:1 を下回る組み合わせ、基調と背景の明るさの不一致)
```

### `config.py`

- `THEMES`に`"custom"`を足す。
- `load_custom_theme(base_dir)`・`save_custom_theme(theme, base_dir)`を足す(`update_config`を使う)。

### `views.py`

- 定数: `THEME_LABELS`・`THEME_ICONS`に`custom`(`カスタム`・`palette`)を足す。
- `apply_theme`: 基調を`ui.dark_mode()`に反映する。`custom`のときは`custom_theme.base`、それ以外は今のとおり。続けて、変数の設定または解除を行う。
- テーマのメニュー: 自動・ライト・ダーク・`カスタム`・(水平線)・`カスタムの色…`。マーカーは`theme-custom`・`theme-custom-settings`。
- CSS: ヘッダーの背景・文字、メニューのボタンとチップの半透明の色を変数経由にする。

### `gantt.py`

- 固定列・チャート枠・スクロールバーの背景(`var(--q-dark-page, #121212)`)を、`var(--app-bg, var(--q-dark-page, #121212))`のように、`--app-bg`を先に見る形にする。ライトの背景(白)も同様。
- 文字色は`var(--app-fg, …)`。
- 状態色・優先度色・土日祝・予定超過の値は変えない。

### `forms.py`(または新規の`theme_dialog.py`)

- `open_theme_dialog`: カスタムの色のダイアログ。

### `export.py`

- `CAPTURE_JS`の背景を、`カスタム`のときは`body`の実際の背景色にする(`body`に`app-custom`クラスがあるか、で判定)。ライト・ダークの書き出しは変えない。

## 適用の仕組み

- `カスタム`のときだけ、`body`にクラス`app-custom`と、変数`--app-bg`・`--app-fg`・`--app-header`・`--app-header-fg`を設定する。
- primary は`body`の`--q-primary`を直接設定して変える(`ui.colors()`が内部でしていることと同じ。`ui.colors()`はイベントの中で呼ぶと、呼び出し時のスロット〔ダイアログ〕に要素ができて、閉じると消えるので使わない)。ボタンなどの部品が追従する。カスタム以外へ切り替えるときは、`removeProperty`で外して NiceGUI の既定に戻す。
- ヘッダーの文字色は`on_color(header_color(theme))`(`--app-header-fg`)。メニューのボタンとチップの半透明の背景は`--app-header-chip`・`--app-header-chip-hover`で持ち、既定は今の半透明の白。ヘッダーの文字が黒のときは、半透明の黒に替える。
- 背景は`body.app-custom { background: var(--app-bg); color: var(--app-fg); }`で当てる。
- 変数の設定と解除は`ui.run_javascript`の 1 回の呼び出しで行い、再描画はしない。
- WebKit は`body--dark`が実行中に変わるとスクロールバーを描き直さないので、切り替えのたびに既存の`refresh_scrollbars()`を呼ぶ。
- Quasar のダイアログ・メニューなどの部品の背景は、基調(`body--dark`)に従う。

## カスタムの色のダイアログ

- 入力項目: 基調(ライト / ダークのトグル)、primary、ヘッダーの背景、画面の背景、文字の色。
- 各色は、色のプレビューと`#RRGGBB`の入力欄を並べる(選択には`ui.color_input`)。
- ヘッダーの背景には`primary に追従`のチェックを付ける。オンのときは入力欄を隠す。
- 色を変えると、すぐ画面に反映する(プレビュー)。開いた時点の`theme`と`custom_theme`を覚えておく。
- ボタンは`適用`と`キャンセル`。`適用`は保存して閉じ、`theme`を`custom`にする。`キャンセル`・ESC・外側クリックは、覚えておいた状態に戻す。
- `既定に戻す`ボタンは、選んでいる基調の既定値を入れる(プレビューまで。保存は`適用`)。
- コントラスト: 文字の色 ↔ 画面の背景の比を表示し、4.5:1 を下回ったら橙の警告と文言を出す(例: `文字と背景のコントラスト比が 3.2:1 です。読みにくい可能性があります`)。適用はできる。ヘッダーの文字は白か黒の良いほうを自動で選ぶので、比は常に約 4.58:1 以上になる(明暗の境で最小)。そのため、ヘッダーは警告の対象にしない。
- 基調と背景の明るさが合っていない場合(基調がライトで背景が暗い、基調がダークで背景が明るい)も、橙の警告を出す(文言: `基調と背景の明るさが合っていません。ダイアログの文字が読みにくくなることがあります`)。Quasar のダイアログなどは基調に従い、背景だけが替わるため。明暗の境は、白と黒に対するコントラスト比が等しくなる相対輝度 0.179。
- 不正な`#RRGGBB`は、入力欄にエラーを出し、`適用`を押せなくする。プレビューは最後の有効な色のまま。

## エラー処理

- `config.json`の読み書きに失敗したら通知する。画面は変えない(保存は`update_config`の一時ファイル経由)。
- 読込時に`custom_theme`がオブジェクトでなければ、全体を既定にする。
- ダイアログが開いている間は、既存のルールどおり ESC と拡大・縮小以外のショートカットは効かない。

## テスト

- `theme.py`: 検証、正規化、コントラスト比(既知の組:白と黒で 21、同色で 1)、白黒の選択、ヘッダーの追従と暗くする規則、既定値、不正なキーだけが既定に戻ること。
- `config.py`: 読み書き、不正値、ほかのキーを消さないこと、古いファイル。
- 画面: メニューの項目とマーカー、ダイアログの適用・キャンセル(ESC を含む)・既定に戻す・追従のチェック・警告の表示・不正入力、変数の設定と解除、`カスタム`以外へ切り替えたときの primary の復元。
- 回帰: ライト・ダーク・自動で、CSS の既定値が変わらないこと(固定していた値と変数の既定値が一致すること)。
- 実機(ネイティブ): ライトの`body`の実際の文字色が既定の`#000000`と一致すること、ダーク基調でスクロールバーが描き直されること、PNG の背景、ヘッダーが明るい色のときの見え方、ダイアログのプレビューとキャンセルでの復元。
