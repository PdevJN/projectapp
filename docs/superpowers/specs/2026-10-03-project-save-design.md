# プロジェクトの保存 UI 設計書

## 目的

画面で編集したプロジェクトを `~/.projectapp/<名前>.json` に保存し、次回起動時に開けるようにする。いまは `storage.save_project` があるが画面から呼ばれず、編集内容が残らない。日程計算(`2026-10-03-schedule-calc-design.md`)の次の段階。

## 範囲

**含む**: 「保存」ボタン、新規プロジェクトの初回保存時の名前入力、名前の検証、保存後のファイル一覧とタイトルの更新、保存の失敗時の通知、書き込みの安全化(一時ファイル経由)。

**含まない**(後続のサブプロジェクト):
- 削除、複製、別名で保存、プロジェクト名の変更
- 未保存の変更の警告、自動保存
- 実績の入力、稼働時間・始業時刻の設定画面、ドラッグ&ドロップほか

## 決定事項

- 保存は、明示的な「保存」ボタンのみ。自動保存はしない。
- 新規プロジェクトは、最初の保存時に名前入力ダイアログを出す。新規のうちはディスクにファイルを置かない。
- 開いて読み込んだプロジェクトは、同じ名前で上書き保存する。名前は変更できない。
- 読込時に `project.name` をファイル名(拡張子なし)にそろえる。ファイル名を手で変えても、画面の名前と保存先がずれて別ファイルができないようにする。

## 名前の検証

`storage.validate_name(name, base_dir, *, new) -> str | None` は、エラー文を返し、問題がなければ `None` を返す(純粋関数)。次の名前を拒否する。

- 空、または空白だけ
- 使えない文字を含む: `/` `\` `:` `*` `?` `"` `<` `>` `|` と制御文字
- `.` で始まる
- 予約名(`config`、`holidays`)
- `new=True` で、同名のファイルがすでにある

前後の空白は取り除いてから検証し、保存にも取り除いた名前を使う。長さの上限は設けない(OS が拒否した場合は保存の失敗として扱う)。

## 構成

| ファイル | 変更 |
|---|---|
| `storage.py` | `validate_name` を追加。`save_project` が名前を検証し(不正なら `ValueError`)、一時ファイルへ書いてから置き換える。`save_project(project, base_dir, *, overwrite=True)` の `overwrite=False` は、同名のファイルがあれば `FileExistsError` にする(新規保存の競合対策)。`load_project` が `name` をファイル名にそろえる |
| `forms.py` | `open_name_dialog(on_submit, validate)` を追加(既存の `open_section_dialog` と同じ作り) |
| `views.py` | `MainView.path`、`save_project_clicked`、「保存」ボタン、保存後の一覧更新を追加 |
| `models.py` | 変更なし |

`save_project(project, base_dir)` のシグネチャは変えない。読込時に名前をそろえるので、保存先は常に `base_dir / f"{project.name}.json"` で決まり、既存のテストもそのまま使える。

### `views.py`

- `self.path: Path | None`: `None` は未保存の新規プロジェクト。「開く」で読み込んだら、そのファイルのパスを入れる。
- 「保存」ボタンを、ヘッダーの「開く」の隣に置く。
- `self.file_select` に選択欄の参照を持ち、保存後に `set_options` で一覧を更新する。

## データの流れ

1. 「保存」を押す。
2. `path is None`(新規): 名前入力ダイアログを開く。検証に通ったら `project.name` に設定し、保存する。
3. `path` がある: そのまま同じ名前で上書き保存する。
4. 保存に成功したら、`path` を設定し、`files` と選択欄の一覧に追加し、タイトルを更新して「保存しました」と通知する。
5. 保存に失敗(`OSError`)したら、赤い通知を出し、`path` と画面の状態は変えない。新規なら、設定しかけた `project.name` を元に戻す。

## エラー処理

- 名前の不正は、ダイアログ内にエラー文を出し、通るまで閉じない。
- 書き込みの途中で失敗しても、一時ファイルを経由するので元のファイルは壊れない。残った一時ファイルは削除する。
- 検証後に同名のファイルが作られていた場合(競合)は、新規保存では上書きせずエラーにする。

## テスト

- `storage`: `validate_name`(空、使えない文字、先頭の `.`、予約名、重複、`new=False` なら重複を許す、前後の空白)、`save_project` の往復、不正な名前で `ValueError`、書き込みの失敗時に元のファイルが残ること、読込時に `name` がファイル名にそろうこと。
- `forms`: 名前入力ダイアログが、不正な名前ではエラーを出して閉じず、正しい名前で `on_submit` を呼ぶこと。
- `views`: 新規の保存でダイアログが出ること、名前の重複で拒否されること、保存後に一覧とタイトルが更新されること、開いたファイルはダイアログなしで同じ名前に上書きされること、保存の失敗で状態が変わらないこと。
- 手動確認(実機): 新規で保存して再起動し、「開く」で読み込めること。
