# インラインセクション(セクションの入れ子) 設計書

作成日: 2026-10-09
ブランチ: `feature/nested-sections`(`develop` から)
経路: architectural(設計書 → 実装計画 → 実行)
要望: 作業記録の要望 7「インラインセクション: root から3階層まで」

## 1. 目的と合意した範囲

セクションの中にサブセクションを置けるようにする(セクション → サブセクション → サブサブセクションの最大 3 階層)。タスクは、root(セクションなし)と、どの階層のセクションにも置ける。同じ画面に、インデントして並べて表示する。

合意した決定(2026-10-09):

- 階層は、root を数えず、セクションを 3 階層まで。
- セクションの中の並びは、タスクが先、サブセクションが後(root と同じ規則)。
- セクションの位置は、番号のパス(タプル)で表す(案 1)。セクションに ID は振らない。
- 1 階層目のマーカーは今のまま(`task-0-0` など)にして、既存のテストの多くがそのまま通るようにする。
- 今のセクションの操作は「追加」と「折りたたみ」だけで、改名・削除・移動はない。今回も増やさない。

やらないこと: セクション自体の改名・削除・移動・並べ替え、タスクとサブセクションの混在した並び、4 階層目以降、セクションへの ID。

## 2. データ(`models.py`・`storage.py`)

- `Section` に `sections: list[Section]`(既定は空)を足す。`Project.sections` が root 直下のセクション。
- `MAX_SECTION_DEPTH = 3`(root 直下のセクションが 1 階層目)。
- `Project.all_tasks()`: root のタスク、続いて各セクションを深さ優先で(そのセクションのタスク → そのサブセクション)返す。
- 保存: セクションの辞書に `"sections": […]` を入れ子で持つ。キーがない・`null` は空(古いファイルを移行なしで読む)。
- 読込で拒否する(「開けませんでした」): 4 階層以上、`sections` がリストでない・要素が辞書でない。名前の空・重複は、今と同じ扱い(セクション名は検証しない)。
- 古い版のアプリは、入れ子のセクションを含むファイルを読めない(サブセクションの中身が失われる)。

## 3. 位置の表し方(`arrange.py`)

- `SectionPath = tuple[int, ...]`。root は `()`、1 番目のセクションは `(0,)`、その 2 番目のサブセクションは `(0, 1)`。
- `Position = tuple[SectionPath, int]`(セクションのパス, 番号)。
- 純粋関数:
  - `section_at(project, path) -> Section | None`(root は None を返さず、呼び出し側が `path == ()` を先に扱う。範囲外は None)
  - `tasks_at(project, path) -> list[Task]`(root は `project.tasks`)
  - `valid_section(project, path) -> bool`(root は常に True)
  - `section_key(path) -> str`(`()` は `top`、それ以外は番号を「.」でつなぐ。`(0,)` は `0`、`(0, 1)` は `0.1`)
  - `parse_section_key(text) -> SectionPath | None`(`top`・`0`・`0.1`・`0.1.2`。不正・空・負・4 階層以上・数字以外は None)
  - `depth_of(path) -> int`(`len(path)`)
- `has_task`・`has_list`・`move_task`・`copy_task`・日程のずらしは、パスで動く。移動で元と先が同じ一覧のときの位置の補正は、今のまま。

## 4. 画面

### 4.1 描画(`gantt.py`・`links.py`)

- セクションの見出し、そのタスク、そのサブセクションの順に、再帰で描く。root のタスクと root 直下のセクションの並びは、今のまま。
- インデント: 見出しの文字と、タスクの名前の欄の左の余白を、階層ごとに 12px ずつ増やす。1 階層目のセクションは、今と同じ見た目。
- マーカーのキーは、パスを「.」でつないだ文字列(`section-0.1`・`task-0.1-3`・`bar-0.1-3`・`row-0.1-3`・`add-task-0.1`・`section-toggle-0.1`・`section-label-0.1`・`section-count-0.1`・`section-name-0.1`)。1 階層目(`0`)と root(`top`)は、今のまま。
- 矢印の行の並び(`links.row_slots`)も、同じ再帰で作る。`RowSlot` の `section` は `SectionPath`。

### 4.2 サブセクションの追加

- 1 階層目と 2 階層目のセクションの見出しに「サブセクション追加」のボタン(`add-subsection-<key>`)を出す。3 階層目のセクションには出さない。読み取り専用(プレビュー)では出さない。
- 押すと、今の「セクション追加」と同じ名前入力のダイアログが開き、そのセクションの `sections` の末尾に足す。親(と、その親すべて)は展開する。
- ヘッダーの「セクション追加」は、今のまま、root 直下に足す。
- 検証: 追加の対象のパスが存在し、深さが 3 未満であること。そうでなければ何もしない。

### 4.3 折りたたみ

- 折りたたみの状態は、パスの集合(`set[SectionPath]`)で持つ。保存はしない(今のまま)。
- セクションの折りたたみは、その中のタスクと、すべてのサブセクション(その見出しを含む)を隠す。子が単独で折りたたまれていても、親を開いたときは、子の折りたたみの状態を保つ。
- 見出しのタスク数は、サブセクションの分も含めた合計。サブセクションがないセクションは、今と同じ表示。
- タスクやサブセクションを足すときは、そのセクションと、その親をすべて展開する。
- プレビューでは、折りたたみを無視して全部出す(今のまま)。

### 4.4 絞り込み

- 絞り込み中は、折りたたみを無視する。タスクが 1 件も一致しないセクション(サブセクションを含む)は隠す。一致するタスクを持つセクションは、その親も表示する(階層が分かるように)。
- 絞り込みの純粋関数: `filtering.section_has_match(section, task_filter) -> bool`(自分と子孫のどれかのタスクが一致するか)。`visible_task_indexes` は、そのセクション自身のタスクだけを扱う(今のまま)。

### 4.5 ドラッグ(`gantt_drag.py`)

- ブラウザ側は、セクションを文字列のキー(`top`・`0`・`0.1`)で送る。サーバー側が `parse_section_key` で戻す。不正なキーは、今と同じく、黙って捨てる。
- タスクは、どの階層のセクションの見出しや、タスクの間にも、移動・コピーできる。見出しに落とすと、そのセクション自身のタスクの末尾(サブセクションの前)に入る。見出しの `count` は、自身のタスク数。
- ドラッグの JS は、node の動作テスト(`test_gantt_drag.py`)を、キーの文字列に合わせて直す。

### 4.6 `GanttActions` の変更

- `add_task(SectionPath)`、`edit_task(SectionPath, int)`、`move_task(Position, Position, bool)`、`shift_task(SectionPath, int, int)`。`add_subsection(SectionPath)` を足す。`add_section()`・`add_top_task()`・`set_name_width` は今のまま。

## 5. 影響する集計とモジュール

- セクションを直接たどっている箇所を、再帰に直す: `models.Project.all_tasks`、`timeline.visible_range`、`linkgraph.link_options`、`links.row_slots`、`storage`(保存・読込。保存は `asdict` が入れ子を再帰する)、`arrange`、`views`(`tasks_in`・`save_task`・`add_task`・`edit_task`・`delete_task`・`shift_task`・セクションの追加)、`gantt`(描画・折りたたみ・ドラッグ)。
- ダッシュボード、担当者向けの書き出し、割り当て超過、負荷、先行タスクの連結、日程計算は、`all_tasks` を通るので、変更は要らない。

## 6. テスト

- 既存のテストのうち、セクション番号を `int | None` で渡しているもの(`test_views`・`test_gantt`・`test_arrange` など)は、機械的に `(0,)` と `()` に直す(実装計画に、使い捨ての移行スクリプトと、手で直す箇所の一覧を書く)。
- 純粋関数を表で網羅する: `section_at`・`tasks_at`・`valid_section`・`section_key`・`parse_section_key`(正常、`top`、不正、4 階層)、`all_tasks` の順、`move_task`・`copy_task`・ずらし(入れ子のパス、同じ一覧の補正)、`section_has_match`。
- 保存・読込: 入れ子の往復、深さ 3 まで通り 4 は拒否、キーなしの古いファイル、`sections` の型の違い。
- `row_slots`: 入れ子の並び、絞り込みで親を残す、折りたたみ(子の状態を保つ)。
- 画面(`User` のシミュレーション): 入れ子の描画とインデント、タスク数の合計、親の折りたたみ、絞り込み、サブセクションの追加(3 階層目にボタンが出ない)、追加時の展開、ドラッグの移動・コピー(入れ子のセクションへ)。
- 実機(ネイティブ): インデントの見た目(ライト・ダーク、拡大・縮小、名前の欄の幅の調整)、折りたたみの操作感、ドラッグ。
