# 付け替え時の完了予定の見直しの設計(要望 32)

> **状態**: 設計(レビュー待ち)— 要望 32 — `feature/reassign-recalc`。現在の仕様は実装後に [`CLAUDE.md`](../../../CLAUDE.md) へ反映する。

## 目的

実績や進捗度のあるタスクで担当を付け替えたとき、残りの作業が新しい担当者でどれだけかかるかを、完了予定に反映するかどうかを、保存の場で選べるようにする。
成功の目安は次のとおり。

- 換算率が変わる保存のとき、確認ダイアログで`見直す`・`見直さない`・`編集に戻る`を選べる。
- `見直す`を選ぶと、完了予定が「今日から、残りの工数 ÷ 新しい換算率」で算出した日時になる。
- 工数・実績・進捗度は変えない。ファイル形式(`version`)も変えない。
- 実績も進捗度もないタスクでは、今までどおり確認を出さない。

## 背景

- 工数は「基準の人が全時間をかけた場合の時間」で保存する。担当を替えても工数は変わらず、換算率(担当者全員の 相対比率 × 割り当て率 の合計)だけが変わり、完了予定の自動算出が動く。
- 自動算出は、開始予定から工数の全部を新しい換算率で割り当てる。すでに消化した分は考慮しない。
- 実績は担当者に紐づかない。

## 決めたこと(2026-10-21 に確認済み)

| 項目 | 決定 |
| --- | --- |
| 「見直す」の意味 | 完了予定だけを見直す。工数は書き換えない |
| 見直しの式 | 完了予定 = `calc_end(今, (工数 − 消化分) ÷ 新換算率, 稼働可能時間, 始業時刻, 祝日)`。土日・祝日は反映される |
| 消化分 | 進捗度があれば 工数 × 進捗度。なければ、実績の区間の合計時間 × 旧換算率(工数を超えない)。どちらもなければ 0 |
| 持ち方 | 「手で指定」の完了予定として保存する。設定を変えても追従しない。ファイル形式は変えない |
| 選択を出す操作 | 換算率が変わる保存すべて(担当の追加・削除・入れ替え・割り当て率の変更) |
| 対象のタスク | 通常タスクで、工数があり、状態が`終了`でなく、実績または進捗度がある |

「実績または進捗度がある」は、要望の文面(実績が記録されている)より少し広い。進捗度だけを入れたタスクも消化分が分かるため含める(レビューで変えてよい)。

## 設計

### 純粋関数(新モジュール `reassign.py`)

NiceGUI に依存しない。`timeline.py` の`calc_end`・`assignees_rate`を使う。

- `consumed_hours(task, old_rate) -> float`: 消化分(基準の人の時間)。
  - `task.progress` が 1 以上なら `工数 × progress / 100`。
  - なければ、実績の区間(簡易は開始〜終了、区間は各行)の合計時間 × `old_rate`。終了のない区間は数えない。
  - 結果は`0`〜`工数`に丸める。
- `needs_review(old, new_assignees, project) -> bool`: 次をすべて満たすとき真。
  - 種別が通常、工数が正、状態が`終了`でない。
  - 実績があるか、進捗度が 1 以上。
  - 保存前後の換算率が、許容差(1e-9)より離れている。
- `reviewed_end(task, old_rate, new_rate, project, now) -> datetime | None`: 見直した完了予定。残り(工数 − 消化分)が 0 以下、または`calc_end`が`None`のときは`None`。

### 画面(`task_dialog.py` の `save()`)

1. `build_task` が成功したあと、元のタスクと新しい担当から`needs_review`を調べる。
2. 偽(または`reviewed_end`が`None`)なら、今までどおり`on_save`して閉じる。
3. 真なら確認ダイアログを出す。文面の例:「換算率が 1.00 → 0.50 に変わります。残り 8h を新しい担当で見直すと、完了予定は 2026-10-23 15:30 です。」
4. ボタン:
   - `見直す`: `planned_end`を算出値に、`planned_end_manual`を真にして`on_save`する。
   - `見直さない`: そのまま`on_save`する。
   - `編集に戻る`: ダイアログを閉じて編集に戻る。
5. 保存は、元に戻す 1 ステップのまま。

右クリックの名前の変更・分解・コピーなど、ほかの経路では出さない(担当を変えないため)。

### 現在時刻

`now`は引数で注入できるようにし、画面では`datetime.now()`を渡す。テストでは固定する。

## 範囲外

- 工数の書き換え、残りの工数の別入力欄、引き継ぎの履歴の保存(`version` を上げる案)。
- 実績の按分(ダッシュボード)の変更。
- 複数タスクの一括付け替え(要望 35)。

## テスト

- 純粋関数: 消化分の 3 パターン(進捗度・区間・なし)と上限、`needs_review`の各条件、祝日・土日またぎ、残りが 0 以下。
- ダイアログ(`User` のシミュレーション): 3 つのボタンの結果、実績なしでは出ないこと、割り当て率だけの変更でも出ること、`見直さない`で完了予定が変わらないこと。
- 既存の保存のテストが通ること。
