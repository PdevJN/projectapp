# メンバーの相対比率のパラメータ化 設計書

作成日: 2026-10-09
ブランチ: `feature/ratio-parameters`(`develop` から)
経路: architectural(設計書 → 実装計画 → 実行)
要望: 作業記録の要望 20「メンバーの相対割合のパラメータ化」

## 1. 目的と合意した範囲

メンバーの相対比率(今は 10〜300% の 1 つの数)を、複数のパラメータの判定値の合計で決められるようにする。たとえば「経験」「専門性」のようなパラメータを定義し、メンバーごとに段階(初級・中級・上級など)を選ぶと、相対比率が計算される。

合意した決定(2026-10-09):

- 換算式は足し算。`相対比率 = 基本比率 + 選んだ段階の判定値の合計`。
- パラメータの定義は、プロジェクト共通。パラメータは名前と段階のリストを持ち、段階は名前と判定値(%)を持つ。メンバーは、パラメータごとに段階を選ぶ。選んでいないパラメータの判定値は 0%。
- 今の `Member.ratio` は「基本比率」の意味で残す(既定 100%)。ファイルの形式は変わらず、古いファイルは移行なしで、これまでと同じ値になる。
- 合計が相対比率の範囲(10〜300%)を外れたときは、範囲に丸めて使い、メンバーの画面で示す。
- 範囲は要望 20 だけ。要望 22(複数アサイン)は実装済みで、換算率は担当者全員の `相対比率 × 割り当て率` の合計のまま、相対比率に実効比率を使う。

やらないこと: パラメータ・段階の並べ替え、パラメータごとの重み、段階を数値で直接入力する方式、メンバーごとに自由にパラメータを持つ方式、割り当て超過とダッシュボードの負荷の変更(これらは割り当て率だけを使うので、影響しない)。

## 2. データ(`models.py`・`storage.py`)

- `Level`: `name: str`(前後の空白を除く。必須。パラメータ内で一意)、`value: float`(判定値。割合。+0.2 が +20%。-0.9〜+2.9、小数点以下 2 桁の%まで)。
- `Parameter`: `name: str`(前後の空白を除く。必須。プロジェクト内で一意)、`levels: list[Level]`(0 件でもよい)。
- `Project.parameters: list[Parameter]`(既定は空)。
- `Member.levels: dict[str, str]`(既定は空。パラメータ名 → 段階名)。
- 保存:
  - プロジェクト: `"parameters": [{"name": …, "levels": [{"name": …, "value": …}]}]`。
  - メンバー: `"levels": {"経験": "上級"}`。
  - キーがない・`null` は空(古いファイルを移行なしで読む)。
- 読込で拒否する(「開けませんでした」):
  - パラメータ・段階の名前が空、または文字列でない。パラメータ名の重複、同じパラメータ内の段階名の重複。
  - `value` が数でない(真偽値を含む)、非有限、範囲外。
  - `parameters` がリストでない、`levels` がリスト・辞書でない、メンバーの `levels` の値が文字列でない。
- 読込で拒否しない: メンバーの選択が、存在しないパラメータや段階を指している(手で編集したファイル)。そのまま持ち、実効比率の計算では 0% として扱う。

## 3. 計算(`ratios.py`。NiceGUI に依存しない純粋関数)

- `RatioDetail`: `base: float`、`adjustments: list[tuple[str, str, float]]`(パラメータ名・段階名・判定値。存在する選択だけ)、`raw: float`(丸める前)、`ratio: float`(丸めたあと)、`clamped: bool`。
- `ratio_detail(member, parameters) -> RatioDetail`: `raw = base + 選んだ判定値の合計`。`ratio = min(max(raw, MIN_RATIO), MAX_RATIO)`。`clamped` は `ratio != raw`。存在しない参照は数えない。
- `effective_ratio(member, parameters) -> float`: `ratio_detail(...).ratio`。使えない値(非有限)の扱いは、`combine_rate` が守る。
- `timeline.assignees_rate(assignees, members)` は、引数に `parameters` を足し、`m.ratio` の代わりに `effective_ratio(m, parameters)` を使う。`conversion_rate(task, project)` は `project.parameters` を渡す。
- 編集ダイアログ(`task_dialog.py`)の換算(`AssigneeFields.chosen`・`refresh_conversion`・説明の文字列)は、`open_task_dialog` に `parameters` を受けて、実効比率を使う。メンバーの一覧に補った担当者(相対比率 100% とみなす)は、`levels` が空なので、そのまま 100% になる。
- 担当者向けの書き出し(`handoff.py`)は `conversion_rate` を通るので、自動で実効比率に追従する。
- パラメータのないプロジェクトと古いファイルは、これまでと同じ値になる。

## 4. 画面

### 4.1 メニュー(`views.py`)

- `プロジェクト`メニューに `パラメータ`(マーカー `open-parameters`)を足す。順は `新規プロジェクト作成`・`設定`・`メンバー`・`パラメータ`。

### 4.2 パラメータのダイアログ(`forms.py` の `open_parameters_dialog`)

- パラメータごとに、名前の入力(マーカー `parameter-name-<p>`)と削除ボタンを置き、その下に段階の行を並べる。各行は、段階の名前(`level-name-<p>-<l>`)、判定値(%。`level-value-<p>-<l>`。-90〜+290)、削除。
- 「段階を追加」(`level-add-<p>`)、「パラメータを追加」(`parameter-add`)、キャンセル、適用(`parameter-apply`)。エラーはダイアログ内に出す(`parameter-error`)。
- 検証(`ratios.build_parameters`): 名前が空・重複、判定値が範囲外・空・非有限・小数点以下 3 桁以上は、エラーにして適用しない。段階が 0 件のパラメータは許す。
- 行の改名を追えるよう、各行は元の名前(`original`)を持つ(メンバーのダイアログと同じ)。
- 適用では、パラメータの一覧、改名の対応、削除される選択を使っているメンバーの数を受け取り、後述の確認を経て `on_apply` を呼ぶ。

### 4.3 メンバーのダイアログ(`forms.py` の `open_members_dialog`)

- 1 行: 名前、基本比率(%)、パラメータごとの選択(「(なし)」と、`上級 +20%` のような段階)、削除。狭いときは折り返す。幅は 28rem から、パラメータの数に応じて広げる(最大 `max-w-full`)。
- 各行に、実効比率を読み取り専用で出す(マーカー `member-effective-<i>`。例: `相対比率 120%`)。選択や基本比率を変えると、その場で更新する。丸めたときは `相対比率 300%(範囲に丸めました)`。
- パラメータがないプロジェクトでは、今の見た目のまま(ラベルは「相対比率(%)」。実効比率の行は出さない)。パラメータがあるときだけ、ラベルを「基本比率(%)」にする。
- 追記(2026-10-09。実機の確認で、名前欄が入力しづらいとの指摘): 行の折り返しをやめ、表形式にした。見出しの行(`member-header-*`)と、列が揃ったグリッド(`member-grid`)で、名前・基本比率・パラメータごとの段階・実効比率・削除を並べる。入力はラベルなしの小さい枠にする(列の意味は見出しが示す)。名前の列は 7rem の固定幅(約半分に絞った。列の数や画面の幅で変わらない)。表の中のコントロールは 14px(入力・選択の文字、プルダウンの項目、実効比率)、行の高さは 36px、見出しは 12px のまま(`forms.MEMBER_TABLE_CSS`。`views.build` で追加する)。表は `member-scroll` の中に置き、横に伸びたときは横スクロールする。ダイアログの幅は、パラメータの数に応じて広げる(最大は画面の 96%)。パラメータがないときも同じ表(名前・相対比率・削除)にする。
- `forms.MemberRow` に `levels: dict[str, str]` を足す。`build_members` は、行の `levels` を、存在するパラメータ・段階だけに絞って `Member.levels` にする。基本比率の検証(10〜300%)は今のまま。

### 4.4 ほかの画面

- ガントチャートの見た目は変わらない(完了予定が実効比率で変わるだけ)。
- 編集中の判定(`is_dirty`)は、今のとおり、プロジェクトの内容の比較で決まる。パラメータとメンバーの適用は、保存せずに編集中にする。

## 5. 定義の変更・削除(`views.py`・`ratios.py`)

- `ParameterEdit`: `parameters`(新しい一覧)、`parameter_renames`(旧名 → 新名)、`level_renames`(パラメータの新名ごとに、旧名 → 新名)。
- `ratios.apply_parameter_edit(project, edit)`: プロジェクトの `parameters` を置き換え、全メンバーの `levels` を更新する。
  - パラメータ名・段階名を、改名の対応で付け替える。入れ替え(A↔B)でも、各選択は 1 回だけ書き換える。
  - 新しい一覧にないパラメータ、または段階への選択は外す(判定値 0% になる)。
- 判定値の変更は、確認なしで、全メンバーの実効比率に反映する(完了予定は保存せず、表示のたびに計算する)。
- 削除の確認: 削除するパラメータ・段階を選んでいるメンバーがいるときは、適用の前に確認ダイアログを出す(マーカー `parameter-delete-confirm`)。文面: `「経験」を選んでいるメンバーが 3 人います。削除すると、その選択は外れて判定値 0% になります`。複数あるときは、パラメータ・段階ごとに 1 行ずつ出す。選んでいるメンバーがいなければ、確認なしで削除する。
- メンバーを改名しても、`levels` は引き継ぐ(`Member` ごと作り直す `build_members` が `levels` を渡す)。

## 6. テスト

- 純粋関数を表で網羅する: `ratio_detail`・`effective_ratio`(足し算、基本比率との組み合わせ、丸め(下限・上限・ちょうど境界)、存在しない参照、選ばないパラメータ、パラメータなし)。`apply_parameter_edit`(改名、入れ替え、削除、段階の削除、使われていない削除)。`build_parameters`(名前の空・重複、判定値の範囲・桁)。
- 保存・読込: 往復、キーのない古いファイル、不正な値の拒否、存在しない参照を持つメンバーの読込。
- 換算: パラメータありの完了予定(`Schedule`)、担当者向けの見積もり、複数の担当者との組み合わせ。
- 画面(`User` のシミュレーション): `パラメータ` のダイアログの追加・削除・適用・エラー・削除の確認、メンバーのダイアログの選択・実効比率の更新・丸めの表示・パラメータなしの見た目・適用での `levels` の保存、編集ダイアログの換算の説明。
- 実機(ネイティブ): ダイアログの見た目(ライト・ダーク、拡大・縮小)、折り返し、操作感。
