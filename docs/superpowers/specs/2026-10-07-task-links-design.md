# タスク同士の矢印連結 設計書

作成日: 2026-10-07
ブランチ: `feature/task-links`(`develop` から)
経路: architectural(設計書 → 実装計画 → 実行)

## 1. 目的と合意した範囲

ガントチャートのタスク同士を「先行 → 後続」で連結し、棒線型の矢印で表示する。先行の完了が後続の開始に連動する。

合意した決定(2026-10-07):

- 連動の意味は **B(押し出しのみ)**。後続の実効の開始 = `max(自分の開始予定, 先行の完了)`。先行が早まっても、自分の開始予定より前には戻らない。実効の開始は保存せず、表示のたびに算出する。
- 連結の種類は、終了 → 開始(FS)だけ。先行は複数持てる。遅れ(ラグ)は持たない。
- 連結の作り方は、**編集ダイアログの「先行タスク」欄だけ**。矢印のドラッグでの連結と、矢印のクリックでの解除は、別の要望として切り離す。

やらないこと: FS 以外の連結、ラグ、ドラッグでの連結、矢印のクリックでの解除、プレビューの表示項目への「矢印」の追加。

## 2. データ(`models.py`・`storage.py`)

- `Task.id: str`: 8 桁の 16 進(`secrets.token_hex(4)`)。プロジェクト内で重複しない。
- `Task.predecessors: list[str]`: 先行タスクの `id` のリスト(既存の項目。これまで未使用だった)。
- 保存: `id` と `predecessors` を書く。
- 読込(古いファイルを既定値で読む。移行は要らない):
  - `id` のないタスクは、読込時に振る。`predecessors` のないタスクは空。
  - 不正な値は、読込を拒否する(「開けませんでした」の通知): `id` が文字列でない・空・重複、`predecessors` がリストでない・文字列以外を含む、存在しない `id` を指す、自分自身を指す、循環。
- コピー(`arrange.copy_task`): 新しい `id`。`predecessors` は空(現状どおり)。ほかのタスクの先行には、コピーを加えない。
- 削除: 他のタスクの `predecessors` から、そのタスクの `id` を取り除く。
- `docs/development.md` の「ファイル形式の注意」に、`id` と `predecessors` を追記する。

## 3. 日程の計算(`timeline.py`)

### 3.1 実効の開始 `effective_start`

- 先行がなければ `planned_start`(従来どおり)。
- 先行があれば `max(planned_start, 各先行の完了)`。`planned_start` が未入力なら、先行の完了の最大値。
- 先行の完了:
  - 状態が「終了」で、実績の終了があれば、その時刻(実際に遅れた分を後続に効かせる)。
  - それ以外は、先行の `effective_end`。
  - 完了予定が求まらない先行は、無視する。
- 実効の開始が非稼働日・時間外でも、そのまま使う(`calc_end` が稼働枠に割り当てる)。

### 3.2 実効の完了予定 `effective_end`

- 工数からの算出は、起点を実効の開始にする。
- 手指定の完了予定、および工数なしの `planned_end` は、押し出された分(実効の開始 − `planned_start`)だけ、同じ幅で後ろへずらす(バーの横ドラッグと同じ考え方。バーの逆転を防ぐ)。`planned_start` が未入力のときは、ずらさない。
- 締切は動かさない。押し出されて締切を過ぎれば、既存の超過の赤が出る。

### 3.3 `Schedule`

- `Schedule`: タスクの `id` から (実効の開始, 実効の完了) への対応。1 回の描画・集計の中で 1 度だけ作って使い回す(ガントチャートの描画、ダッシュボード、割り当て超過の集計)。
- 連鎖(A → B → C)は再帰で解く。訪問済みの集合を持ち、万一の循環では押し出しなしとして扱う(無限再帰しない)。
- 既存の `effective_end(task, project, holidays)` のシグネチャは変えない。単独で呼ぶときは、そのタスクの上流だけをその場で解くラッパーにする。

### 3.4 `planned_start` を読む箇所の扱い

| 場所 | 扱い |
|---|---|
| `timeline.py` の `counted_span`(割り当て超過) | 実効の開始へ |
| `timeline.py` の超過判定・進捗の期待値(`expected_progress` の呼び出し) | 実効の開始へ |
| `timeline.py` の `effective_end` / `computed_end` の呼び出し(約 360 行) | 実効の開始を起点に |
| `gantt.py` の棒の描画・見える範囲の判定・進捗の期待値 | 実効の開始へ |
| `gantt.py` の実績の棒・マーカー(840 行付近) | 実効の開始が要るか確認して、要るなら置き換える |
| `dashboard.py` の期間内の判定(48 行付近)・予定の期間(180 行付近) | 実効の開始へ(`Schedule` を使う) |
| `handoff.py` の基準日 | 実効の開始へ |
| `arrange.py` の `shift_task`・`min_shift_days` | 3.5 参照 |
| `views.py`(553 行付近) | 内容を確認して、必要なら置き換える |
| `forms.py`・`task_dialog.py`・`storage.py` | 置き換えない(自分の開始予定を入力・保存する) |

実装計画の最初に `grep planned_start` で全件を洗い出し、この表と突き合わせる。取りこぼしが最大のリスク。

### 3.5 バーの横ドラッグ(`arrange.py`・`gantt_drag.py`)

- 押し出されているタスクは、実効の開始を基準にずらす。新しい開始予定 = 実効の開始 + ドラッグした日数。
- 先行の完了の日より前へはずらさない(既存の「基準日より前へは動かさない」(`min_shift_days`)に足す)。
- 先行側をずらすと、後続は自動で追従する。後続の開始予定は書き換えない。

## 4. 編集ダイアログ(`task_dialog.py`・`forms.py`)

- 「先行タスク」欄: 複数選択のセレクト。候補は全タスクから、自分自身と、自分を(直接・間接に)先行にしているタスクを除く(循環を防ぐ)。
- 候補の表示は「セクション名 / タスク名」。同名が複数あるときは「(2)」などを添える。セクションなしは、セクション名を省く。
- 欄の下に、押し出されているときだけ 1 行のヒント: 「先行の完了により、実際の開始は 10/12 09:00 です」。
- 「編集中」の判定とキャンセル時の確認は、`current()` の比較に先行を含める。
- `build_task` は、存在しない `id`・自分自身・循環を検証し、不正なら保存しない。
- 新規タスクの `id` は、作成時に採番する。

## 5. 矢印の描画(`links.py` 新規・`gantt.py`)

- 行の並び: 表示中の行(見出し・追加行・タスク)を 1 か所で作り、描画と矢印の計算の両方が同じ並びを使う。行の高さは既存の定数(`ROW_HEIGHT_PX`、`ADD_ROW_HEIGHT_PX`、見出し)。
- `links.py`(純粋関数): 行の並びから縦位置を出す。先行と後続の棒の位置から、折れ線を求める。
- 形: 棒線型(直角の折れ線)。先行の棒の右端の中央から右へ 6px 出て、後続の行の中央の高さまで縦に動き、後続の棒の左端へ矢じりで入る。後続の左端が先行の右端から 12px 未満のときは、行の間を通る 4 区間の経路にする。
- 1 つの SVG を `ui.html` 1 要素で、チャート全体に重ねる(要素数を増やさない)。座標は、名前の欄の右端から始まる枠(`left: var(--name-w)`)の内側の px。`pointer-events: none`。重なりの順は、格子線・縞 < 矢印 < 棒 < 固定の名前の列 < 見出し。色は、ライト・ダークで CSS 変数の灰色。
- 出さない場合: 絞り込みでどちらかの行が隠れている、折りたたみで隠れている、どちらかの棒が表示範囲外。
- 折りたたみの切り替えは、再描画せず、矢印の SVG だけを作り直す。
- 全スケール(日次・週次・月次)、プレビュー、PNG 書き出しで出す。
- SVG の各経路に `data-link="先行ID-後続ID"` を付ける(テスト用)。

## 6. 影響範囲

`models.py`・`storage.py`・`timeline.py`・`links.py`(新規)・`gantt.py`・`gantt_drag.py`・`arrange.py`・`forms.py`・`task_dialog.py`・`views.py`・`dashboard.py`・`handoff.py`・`docs/development.md`・`CLAUDE.md`(連結の記述)。担当者向けの書き出しは、todoapp の形式に独自のキーを足さないため、`predecessors` を出さない(基準日だけ実効の開始にする)。

## 7. テスト(TDD。純粋関数を先に)

- `timeline`: 押し出し(先行が遅い・早い・同時)、先行が複数、連鎖、開始予定なし、終了済みの先行は実績の終了を使う、手指定の完了予定が同じ幅でずれる、工数なしの `planned_end` のずれ、循環の安全性、完了予定が求まらない先行の無視、`Schedule` と単独の `effective_end` が一致する。
- `storage`: 往復、古いファイルの読込、不正な値の拒否(存在しない `id`・自分自身・循環・重複・型の誤り)。
- `forms`・ダイアログ: 候補から自分と後続を除く、同名の区別、検証、編集中の判定、ヒント。
- `views`: 削除で `id` が外れる。`arrange`: コピーで先行が空、押し出されたタスクのドラッグ、`min_shift_days`。
- `links`: 縦位置(折りたたみ・絞り込みあり)、折れ線(通常・近接)。
- `gantt`: 矢印の有無(絞り込み・折りたたみ・範囲外)、折りたたみで矢印だけ更新、ダークテーマ、プレビュー、書き出し。
- 既存のテスト(約 1,271 件)、`ty check`、並列実行(`uv run pytest -n auto`)が通ること。
- 最後に、ネイティブで実機確認する(矢印の見た目、ライト・ダーク、全スケール、折りたたみ・絞り込み、ドラッグ、PNG)。

## 8. 段階(実装計画でタスクに分ける)

1. データ(`id`・`predecessors`・保存と検証)
2. 日程(`Schedule`・`effective_start`・置き換え)
3. ダイアログ(先行欄・ヒント・削除時の整合)
4. ドラッグへの反映
5. 矢印の描画(`links.py`・SVG)
6. ダッシュボード・書き出しの置き換えと文書の更新

## 9. リスクと保留

- `planned_start` の取りこぼし(3.4 の表と grep の突き合わせで防ぐ)。
- 行の縦位置のずれ(行の並びを 1 か所で作って防ぐ)。
- 保留: 矢印のドラッグ連結・クリックでの解除(別の要望)、先行の完了が範囲外のときの矢印の端の表示、頭文字が同じ担当者のような、表示上の区別が要る項目はなし。
