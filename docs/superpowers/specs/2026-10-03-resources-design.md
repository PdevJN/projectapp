# 見積もりのバッファ換算とリソース割り当て比率 設計書

## 目的

担当者(人的リソース)を、プロジェクトのメンバーとして管理し、見積もり(工数)を担当者ごとに実際の日数へ換算する。換算は2つの比率で決まる。

- **相対比率**: 基準の人(100%)に対する、人ごとの作業速度。
- **割り当て率**: その人の時間のうち、タスクに使う割合。同じ人の同時期の合計は、最大 100%。

`CLAUDE.md` の次の記述を実現する。

- リソースは、原則1人を基準倍率 100% として、その相対比率をパラメータで管理する。
- 見積もりは、人的リソースを時間に換算し、バッファをつけて日工数にする。バッファは、1日の稼働可能時間(既定 6.5h)で設定できる。
- 人的リソース1人は、プロジェクト内で最大 100% まで分散できる。

「見積もりのバッファ」は、稼働可能時間として今も完了予定の算出に効いている。この変更は、その上に、担当者による換算と、割り当ての合計の判定を足す。

## 範囲

**含む**: メンバー(名前と相対比率)の管理、タスクの担当者の選択と割り当て率、完了予定の算出への換算の反映、日工数の表示、割り当て合計の判定と警告(通知とガントの縞)、古いファイルの担当者の変換、文書と用語。

**含まない**(後続のサブプロジェクト、または対象外):
- 担当者でのガントの絞り込み・フォーカス、検索(別の機能)
- 日ごとの稼働カレンダー、休暇、メンバーごとの稼働可能時間
- 割り当て超過の自動解消(期間の自動調整)
- 実績に基づく割り当ての集計
- 見積もりの人日入力(工数は時間のまま)

## 決定事項

- 相対比率と割り当て率は**別の概念**。メンバーが `ratio`(相対比率)を、タスクが `allocation`(割り当て率)を持つ。
- 工数(h)は、**基準の人が、全時間をかけて作業した場合の時間**。入力は今のままの「時間」。
- 換算率 = `ratio × allocation`。換算後の工数 = 工数 ÷ 換算率。これを稼働可能時間の枠に割り当てる(`calc_end` の中身は変えない)。
- 担当者は**プロジェクトのメンバー一覧から選ぶ**(自由入力はやめる)。メンバーの管理は専用のダイアログで行う。
- 割り当て率の合計が 100% を超えても、**保存はできる**。通知(警告)と、ガントの縞で示す。
- 状態が「終了」のタスクは、合計に数えない。
- ガントでの表現は、**行の背景ではなく、タスクの棒の内側だけ**。超過している期間にだけ、斜めの縞を重ねる(予定超過の赤い行と混ざらない)。
- 手で指定した完了予定は、換算しない(利用者が日付を決めている)。

## データ

### モデル(`models.py`)

- `Member.name: str`、`Member.ratio: float`(相対比率。1.0 = 100%。既存)。範囲は 0.1 以上 3.0 以下(10%〜300%)。
- `Task.assignee: str | None`(既存)。メンバー一覧の名前、または `None`。
- `Task.allocation: float = 1.0`(新規。割り当て率)。範囲は 0.01 より大きく 1.0 以下(1%〜100%)。
- 定数: `MIN_RATIO = 0.1`、`MAX_RATIO = 3.0`、`MIN_ALLOCATION = 0.01`、`MAX_ALLOCATION = 1.0`。

### 読み込み(`storage.py`)

- `allocation` がないタスクは 1.0 で読む。
- メンバーの `ratio` と、タスクの `allocation` は、有限の数値で範囲内であること。範囲外・NaN・inf・bool・文字列は、「開けませんでした」と通知する(読み込みを拒否)。
- 担当者名がメンバー一覧にないタスク(古いファイルの自由入力)は、読み込み時に、その名前をメンバー(相対比率 100%)として追加する。名前の前後の空白は取り除いて照合する。担当者名が空(空白のみ)なら、担当者なし(`None`)にする。追加したメンバーは、読み込み直後のスナップショットに含める(開いただけでは「編集中」にならない)。保存すると書き込まれる。
- メンバー名の重複(手編集のファイル)は、最初の1件だけを残す。

## 換算と判定(`timeline.py`、純粋関数)

### 換算率

`conversion_rate(task, project) -> float`:担当者がメンバーに見つかれば `member.ratio × task.allocation`。見つからない、または担当者がなければ 1.0。

### 完了予定

`effective_end` の規則は、設計書 `2026-10-03-planned-dates-design.md` のとおり。算出の段(工数が 0 より大きく、開始予定があるとき)だけ、`calc_end` に渡す工数を `工数 ÷ 換算率` にする。

- 手で指定の完了予定、締切、開始予定の翌日の規則は変えない。
- 換算率が 1.0 のとき、結果は今と同じ。
- `computed_end(start, effort_hours, daily_hours, work_start, holidays, deadline=None, rate=1.0)` に、`rate` を足す。`rate` が 0 以下や NaN のときは、換算しない(1.0 として扱う)。

### 日工数

`effort_days(effort_hours, rate, daily_hours) -> float | None`:工数が 0 より大きく有限、`daily_hours` が 0 より大きいとき、`工数 ÷ 換算率 ÷ daily_hours`。それ以外は `None`。ダイアログの表示に使う(入力途中の値で計算するため、タスクではなく数値を受け取る)。

### 割り当て合計の超過

`overallocations(project, holidays) -> list[Overload]`:

- `Overload`: `member: str`、`start: datetime`、`end: datetime`、`total: float`(区間内の合計の最大値。1.0 = 100%)。
- 対象のタスク: 担当者がメンバーに見つかり、状態が「終了」でなく、開始予定と `effective_end` が両方あり、`effective_end` が開始予定より後。
- 期間は [開始予定, `effective_end`)(終端は含まない)。同じ人のタスクについて、区間の境界で切って、各区間の割り当て率の合計を求める。合計が 1.0 を超える連続した区間を、1つの `Overload` にまとめる。端が接するだけ(終了 = 次の開始)は、重ならない。
- 浮動小数の誤差のため、合計の比較には小さな余裕(`1.0 + 1e-9`)を持たせる。ちょうど 100% は超過にしない。
- タスクごとに、自分に重なる超過の区間を取り出す補助関数 `clip_overloads(task, project, holidays, overloads)` を持つ。

## 画面

### メンバーのダイアログ(`forms.py`、新規)

- ヘッダーの「設定」の隣に「メンバー」ボタンを置く(マーカー `open-members`)。
- 一覧は、名前と相対比率(%)の行。行ごとに編集と削除。下に追加の入力欄(名前、比率。既定 100)と「追加」。
- 検証(`build_member`):名前は前後の空白を取り除き、空と重複(完全一致)を拒否。比率は 10〜300 の数値(%)で、小数点以下は 2 桁まで。
- 名前の変更は、そのメンバーを担当するタスクの `assignee` もまとめて変える。
- 削除は、担当するタスクが 1 件でもあれば拒否する(「担当するタスクが N 件あります」)。
- 「適用」で反映する(保存は自動ではしない)。「編集中」の判定に入る。同じ値なら何もしない。ダイアログは閉じると要素を取り除く(`disposable`)。

### タスクの編集ダイアログ(`task_dialog.py`)

- 並び: 名前 → 1行目(開始予定・完了予定) → 2行目(締切・工数) → 3行目(担当者・割り当て率) → 優先度 → 状態 → 色。
- 担当者: メンバーの選択欄(先頭に「(なし)」)。割り当て率: 数値欄(%)。担当者が「(なし)」のときは無効にして、100% 固定で保存する。既存の値が非表示のとき、入力した値は保つ。
- 換算の表示(工数の下の補助行): 担当者がいて、工数が 0 より大きいときだけ。例:「15h → 2.3日分(相対比率 120% × 割り当て 80%)」。小数点以下 1 桁。工数、担当者、割り当て率の入力に追従する。
- 完了予定の算出値の表示は、換算を反映する。
- 保存時、その担当者の合計が 100% を超えるなら、保存したうえで警告を通知する(「田中 の割り当てが 120% になる期間があります」)。
- 変更の判定(閉じる確認)に、担当者と割り当て率を含める。

### ガントチャート(`gantt.py`)

- 超過区間と重なる部分に、棒の上へ斜めの縞を重ねる(半透明の白と黒の縞で、タスクの色に依存しない)。重ねる要素は、クリックを通す(`pointer-events: none`)。
- 縞の位置は、棒の位置計算(`_position`)で求める。棒の外側にはみ出さない。
- ツールチップは、「田中 の割り当てが最大 120%(2026-06-12〜2026-06-18)」。
- 行の背景は変えない。名前の横のアイコンも付けない。

### 用語

画面の「担当者」はそのまま。「相対比率」と「割り当て率」を使う。`CLAUDE.md` に定義を書き足す。

## テスト

先にテストを書く。

- **モデルと保存**: 往復(`ratio`、`allocation`)、`allocation` のない古いファイルは 1.0、担当者の自動追加(重複なし、前後の空白、空白のみは `None`、メンバー名の重複)、範囲外・NaN・inf・bool・文字列の `ratio` / `allocation` の拒否、自動追加が読み込み直後の「編集中」にならないこと。
- **換算**: 換算率 1.0 で今と同じ、`ratio` が大きいほど早い、`allocation` が小さいほど遅い、担当者なし・メンバーに見つからないとき換算なし、手で指定の完了予定は換算しない、算出できないときの締切への代替、`rate` が 0 以下・NaN のとき換算しない。
- **日工数**: `effort_days` の値(例: 15h、1.2 × 0.8、6.5h/日 = 約 2.44)、工数 0 以下・NaN・inf は `None`。
- **超過の判定**: 重ならない、端が接する、合計がちょうど 100%、101%、3 件が部分的に重なる、状態が「終了」を除く、担当者なし・開始予定なしを除く、完了予定が開始予定より前を除く、区間のまとめ方、他の担当者は混ざらない。
- **メンバーのダイアログ**: 追加、重複拒否、空の名前、範囲外の比率、名前の変更がタスクに伝わる、担当するタスクがある削除は拒否、「編集中」になる、同じ値の適用では何も起きない、閉じると要素が消える。
- **タスクのダイアログ**: 担当者の選択肢、「(なし)」で割り当て率が無効・100%、換算の表示が入力に追従する、超過のときの警告通知、既存タスクが値を持って開く、変更の判定。
- **ガント**: 縞が超過区間にだけ出る、棒の外にはみ出さない、クリックが効く、ツールチップ、縞が出ない場合(超過なし、棒なし)。
- **実機での確認**: メンバーのダイアログの見た目と幅、担当者と割り当て率の欄、換算の表示、縞(ライト/ダーク)、警告の通知、旧形式のファイルの担当者の自動追加。

## 実装の順序

ブランチは `develop` から `feature/resources` を切り、関心ごとに `feature/resources-<関心ごと>` を切って、本体にマージする(`feature/resources/…` は Git の参照名の制約で作れない)。

1. モデルと保存(`-model`)。
2. 換算と超過の計算(`-calc`)。
3. メンバーの管理(`-members`)。
4. タスクのダイアログ(`-dialog`)。
5. ガントの縞(`-gantt`)。
6. 文書(`-docs`)。
