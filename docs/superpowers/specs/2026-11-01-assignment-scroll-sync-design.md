# 割り当て表とガントチャートの横スクロール連動の設計(要望 117)

> **状態**: 実装済み(`feature/assignment-scroll-sync`。実機確認待ち。計画 [`plans/2026-11-01-assignment-scroll-sync.md`](../plans/2026-11-01-assignment-scroll-sync.md))。要望 116(割り当て表示)の第 2 段階。[元の設計](2026-11-01-assignment-view-design.md)

## 目的

下部パネルの`割り当て`表を見ながら、ガントチャートの同じ日の列と見比べられるようにする。表とチャートの横位置を揃え、どちらを動かしても、もう一方がついてくる。

## 決めたこと

| 項目 | 決定 |
|---|---|
| 連動の向き | 両方向。表を横に動かすとチャートも動き、チャートを動かすと表も動く |
| 揃える仕組み | 表の左端の担当者列を、チャートの名前欄と**同じ幅**(`--name-w`と同じ`name_width`)の`position: sticky; left: 0`にし、日付の列を、チャートと**同じ px 幅**(`COLUMN_WIDTH_PX[scale]`:日次 40・週次 56・月次 80)にする。両方の`scrollLeft`を同じ値にすれば、同じ日の列が縦に揃う。列は両方とも同じ`build_columns`の結果なので、日付はずれない |
| 担当者列の幅 | チャートの名前欄と同じ。名前欄の幅をドラッグで変えたら、表の担当者列も追従する。長い名前は省略表示(`…`)にし、ホバーで全文を出す。アイコン(18px)は残す |
| セルの数字 | 日次(40px)に 3 桁(`200`)が入る大きさ(12px)のまま。幅に収まらない場合は、数字を`…`にせず、はみ出させない(`overflow: hidden`)。ホバーで`割り当て率(%)`を出す |
| 縦のスクロール | 連動しない。担当者が多いときだけ、表の中で独立して縦にスクロールする |
| 連動の方法 | 小さな JS。両方の`scroll`イベントを受け、もう一方の`scrollLeft`を合わせる。片方が動かしている間(合わせている最中の`scroll`)は無視してループを防ぐ |
| 表示しない間 | `割り当て`ビューを出していないときは、連動しない(表がない) |
| 保存 | しない。ファイル形式(`version`)は変えない |

## 構成

| 部品 | 役割 |
|---|---|
| `bottom_panel.py` | 表の列幅(担当者列は`name_width`、日付列は列幅の px)を受け取って描く。担当者列を sticky にし、名前を省略表示にする。表の横スクロール枠に`data-assignment-scroll`を付ける |
| `gantt.py` | 表に、いまの刻み(`COLUMN_WIDTH_PX[view_scale]`)と`name_width`を渡す。連動の JS を、`割り当て`ビューを出したとき・描き直したときに仕掛ける。名前欄の幅が変わったら、パネルを更新する |
| 純粋関数 | 列幅などを決める小さな関数(`bottom_info.py`)。NiceGUI に依存せず、単体でテストする |

## 守るもの

- 既存の`TRACK_SCROLL_JS`(スクロール位置の記憶)・`SHOW_CHART_JS`(戻すときの位置)を壊さない。チャートの`scroll`の処理に、連動を足すだけにする。
- 画面の拡大・縮小(`zoom`)で、揃いがずれない(両方に同じようにかかる)。
- `割り当て`ビューの切り替え・選択でパネルが描き直されても、横位置が先頭に戻らない(要望 116 の最終レビューで先送りした、選択のたびに表が作り直される件は、ここで直す。描き直したあとに、チャートの`scrollLeft`へ合わせる)。

## テスト

- 純粋関数: 刻みごとの列幅
- 画面: 表の列幅・担当者列の幅が、`COLUMN_WIDTH_PX`・`name_width`と一致する。名前欄の幅を変えると表の担当者列が追従する。刻みを変えると列幅が変わる。選択で描き直されても、連動の JS が仕掛け直される。
- 既存の smoke、`ruff`・`ty`
- 実機でしか確かめられない: チャートを動かすと表がついてくる、表を動かすとチャートがついてくる、揃い(日次・週次・月次)、名前欄の幅のドラッグ、`当日`への移動、拡大・縮小、選択しても位置が戻らない

## 範囲外

- 表からのタスクの選択・編集
- 連動の入り切り(常に連動)
