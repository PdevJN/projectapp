# チームの設計

> **状態**: 完了(段階 1・2: PR #126、段階 3: PR #127。実機確認済み。2026-10-30〜31)。計画 [段階 1](../plans/2026-10-30-teams-stage1.md)・[段階 2](../plans/2026-10-30-teams-stage2.md)・[段階 3](../plans/2026-10-30-teams-stage3.md) — 要望 85。現在の仕様は [`CLAUDE.md`](../../../CLAUDE.md) に反映済み。

## 目的

プロジェクトに「チーム」を登録し、次の 3 つに使う。

1. 担当の割り当て: チームを選ぶと、メンバーをまとめて担当に入れる。
2. 絞り込みと集計: ガントチャートとダッシュボードを、チームで絞る。
3. 負荷と必要人数: `人ごとの負荷`・`残りの工数と必要人数`・`工数の予定と実績`を、チーム単位で出す。

## 決めたこと(2026-10-30 に確認済み)

| 項目 | 決定 |
| --- | --- |
| 持つ単位 | プロジェクトごと(メンバーと同じ) |
| メンバーとの関係 | 1 人は複数のチームに入れる(兼務)。チームなしも可 |
| 兼務の集計 | 所属の割合で按分する(例: A 60%・B 40%)。合計は全員と一致する |
| 割合の制約 | チームに入っているメンバーは、所属の割合の合計をちょうど 100% にする |
| 担当への割り当て | 展開方式。チームを選ぶとその時点のメンバーを担当者として入れ、タスクにチームの記録は残さない |
| 絞り込み・集計 | メンバーの所属から導く。チームとメンバーの絞り込みは、同じプルダウンのどちらか一方 |
| 進め方 | 段階 1(データ・管理・割り当て)→ 2(絞り込み)→ 3(集計)。PR は段階ごと |

## 段階 1: データと管理画面

- **モデル**: `Team`(安定した `id`・名前)を `Project.teams` に持つ。所属はメンバー側の `Member.teams: list[Membership]`(`team_id`・割合 1〜100 の整数)。
- **ファイル**: `version` を 17 に上げる。キーのない古いファイルは「チームなし」で読む。存在しないチーム `id`・同じチームの重複した所属・合計が 100% でない所属は、読込を拒否する。
- **管理画面**: `メンバーとパラメータ`に`チーム`タブを足す(名前の登録・改名・削除)。メンバーの表に`チーム`列を足し、所属の割合を入れるボタンを置く。適用・未適用の `●`・キャンセルは既存のタブと同じ作法。1 つのチームだけに入れるときは割合の入力を出さず 100% にする。
- **チームの削除**: 所属するメンバーがいるときは確認(人数を添える)を出し、その所属を外す。残る所属の割合は比を保って 100% に正規化し、端数は最大の所属に寄せる。所属が 0 になれば`チームなし`。
- **元に戻す・3 者マージ**: 元に戻す対象に含める。マージはチームを `id` で、メンバーの所属をリスト全体で 1 項目として比べる。
- **担当への割り当て**: タスクの担当欄に`チームから追加`を足す。チームと割り当て率を指定すると、メンバーを 1 人ずつ担当に加える(いる人は更新)。所属するメンバーがいないチームは選べず、理由を出す。
- **入力の検証**: チーム名は 30 文字以内で、制御文字・ゼロ幅文字は不可(タスク名と同じ)。同じ名前・空は不可。割合は整数 1〜100%、合計が 100% でないと、メンバーの表の`適用`を押せず、行にエラーを出す。

## 段階 2: 絞り込み

- **ガントチャート**: ツールバーの担当者の絞り込みに`チーム`の選択肢を足す。チームのメンバーが担当に入っているタスクだけを出す。共同タスクは 1 件として丸ごと出し、担当なしは入らない(メンバーの絞り込みと同じ)。
- **ダッシュボード**: 期間の横のプルダウンに`チーム`を足す。選ぶと、全カードがそのチームのメンバーが担当のタスクだけになる。`全員`のときは、`進捗と遅れ`の`メンバー別`の隣に`チーム別`の行を足す。
- **ビュー**: 保存済みのビューにチームの選択も入れる。保存したチームが今の名簿にないときは、画面だけ`全員`に戻す(ビューは書き換えず、`●`も出さない)。

## 段階 3: 集計

按分は、メンバーの値にチームの割合を掛ける(例: 田中の負荷 80%・所属 A 60%・B 40% → A に 48%、B に 32%)。ファイル形式は変えない(version 17 のまま)。集計は保存せず、表示のたびに計算する。

### 実装の方針(2026-10-30 に承認済み)

`dashboard.Scope` に重みを持たせる。チームを選ぶと、`{メンバー名: 所属の割合}`(割合は `percent / 100`)の辞書を渡す。メンバーを選んだとき・全員のときは、重み 1.0 と同じ扱いで、結果は今までと変わらない。各集計は、メンバーの値に重みを掛ける。`_names` はキーの集合を返し、重みは `_factor(scope, name)` で引く。

却下した案: 全員分を計算したあとにチームごとに掛ける(必要人数の日数 `ends` が、絞ったタスクから決まるため求まらない)・チームごとに別の集計関数を作る(重複し、合計の一致を保ちにくい)。

### 按分する集計

- **`残りの工数と必要人数`**: 共同タスクを割り当て率の比で按分したあと、各担当者の分に重みを掛ける。工数の合計・状態ごとの内訳・担当別の行・必要人数は、この値で出す。今いる人員は、`相対比率 × 重み` の合計。必要人数の日数は、絞ったタスクの完了予定・締切から、今までどおり決める。
- **`チーム別`の行**(`全員`のときだけ。担当別の隣): メンバーごとの残りの工数を、所属の割合で各チームに配る。どのチームにも入っていないメンバーは `チームなし` の行に入れる。担当なし(`未割当`)の行は今までどおり。チーム別の行の合計は、全員の合計と一致する(端数の誤差を除く)。0 の行は出さない。
- **`人ごとの負荷`**: 人の行は変えない。チームを選ぶと、平均と最大に重みを掛けて出す。**100% 超の日数は、掛ける前の値で判定する**(兼務の人が、割合のせいで超過に見えなくなるのを避ける)。
- **`工数の予定と実績`**: 予定と実績の両方に重みを掛ける(担当者への按分のあと)。

### 按分しない集計

`進捗と遅れ`・`チーム全体の進捗`の円グラフ・`期限とマイルストーン`は、段階 2 のとおり、共同タスクを丸ごと数える。按分するのは、工数と負荷だけ。全プロジェクトを重ねる負荷(`CrossLoad`)は、チームの重みを掛けない(段階 2 のとおり、メンバー名で絞るだけ)。

## テスト

- モデル: 読み書きと検証(拒否する値)、削除時の正規化、改名の追従、3 者マージ。
- 管理画面: チームタブの登録・改名・削除、メンバーの表の割合、`適用`の無効化、元に戻す。
- 割り当て(段階 1): `チームから追加`の展開と更新。
- 絞り込み・集計(段階 2・3): 絞り込みの対象、按分した負荷・工数・必要人数、`チーム別`の合計が全員と一致すること、ビューの保存と復元。

## 含めない

- タスクにチームを持たせる(名簿の変更への追従)。
- 週ごとの担当をチーム単位で入れる(展開した担当者で、今までどおり入れる)。
- チームごとの稼働設定・上限。
