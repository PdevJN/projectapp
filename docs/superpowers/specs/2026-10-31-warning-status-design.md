# 警告の状態の設計

> **状態**: 完了(PR #161・#162・#163。2026-10-31)。要望 103。実装は 3 段階(計画は `plans/2026-10-31-warning-stage1.md` ほか)。現在の仕様は [`CLAUDE.md`](../../../CLAUDE.md) に反映済み。

## 目的

遅延(予定超過。赤い行)になる前に、「このペースだと完了予定に間に合わない」タスクを知らせる。進捗度や実績から出る残りの工数と、完了予定までに積める稼働量を比べ、足りなくなりそうなタスクを `警告` とする。ダッシュボードでは、メンバーごとに警告の件数を見て、抱えすぎを早めに見つけられるようにする。

## 決めたこと(会話で確認済み)

| 項目 | 決定 |
|---|---|
| 判定の測り方 | `残りの工数 ÷ 今から完了予定までの稼働量`(基準の人の時間で測る)。予定どおりなら 100% |
| 基準 | 110% 以上で警告(固定。設定で変えない)。※下の「基準の考え方」を参照 |
| 予定超過との関係 | すでに予定超過(赤)のタスクは警告にしない。赤を優先する |
| 表示先 | ガントチャートの行と名前の欄(赤と同じ場所の背景)・ダッシュボードの `進捗と遅れ`(メンバー別・チーム別の件数)・`期限とマイルストーン` |
| メンバーごとの閾値 | 警告の件数の閾値(`warning_limit`)。警告の件数が閾値以上のメンバーを強調する。空は強調しない。ファイル形式は version 19 |
| 色 | 遅延の赤とは別の色(既定は黄系)。設定で入力でき、全プロジェクト共通(`config.json` の `warning_color`) |
| 状態色 | 変えない(未着手の白抜き・一時停止の濃いグレーは要望 107、色の設定は要望 106) |
| 追加工数 | 後から足せる形にしておく(要望 105)。実装はしない |
| 要望 98 のボタン | `警告を含む` を有効にする。表示の切り替えだけで、保存しない |

## 基準の考え方

このアプリの完了予定は、工数から自動で算出される(`開始予定 + 工数` を稼働の枠に割り当てた日時)。そのため、予定どおりに進んでいるタスクは、完了予定までの稼働量がちょうど工数と同じになり、比は常に 100% になる。最初に考えた「80% 以上で警告」では、予定どおりのタスクが開始の時点から全部警告になってしまう。そこで、100% を超えそうなときを警告にし、日付の切れ目の誤差で出ないように 10% の幅を持たせて 110% とした(既存の `遅延` の許容幅 10 ポイントと同じ感覚)。

- 完了予定を手で指定して余裕を持たせたタスクは、比が 100% より小さいので、余裕を使い切るまで警告にならない。
- 完了予定が工数に対して短すぎるタスク(例: 工数 40h に対し、完了予定までの稼働が 30h)は、開始の前から警告になる。計画自体が足りないことを知らせる。
- 開始予定を過ぎても着手していない(進捗度・実績がない)タスクは、稼働量だけが減るので、比が上がって警告になる。

## 判定

### 対象と除外

対象は、通常タスクで、状態が`終了`でなく、工数があり、完了予定が今より先で、残りの工数が 0 を超えるもの。次は対象外にする(警告にしない)。

- まとめ・チェックポイント・プロジェクト参照(参照先の中のタスクは、そのプロジェクト自身の判定で数える。ダッシュボードの節を参照)
- 工数がない・完了予定が決まらないタスク
- すでに予定超過のタスク(`is_overdue`)

### 計算

```
残りの工数   = 工数(追加工数があれば足す) − 消化分     … 今の _remaining_hours と同じ規則
稼働量       = 開始(今と開始予定の遅いほう)から完了予定までに、担当者の稼働の枠で積める、
                換算率つきの時間の合計(`timeline.work_capacity`)
比           = 残りの工数 ÷ 稼働量
警告         = 比 ≥ 1.10(稼働量が 0 で残りがあるときも警告)
```

- 稼働量は、`calc_end` と同じ枠の扱い(担当者の稼働日の上書き・祝日・イベントの休み・週ごとの担当)で数える。担当者がいなければ通常のカレンダーで換算率 1。
- 開始(稼働量の数え始め)は `max(今, 実効の開始)`。完了予定は、先行の押し出しを反映した実効の完了予定。
- 判定の結果は、残りの工数・稼働量・比を持つ値(`Pace`)にして、表示のホバーが同じ数字を使えるようにする。

### 追加工数への備え

残りの工数の計算で使う工数を、`total_effort(task)` の 1 か所から取る(今は `task.effort_hours` を返す)。要望 105 で追加工数を持たせるときは、ここだけを足す。判定・ダッシュボード・要望 98 の遅れの取り戻しは、すべてこれを通す。

## 残りの工数の計算の移動

`_remaining_hours` と `_open_hours`(いずれも `dashboard.py` の内部)を、独立したモジュール(`remaining.py`。NiceGUI に依存しない純粋関数)に移し、`dashboard.py` とガントチャートの判定の両方から使う。`_open_hours` が使う稼働時間の計算(`_overlap_hours`)の依存は、実装計画で確認して一緒に移す。挙動は変えない(既存のテストがそのまま通る)。

## 表示

### ガントチャートと名前の欄

- 警告のタスクは、予定超過(赤)と同じ場所(タスクの行の背景と、名前の欄の背景)に、警告の色の薄い色(予定超過の赤と同じ濃さ)を重ねる。棒は今までどおり状態色のままで、色は混ざらない。予定超過のタスクには出さない(赤が優先)。
- 名前の欄のホバーに `警告: 残り 12.0h / 稼働 10.0h(120%)` を出す。
- プレビューと画像にも反映する。表示は、予定超過の赤みと同じ表示項目(`予定超過の赤みと割り当て超過の縞`)に従う。
- PlantUML には出さない。

### 色の設定

- テーマのメニューに `警告の色…` を足す(今日の線の色と同じ形の小さなダイアログ。`#RRGGBB` の入力欄と色の選択。空欄は既定の色)。色を変えるとすぐ画面に反映し、`適用` で保存、`キャンセル`・ESC・外側クリックで保存済みの色に戻す。`既定に戻す` は入力欄を空にする。不正な値は入力欄にエラーを出して `適用` を押せなくする。
- 保存先は `~/.projectapp/config.json` の `warning_color`(全プロジェクト共通。ライト・ダークで同じ色)。元に戻す・やり直しの対象にしない。
- 既定の色は黄系にする。具体的な値は、実装のとき、`dataviz` のバリデータで、予定超過の赤・状態色(特に一時停止の橙)と比べて決める。

## ダッシュボード

### `進捗と遅れ`

- 状態別の件数の行(`未着手 4 実行中 1 一時停止 0 終了 1`)に、状態とは別に `警告 n` を足す。
- `メンバー別`・`チーム別` の各行に `警告 3 件` を足す。件数は、そのメンバー(チーム)の担当に入っているタスクの数で、共同タスクは担当者それぞれの行に 1 件ずつ数える(進捗の件数と同じ数え方)。担当がメンバーでないタスク・担当なしは `未割り当て` に数える。期間には影響されない。
- メンバー別の行は、そのメンバーの閾値(`warning_limit`)があり、警告の件数が閾値以上のとき、`警告 3 件` を警告の色で強調する(アイコンつき)。閾値がないメンバー、チーム別の行は強調しない。
- メンバー・チームの絞り込みに従う(共同タスクは丸ごと数える)。
- 参照行の参照先の通常タスクも、開いているプロジェクトのタスクと同列に数える(要望 90 と同じ規則)。判定は、参照先自身の稼働設定・祝日・イベントで行う。

### `期限とマイルストーン`

- 警告のタスクの行(`締切`・`完了予定` のどちらも)を、警告の色にして `警告` と添える。予定超過の行(赤)はそのまま。期間の絞り込み・メンバーの絞り込みの規則は今までどおり。

### メンバーの閾値の設定

- `プロジェクト` メニューの `メンバーとパラメータ` のメンバーの表に `警告の件数` の列を足す(整数 1〜999。空は閾値なし)。適用はタブごとで、今までのメンバーの列と同じ。

## ファイル形式(version 19)

- メンバーに `warning_limit`(整数 1〜999 または `null`)を足す。version は 18 → 19。キーのない古いファイルは `null` で読み(移行を要らなくする)、整数でない値・範囲外・真偽値は読込を拒否する。
- 3 者マージ(`merge.py`): メンバーのほかの値と同じく、`warning_limit` を 1 項目として比べる。
- 設定のエクスポート・インポート(要望 78): メンバーの項目に含め、インポートで上書きできる。子プロジェクトへの切り出し(要望 89)は、引き継ぐメンバーに含まれる。
- 元に戻す・やり直しの対象(メンバーの適用と同じ)。

## 要望 98 の `警告を含む` ボタン

- ボタンを有効にして、`遅延のみ`(今までの遅れ。予定超過)と `警告を含む`(予定超過と警告)を切り替えられるようにする。切り替えると、ダッシュボードの `残りの工数と必要人数` を集計し直す。
- 切り替えは表示だけで、保存しない(ダッシュボードを開いている間だけ有効。開き直すと `遅延のみ`)。ビューには入れない。
- `警告を含む` のとき、遅れの見出しは `うち遅延・警告 5 件・38.0h` になり、`遅れがなければ` の比較も、警告のタスクを除いた不足を示す。警告のタスクは、予定超過のタスクと同じく、残りの工数の全量を数える(見込み超過分だけではない)。
- 遅れの判定は、`_is_late` に `LateBasis`(`遅延のみ`・`警告を含む`)を渡す形にする。

## テスト

- 判定: 予定どおり(比 100%)は警告にならない。110% 以上で警告。完了予定を手で指定して余裕があるものは警告にならない。稼働量が 0 で残りがあるときは警告。予定超過・終了・まとめ・節目・参照行・工数なしは警告にしない。着手が遅れたタスクが警告になる。週ごとの担当・稼働日の上書き・祝日・担当なしで、稼働量が `calc_end` と整合する。
- 残りの工数の移動: 既存のテストがそのまま通る。`total_effort` が工数を返す。
- 稼働量: 稼働の枠・休み・複数の担当者の重なり・週ごとの担当で、`calc_end` の消化と同じ枠を数える(工数ちょうどの稼働量で、終了が完了予定に一致する)。
- ガントチャート: 警告の行・名前の欄の背景、ホバーの文字、予定超過との優先、表示項目のオフ、プレビュー・画像。
- 色の設定: 読み込み・保存・不正値・既定に戻す・キャンセル(今日の線の色のテストと同じ形)。
- ダッシュボード: 件数(共同タスク・担当なし・参照先・絞り込み)、閾値での強調、`期限とマイルストーン` の行。
- ファイル形式: version 19 の読み書き、古いファイルの既定、不正値の拒否、マージ、設定のエクスポート・インポート。
- 要望 98: ボタンの有効化、切り替えでの再集計、保存されないこと。
