# 日ごとの担当: 遅れを取り戻すとき、翌日から増員できるようにする(要望 135)設計書

> 日付: 2026-11-08 / ブランチ: `feature/daily-crew` / 関連: 要望 132(増員の試算。`crew_trial.py`)・133(完了見込み。`forecast.py`)・134(警告のタスクへの増員)

## 1. 目的と範囲

担当を変えられる最小単位は週(`週ごとに分ける`。開始から 7 日ごと)で、増員日は週頭に遅い側へ丸めている。遅れに気づいた日に決めても、増員が効くのは来週頭になる。**翌日から**人を足せるようにする。

決めたこと:
- 担当を**日ごとに分けられる**ようにする。範囲は、**週ごとの担当のうち、選んだ 1 週だけ**(週ごとのタスクの、定義済みの週の中)。全期間を日ごとにはしない。
- 遅延対応(132・133・134)の増員は、増員日を**丸めず日付のまま**使い、増員日を含む週**だけ**を自動で日ごとにする。
- `日ごとに分ける`の表示は、`週ごとに分ける`の表示と**区別がつく**ようにする。
- 日の位置は、暦日の差(`timedelta`)だけで数える。月・年・閏年で場合分けしない。

範囲外: 全期間の日ごとの編集、右クリックメニューからの日ごとの入口、時間単位の担当、週をまたぐ日ごとの範囲指定。

## 2. データ

`Task.daily_crew: dict[int, list[list[Assignee]]]`(週の添字 → その週の 7 日ぶんの担当)。

- 週の起点は `weekly_crew` と同じ(実効の開始の日から 7 日ごと)。添字は 0 始まり。
- 添字は、`weekly_crew` の定義済みの週(`0 <= k < len(weekly_crew)`)だけ。各日の担当は 1 人以上、長さはちょうど 7。
- 日ごとの週でも、`weekly_crew[k]` にはその週の担当の**和集合**を残す。`assignees` の和集合・ダッシュボードの担当表示など、週を前提にした既存の読み手が壊れない。計算だけが `daily_crew[k]` を優先する。
- 最後の週が日ごとのとき、その 7 日目の担当が以降も続く。
- ファイル形式: `version` を 21 から **22** に上げる。キーのない古いファイルは `daily_crew = {}` として読む。不正(範囲外の添字・7 日でない・担当のいない日・メンバーにいない人)は拒否し、新しい `version` も拒否する。保存は一時ファイル経由(既存のとおり)。

## 3. 計算(`timeline.py`)

- 今の `calc_end`・`consumed_slices`・`work_capacity`・`crew_pieces` は、週の添字を「開始からの日数 ÷ 7」で引く。これを**日の添字**で引くように一般化する。週はそのまま 7 日分の同じ担当、日ごとの週は 7 つの別の担当に展開する。
- 展開は 1 か所の関数(`weekly_crews` を日ごとの展開を返す形に拡張)にまとめ、`pace`・`forecast`・`crew_trial`・`handoff`・`dashboard` は同じ展開を使う。
- `daily_crew` が空のタスクは、展開しても今までと同じ並びになる(**結果が従来と一致**することをテストで保証する)。
- 133 の `weeks_start`(週の区切りの起点)は、そのまま日の添字の起点として使う。
- 担当者個人の稼働日の上書き(`Member.work_days`)・祝日・イベントの休みは、今の稼働の枠の扱いのまま。日ごとの週でも、その人の休みの日は稼働量 0。

## 4. 遅延対応との接続(132・133・134)

増員日 `d`(日付)を、丸めずに使う。`k = (d − 週の起点) の日数 // 7`、`j = (d − 週の起点) の日数 % 7`。

- `k − 1` 週目以前: 変えない(過去の棒は縮まない)。
- `k` 週目: `j = 0` なら**日ごとにせず**、週の担当に増員を足すだけ。`j ≥ 1` なら日ごとの週にし、`j` 日目より前は元の担当、`j` 日目以降は元の担当+増員。
- `k + 1` 週目以降: 元の担当+増員(今の引き継ぎと同じ)。
- 定義済みの最後の週より先なら、直前の週のコピーで間を埋める(今と同じ。52 週を超えるなら拒否)。
- 週ごとの担当のないタスクを確定するときは、実効の開始から数える週に変換する。

入口ごとの既定の増員日は**翌日**(今日の翌暦日):
- 134(ダッシュボードの警告のタスクに足す): 翌日(今の「次の週頭」から変える)。
- 132 の`増員を試す…`: 日付欄の既定を翌日にし、丸めの説明文をなくす。
- 132 の`ガントチャートで試す`(投入候補): 翌日。

133 の `forecast_end(extra_crew=(名前の列, 増員日))` は日付をそのまま受ける。`snap_week` は「週と週内の日の位置を返す関数」に置き換える。試算と確定後の見込みが同じ日になる(133 の「週の数え方で数日ずれる」限界が解消する)。

132・133・134 の「増員日は週頭へ遅い側に丸める」は廃止する。増員日が週頭でないケースで、132 のテストの期待値が変わる(意図した変更)。

休み: 増員日が、増員する人の個人の休みや、プロジェクトの休み(土日祝・イベント)に当たるときも、増員日は変えない(増員日を含む週は日ごとになる)。効き始めは、その人の次の稼働日になる。134 と 132 のダイアログに、`この人は m/d まで休みです(効き始めは m/d)` を出すが、確定は止めない。

## 5. 画面

- 入口: ガントの棒の週チップを押すと開く`週の担当`ダイアログに、`日ごとに分ける`を足す。押すと、その週の担当を 7 日すべてにコピーして日ごとの週にする。日ごとの週のダイアログは、日付と曜日つき(`11/23(月)`)の 7 行で、各行の担当を直せる。`週ごとに戻す`は、その週の 1 日目の担当を週の担当にする。右クリックの`週ごとに分ける / 週ごとをやめる`は変えない。
- 編集は、元に戻せる 1 回の編集。保存時の割り当て超過の通知は今の週ごとと同じ。
- 表示の区別: 週チップは 7 日ぶんの幅に 1 つ。日ごとの週は、その 7 日ぶんの幅を**1 日ずつの細いチップ 7 つ**に分け、週チップと色味を変える(2 つ目の色の縁取り)。隣の日と担当が同じでも、縦の細い区切りで日ごとだとわかる。幅が足りないときは頭文字だけ。
- ホバー: 週は`第3週 11/16〜11/22`、日ごとは`第3週 11/23(月)`。増員の目印(`week-added`)は日ごとのチップにも同じ判定で付ける。
- 下部パネルの`担当`の行: 日ごとの週があるとき`日ごとの週あり`を足す。

## 7. テスト

既存の週ごとのテストは、増員日が週頭でないもの(132 の期待値)を除き、期待値を変えない。

1. **互換**: `daily_crew` が空なら、完了予定・稼働量・区間・見込みが従来と完全一致。
2. **等価**: 7 日とも週と同じ担当の日ごとの週は、週のままと同じ結果。
3. **日ごとの効き方**: 週の途中から人が増える・外れる。最後の週が日ごとのとき 7 日目の担当が続く。
4. **増員日の位置**: 週の途中・週の 1 日目(日ごとにしない)・定義済みの週より先・過去の週が不変。
5. **翌日と休み**: 今日が金曜の翌日=土曜、土日祝を空けて次の稼働日から効く。
6. **年末年始**: イベント(2026/12/28〜2027/01/03)が休みのとき。今日が 12/25(金)・12/27(日)・12/28(イベント初日)で翌日が休みに入る場合。日ごとの週が 12/28〜1/3、12/30〜1/5 のように年をまたぐ場合。効き始めが 1/4(月)以降。134 の既定・132 の既定・完了見込みが同じ日を指す。
7. **閏年の有無で 2月から 3月**: 2028(閏年)の 2/28 の翌日=2/29、2/29 の翌日=3/1。2027(平年)の 2/28(日)の翌日=3/1(月)。日ごとの週が 2月末〜3月初めをまたぐ(週の起点が 2/26 など)。週の添字が閏日の有無に関わらず暦日の差で一貫する。
8. **一致**: 増員日が週の途中でも、確定後の完了見込み = 試算(6・7 の日付でも)。
9. **増員する人の非稼働日**: 増員日が増員する人の個人の休みに当たる(その日は稼働量 0、他のメンバーは影響なし)。翌日が休みで次の日から稼働(効き始めがその人の次の稼働日、見込みと試算が同じ日)。休みが連続する(イベント+個人の休み 1/4 → 効き始めは 1/5 以降)。週の途中で休みから戻る。全員が休みの日は工数が進まない。個人だけ稼働にした休日(土日など)に増員分が効く。休みの日付が 2/29・12/31〜1/1 でも同じ。
10. **ファイル**: v22 の往復、v21 の読み込み、不正値の拒否(範囲外の添字・7 日でない・担当のいない日・メンバーにいない人)、新しい`version`の拒否。
11. **画面**: 日ごとのチップが週チップと見分けられる。ダイアログの日付と曜日。1 回の Undo で戻る。休みの確認の一文。
12. **マージ・一括編集・分解**: 上の表の振る舞い。
13. **性能**: 300 タスクの見込みが 0.1 秒未満(今のまま)。

## 8. 守ること

- 当初の完了予定の意味(開始日から全工数)・予定超過・警告の判定式は変えない。
- 見込みと試算は保存しない。確定したときだけ`weekly_crew`と`daily_crew`に書く。
- 見込みは、残りの工数を今の担当が並行して進める前提の算術で、予測ではない(立ち上がりの遅れ・休みの予定外の変更は見ない)。
