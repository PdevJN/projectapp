# プロジェクトの格納先を指定する 設計書

要望 8(2026-10-04〜05 に受領)。要望 10(git / GitHub 連携)の最初の子の作業。

## 目的

プロジェクトファイル(`<名前>.json`)の置き場所を、`~/.projectapp` 以外のフォルダに変えられるようにする。要望 10 では、複数人が同じ git リポジトリでプロジェクトファイルを共有する。各自が `clone` した作業ツリーを格納先に指定できるようにするのが、直接の動機。

## 背景

今の `base_dir`(`~/.projectapp`)は、次の二役を兼ねている。

- プロジェクトの JSON の置き場所(`storage.py`、`views.py`)
- アプリの設定の置き場所(`config.json`: テーマ・倍率・名前の欄の幅・レイアウト。`holidays.json`: 祝日のキャッシュ)

格納先を共有リポジトリに向けると、設定が一緒にリポジトリへ入り、各自のテーマや倍率がコミットで互いに上書きされる。また、格納先を覚える場所が、格納先の中になってしまう。

## 範囲

**含む**:
- 設定の置き場所(`~/.projectapp`)と、プロジェクトの格納先(`project_dir`)の分離
- `config.json` の `project_dir`(未設定なら `~/.projectapp`)
- ファイルメニューの「格納先を変更」(OS のフォルダ選択。ネイティブウィンドウのみ)
- 格納先の検査(`check_project_dir`)
- 起動時に格納先が使えないときの、既定の場所へのフォールバック
- プロジェクト格納フォルダを開くボタンを、新しい格納先に追従させること
- 仕様(`CLAUDE.md`)と `docs/development.md` の更新

**含まない**:
- ヘッダーへの格納先の表示
- 格納先の履歴・複数の格納先の登録
- プロジェクトファイルの移動・コピー(古い格納先のファイルは、そのまま残す)
- パスの手入力
- git に関する機能(要望 10 の、後続の子の作業)

## 決定事項(確認済み)

- **設定は固定、プロジェクトだけ移す**。`~/.projectapp` は設定の置き場所のままで、`config.json` と `holidays.json` はここに残す。格納先を変えても、各自の設定は保たれる。リポジトリには、プロジェクトの JSON だけが入る。既存の利用者は、何も変わらない。
- **入口は、ファイルメニューの「格納先を変更」**。設定ダイアログ(プロジェクトごとの設定)には入れない。格納先は全プロジェクト共通のため。
- **変更前に検査して、拒否する**。空のフォルダは許可する(新規プロジェクトの保存先になる)。
- **起動時に使えない格納先は、通知して既定の場所で起動する。設定は書き換えない**。ドライブをつなぎ直して再起動すれば、元に戻る。

## 設計

### 設定(`config.py`)

- `config.json` に `project_dir`(絶対パスの文字列)を足す。未設定・空・文字列でない値は「未設定」として読む。
- `load_project_dir(base_dir) -> Path | None` と `save_project_dir(path, base_dir)`。ほかの設定と同じく、`update_config` で一時ファイル経由で書き、ほかのキーを消さない。`~` は展開して読む。
- `check_project_dir(path: Path) -> str | None`(純粋に近い関数。エラー文を返し、問題がなければ `None`):
  - 存在しない: 「フォルダが見つかりません」
  - フォルダでない: 「フォルダではありません」
  - 書き込めない(`os.access(path, os.W_OK | os.X_OK)` が偽): 「書き込めません」
  - 空のフォルダ、プロジェクトの JSON がないフォルダは許可する。
  - 既存のファイルには触れない。確認は `os.access` だけで、ファイルを作らない。

### `MainView` の二役の分離(`views.py`)

- コンストラクタの `base_dir` は、設定側のままにする(既存のテストの呼び出しを変えない)。
- 新しく `project_dir: Path | None = None` を受ける。決め方:
  1. 引数があれば、それを使う。
  2. なければ `load_project_dir(base_dir)` を試し、`check_project_dir` に通れば使う。通らなければ、通知して `base_dir` を使う(設定は書き換えない)。
  3. 未設定なら `base_dir`。
- 設定側(`base_dir`)を使い続けるもの: `load_*` / `save_*`(テーマ・倍率・幅・レイアウト)、`load_cache` / `download_holidays`。
- 格納先(`project_dir`)を使うもの: `list_project_files`、`validate_name`、`save_project`、フォルダを開くボタン(`open_folder`)。
- `storage.py` の `BASE_DIR` の既定値は、設定の置き場所の意味で残す。`storage.py` の関数は、引数のディレクトリをプロジェクトの格納先として扱うので、変えない。

### 格納先を変更する操作

- ファイルメニューに「格納先を変更」(マーカー `file-change-dir`、アイコン `drive_file_move` など)を、「祝日を更新」の前に足す。ネイティブウィンドウ以外では、押すと通知する(PNG の保存と同じ扱い)。
- 流れ:
  1. 編集中なら、`open_unsaved_dialog` で「保存して変更・保存せず変更・キャンセル」を聞く。
  2. OS のフォルダ選択を開く。キャンセルなら何もしない。フォルダ選択は、`ImageExporter.ask_path` と並ぶ形で、ネイティブの機能を 1 か所に集める。
  3. `check_project_dir` に落ちたら、変更せずに理由を通知する。
  4. 通ったら、`save_project_dir` で保存し、`project_dir` を更新して `files` を走査し直し、保存前の新規プロジェクトを表示する(`new_project` と共通の経路)。
  5. 選んだフォルダが、現在と同じなら、何もしない。
- ショートカットは足さない。

### 起動時

- 保存した `project_dir` が使えない(存在しない・書き込めない)ときは、「格納先が見つからないため、既定の場所を使っています」を通知し、`~/.projectapp` で起動する。`config.json` の `project_dir` は、そのまま残す。
- その間に保存したファイルは、既定の場所に作られる(再起動で元の格納先に戻ると、見えなくなる)。これは、一時的な不在のときの、許容した動作。

### ドキュメント

- `CLAUDE.md`: 「プロジェクトファイル」の節の `~/.projectapp/プロジェクトの名前.json` を「格納先(既定は `~/.projectapp`)」に改め、「データの保存先」と「ヘッダー」(`ファイル`メニュー、フォルダを開くボタン)を更新する。
- `docs/development.md`: 設定の置き場所と格納先が別であること、`project_dir` の読み方を追記する。

## テスト

- `config`: `project_dir` の読み書き、ほかのキーを消さないこと、不正な値は未設定として読むこと。
- `check_project_dir`: 存在しない・ファイル・書き込めない・空のフォルダ・通常のフォルダ。
- `MainView`: 格納先を指定すると、ファイル一覧・保存・名前の検査がそのフォルダになり、`config.json` と `holidays.json` は設定側に残ること。
- 変更の操作: 成功(一覧が読み直され、新規プロジェクトになる)、検査に落ちる(変更されない)、編集中の三択、キャンセル、同じフォルダ。
- 起動時のフォールバック: 通知が出ること、設定が書き換わらないこと。
- フォルダを開くボタンが、格納先を開くこと。
- 既存のテストが、変更なしで通ること。

## 未確認・リスク

- フォルダ選択ダイアログ(`pywebview` のフォルダ選択)の、ネイティブでの動作は、実機で確認する。
- 書き込めるかの検査を `os.access` だけにしたため、ネットワークドライブや iCloud の一部の状態では、検査を通っても保存に失敗しうる。そのときは、これまでどおり保存の失敗として通知する。
