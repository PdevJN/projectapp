# 追加工数の設計

> **状態**: 設計(2026-11-02。要望 105)。利用者の承認はチャットの設計案まで。この設計書のレビュー待ち。

## 目的

作業を進めるうちに、見積もりに入っていなかった作業が見つかることがある。そのとき、タスクの工数を直接書き換えずに、`追加工数`として後から足せるようにする。もとの見積もりと追加分の区別を残し、いつ・何時間・なぜ足したかが後から分かるようにする。

## 決めたこと(会話で確認済み)

| 項目 | 決定 |
|---|---|
| 進捗度との関係 | 足したとき、消化時間を保って進捗度を再計算する(工数 10h・50%〔消化 5h〕に 5h を足すと、15h・33%) |
| 持ち方 | 履歴のリスト(`id`・日付・時間・理由)。合計 = もとの見積もり + 追加の合計 |
| 入口 | 右クリックの`追加工数を足す…`(小ダイアログ)と、編集ダイアログの`追加工数`の節(履歴の修正・削除) |
| 完了予定 | 自動算出のタスクは、合計工数で算出して延びる。手で指定した完了予定は変えない |
| ファイル形式 | `version` を 19 から 20 に上げる。キーのない古いファイルは、追加なしで読む |

## データ

- `models.ExtraEffort(id, date, hours, reason)` を足す。`id` は 3 者マージで同じ項目を突き合わせるための、タスクの`id`と同じ形の短い文字列。`date` は`date`、`hours` は 0 より大きい有限の数、`reason` は空でもよい文字列。
- `Task.extra_efforts: list[ExtraEffort]`(既定は空)と、`Task.total_effort`(= `effort_hours + Σ hours`)を足す。`effort_hours` は書き換えず、`もとの見積もり`として残す。
- `remaining.total_effort(task)` は`task.total_effort`を返す。残りの工数・警告・ダッシュボード・遅れの取り戻し(要望 98・104)は、すでにここを通っているので、追加分が自動で反映される。
- 保存: タスクの項目`extra_efforts`(各要素は`id`・`date`〔ISO 形式〕・`hours`・`reason`)。不正な値は拒否する(`hours` が 0 以下・有限でない・数値でない、`date` が日付でない、`id` の重複)。`version` が 20 未満のファイルは、キーがなければ空として読む。新しい`version`は今までどおり拒否する。
- 通常タスク以外(まとめ・節目・プロジェクト参照)には持たない(空のまま)。

## 計算

- 完了予定の算出は、`timeline.py` の `effort_hours` の参照(開始からの稼働の積み上げ、`effort_days`、完了予定の算出、`handoff.py` の担当者向けの換算)を、合計工数に替える。自動算出のタスクは追加分だけ延び、手で指定したタスクは変わらず、算出値の参考表示(要望 34)に追加分が出る。
- 進捗度の再計算: 足すときだけ、`round(旧進捗度 × 旧合計 ÷ 新合計)` に直す(0〜100 に収める)。進捗度が未設定なら触らない。実績から消化分を数えるタスク(進捗度なし)は、実績が変わらないので、そのまま。
- 履歴の修正・削除では、進捗度を再計算しない。進捗度の再計算は、足す操作のときだけ。
- 担当の付け替えの見直し(`reassign.py`)と実績のあるタスクの分解は、合計工数を使う。

## 画面

- **右クリック** `追加工数を足す…`(通常タスクの行・棒だけ)→ 小ダイアログ。入力は`時間`(必須。0 より大きい)と`理由`(任意)。日付は画面の「今」(`MainView.now`。`FAKE_NOW`で指定できる)の日付。
  - 進捗度が変わるときは、`進捗度 50% → 33%` をダイアログに出す。
  - 実行すると、追加の記録と進捗度の再計算を、元に戻す 1 ステップにする(`save_task` 経由)。
- **編集ダイアログ**に`追加工数`の節を足す(要望 62 の折りたたみの流儀に合わせる)。`もとの見積もり`・`追加の合計`・`合計`と、履歴の表(日付・時間・理由。行の修正と削除)を出す。工数の欄が`もとの見積もり`であることを、ラベルで示す。
- **下部パネルの詳細**: 追加があるときだけ、`工数 15h(もと 10h + 追加 5h)` と出す。
- 一括編集の工数の増減(倍率は要望 83)は、`effort_hours`(もとの見積もり)を直す。追加分は変えない。

## 周辺

- **3 者マージ**: `extra_efforts` を`id`ごとにマージする(追加・削除・同じ項目の変更を、タスクの`id`のマージと同じ流儀で)。同じ項目の衝突は画面で選ぶ。
- **分解**: 親の合計工数を子に分ける。子は追加なし。元のタスクの履歴は、親(まとめ)に残さない(まとめは工数を持たない)。
- **書き出し**: 担当者向けファイル・PlantUML・CSV/TSV は合計工数で出す。履歴は出さない。取り込みは、追加なしのまま。
- **設定ファイル**(プロジェクトの設定値の書き出し)は、タスクを含まないので影響なし。
- **PlantUML の取り込み**: 追加なし。

## 範囲外(やらない)

- ダッシュボードの、もとの見積もりとの差のカード(後から足せる形のまま)。
- 追加工数の PlantUML・CSV への出力と取り込み。
- 履歴の修正・削除に伴う進捗度の自動再計算。

## テスト

- 計算: 合計工数の算出、進捗度の再計算(端数・0%・100%・未設定)、完了予定が追加分だけ延びること(自動算出)と変わらないこと(手で指定)、警告・残りの工数・ダッシュボードに反映されること。
- 保存: 往復、`version` 19 のファイルの読み込み(キーなし)、不正な値の拒否。
- マージ: 双方が別々に足した場合、同じ項目を別々に直した場合(衝突)、片方が削除した場合。
- 画面: 右クリックのダイアログ(進捗度の変化の表示、元に戻す 1 ステップ)、編集ダイアログの節。
- 周辺: 分解、書き出し(合計工数)、担当者向けファイル。

## 実装上の決め(設計書の確認で固定)

- 追加の日付は、画面の「今」(`MainView.now`)の日付にする。テストと実機確認で日付を指定できる。
- 編集ダイアログの`工数`の欄のラベルは変えない。追加があるときだけ、欄の下に`もとの見積もり。追加 +5h で合計 15h`の補足を出す。
