# 進捗率に応じたバーの表現 設計書

## 目的

進捗度(要望1)と予定の経過を比べ、ガントチャートの棒で「通常・遅延・前倒し・完了・遅延完了」を見分けられるようにする。`.claude/MEMORY.md` の要望14に対応する。

- 進捗率に応じたバーの表現: 通常、遅延時、前倒し時、完了時、遅延完了時で、バーの見た目を変える。

進捗度(`2026-10-04-progress-design.md`)の続き。色・模様の使い分けは、予定超過の行の赤い背景、割り当て超過の縞、タスクの色との競合に注意する。

## 範囲

**含む**: 進捗の状態(5 つ)の判定、予定の棒の進捗の塗り分け、状態を示す枠線と印、ツールチップ。

**含まない**:
- 状態(開始・実行中・一時停止・終了)別のバーの色(要望12)。タスクの色は変えない。
- 許容幅を変える設定画面
- 稼働時間・祝日を考慮した「進んでいるはずの割合」の計算
- プロジェクト全体の集計(要望6)
- データ・保存形式の変更(`Task`・`Actual` は変えない)

## 決定事項

- 状態は `ProgressState`(`NORMAL`・`DELAYED`・`AHEAD`・`DONE`・`LATE_DONE`)。判定できないときは `None`で、棒は今のまま(塗り分けも枠線も印も出さない)。
- 表現は、予定の棒の中に、進捗度の塗り分け、状態を示す枠線、右の印で表す。実績の棒(下半分)・縞・赤い行の背景・◆(締切)・タスクの色は変えない。
- 「進んでいるはずの割合」は暦の時間で計算する(稼働時間・祝日は見ない)。単純さを優先し、週末をまたぐ棒では、休日の分だけ遅延寄り・前倒し寄りにぶれる。許容幅で吸収する。
- 許容幅は定数 `PROGRESS_TOLERANCE = 10`(パーセントポイント)。設定画面は作らない。
- 状態が「終了」なら、進捗度の入力に関係なく `DONE` か `LATE_DONE`。遅延完了かどうかは `is_overdue` の結果を使う(実績の終了が完了予定か締切を過ぎたもの)。
- 赤は予定超過の背景と競合するため、枠線には使わない。橙は ◆(締切)と競合するため使わない。

## 判定(`timeline.py`)

```python
class ProgressState(StrEnum):
    NORMAL = "通常"
    DELAYED = "遅延"
    AHEAD = "前倒し"
    DONE = "完了"
    LATE_DONE = "遅延完了"

PROGRESS_TOLERANCE = 10  # 進んでいるはずの割合との差の許容幅(パーセントポイント)

def expected_progress(start: datetime, end: datetime, now: datetime) -> float:
    """現在時刻までに進んでいるはずの割合(0〜100)。暦の時間で、開始〜完了予定の経過割合。"""

def progress_state(
    task: Task, project: Project, holidays: dict[date, str], now: datetime
) -> ProgressState | None: ...
```

`expected_progress`:
- `end > start` のとき、`(now − start) ÷ (end − start) × 100` を 0〜100 に丸める。
- `end <= start`(長さ 0 以下)のとき、`now >= end` なら 100、そうでなければ 0。

`progress_state`:

| 順 | 条件 | 結果 |
|---|---|---|
| 1 | 状態が「終了」かつ `is_overdue` が偽 | `DONE` |
| 2 | 状態が「終了」かつ `is_overdue` が真 | `LATE_DONE` |
| 3 | 進捗度(`current_progress`)・開始予定・完了予定(`effective_end`)のどれかがない | `None` |
| 4 | 進捗度 < 進んでいるはずの割合 − `PROGRESS_TOLERANCE` | `DELAYED` |
| 5 | 進捗度 > 進んでいるはずの割合 + `PROGRESS_TOLERANCE` | `AHEAD` |
| 6 | それ以外 | `NORMAL` |

- 4・5 の境界(ちょうど許容幅の差)は、`NORMAL` に含める(不等号は厳密)。
- 開始予定より前(`now < start`)は、進んでいるはずの割合が 0 になるので、進捗度が 10 を超えると `AHEAD`、10 以下は `NORMAL`。
- 状態が「終了」でないタスクの、進捗度 0 は「入力あり」として判定に使う(`is not None`)。

## 表現(`gantt.py`)

### 進捗の塗り分け

- 予定の棒の内側に、左端から進捗度の割合の幅で、タスクの色(不透明)を塗る。残りは、今の半透明のまま。
- 塗りの割合: `current_progress`。状態が「終了」で進捗度が空のときは 100。それ以外で進捗度がないとき(`None`)は塗らない。
- 塗りは棒の全高。縞(`overload_stripes`)は塗りの上に重ね、実績の棒(下半分)は塗りの手前に出す(今の重なりのまま)。
- 塗りは `pointer-events: none`。棒のクリック・ドラッグを妨げない。
- マーク: `progress-fill-{key}-{ti}`。

### 枠線

予定の棒に、内側 2px の枠線(`outline: 2px solid <色>; outline-offset: -2px`)を付ける。

| 状態 | 枠線の色 |
|---|---|
| `DELAYED` | `#b26a00`(琥珀) |
| `AHEAD` | `#00897b`(青緑) |
| `DONE` | `#757575`(灰) |
| `LATE_DONE` | `#8e24aa`(紫) |
| `NORMAL` / `None` | なし |

色は定数 `PROGRESS_STATE_COLORS` にまとめる。

### 印

棒の右端の外側(右に 4px)に、小さな文字の印を出す。`NORMAL` と `None` は出さない。

| 状態 | 印 |
|---|---|
| `DELAYED` | `▼` |
| `AHEAD` | `▲` |
| `DONE` | `✓` |
| `LATE_DONE` | `✓!` |

- 文字の色は枠線と同じ。ツールチップを出すため、マウスを受ける(`pointer-events` は指定しない)。棒の外にある小さな要素なので、棒のクリック・ドラッグは妨げない。
- ツールチップは「遅延(進捗 30% / 予定 60%)」の形。完了・遅延完了は「完了」「遅延完了」だけ。進捗度が空の完了は、進捗の部分を省く。
- マーク: `progress-state-{key}-{ti}`。

### 棒がないとき

予定の棒がない(開始予定または完了予定がない)タスクは、塗り分け・枠線・印のいずれも出さない。実績の棒だけがあるタスクは、今のまま。

## 既存機能との関係

- 赤い行の背景(`is_overdue`)は変えない。「遅延完了」は赤い背景のまま、棒に紫の枠線と `✓!` が付く。
- 割り当て超過の縞は、塗りの上に残る。
- ドラッグでの横移動、絞り込み、スケールの切り替えは、棒の位置計算を使う今のまま。塗りと印は棒の子要素(印は同じ行の絶対配置)で、位置は棒に従う。
- 予定の棒の半透明(`planned_background`)は、塗りの背面でそのまま使う。

## エラー処理

判定は純粋関数で、例外を出さない。進捗度が 0〜100 の範囲外の値(手編集のファイル)は、読込時に弾かれる(進捗度の設計書どおり)。

## テスト

- `expected_progress`: 区間の前・途中・後、長さ 0 で前・後。
- `progress_state`: 終了(間に合った・遅れた・実績の終了なし)、進捗度なし、開始予定なし、完了予定なし、遅延、前倒し、通常、ちょうど許容幅の差(`NORMAL`)、許容幅を 1 超えた差(`DELAYED` / `AHEAD`)、開始予定より前で進捗度が 10 以下・11 以上、進捗度 0。
- `gantt`: 塗りの幅(進捗度の割合)、進捗度 0 で塗りが 0 幅、終了で進捗度が空のとき 100%、進捗度なしで塗りがない、各状態の枠線の色、印と文字、`NORMAL` と `None` で印がない、予定の棒がないとき何も出ない、塗りと印が `pointer-events: none`、縞が塗りと共存すること。

## 影響するファイル

- `timeline.py`: `ProgressState`、`PROGRESS_TOLERANCE`、`expected_progress`、`progress_state`
- `gantt.py`: 塗り、枠線、印、定数 `PROGRESS_STATE_COLORS`
- `docs/development.md`: 進捗の状態の判定と、暦の時間で計算すること
