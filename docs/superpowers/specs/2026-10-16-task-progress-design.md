# タスクの進捗度 設計書

2026-10-16。architectural。ブランチ `feature/task-progress`。要望 38。

## 背景と目的

進捗度は、実績の区間(`Actual.progress`。区間の終わり時点の累積)にしか置けない。そのため、実績を持たない取り込み(要望 37 の PlantUML)は進捗度を入れられず、状態だけを決めて捨てていた。実績を作ると、実際に作業していないのに作業した記録になる。

目的は、**進捗度を、実績の区間に紐づけずに、タスクそのものの値として持てるようにすること**。成功の基準は次の 2 つ。

- 実績のない取り込みや手入力でも、進捗度を保てる。
- 既存のファイルと、区間に進捗度を入れる今の使い方が壊れない。

## 決定事項

- `Task.progress: int | None`(0〜100。`None` は未入力)を新設する。
- 実績の区間の進捗度との関係は、**区間を優先、なければタスクの値**。区間の進捗度は今のまま(廃止しない)。
- 編集ダイアログに入力欄を足す。区間に進捗度があるときは、読み取り専用で区間の値を示す。
- 状態と進捗度は連動させない(100% でも状態は変えない)。
- チェックポイントは、進捗度を持たない。
- PlantUML の取り込みは、`is N% completed` の N(1〜100)を `Task.progress` に入れる。0 は入れない(`None` のまま)。

## データとファイル形式

- `models.Task` に `progress: int | None = None` を足す。
- ファイル形式は version 5。保存は `"progress"`(整数か `null`)。キーのない古いファイル(version 4 以下)は `None` として読む。
- 読込(`storage`)は、整数で 0〜100 のみ受け付ける。範囲外・整数以外・真偽値は `ValueError` で拒否する(区間の進捗度の検証と同じ規則)。`progress` のキーは version 5 以上でだけ読む(`events` と同じ。version 4 以下の同名のキーは無視する)。チェックポイントは、使わない項目を空にする既存の規則(`_checkpoint`)に合わせて、`progress` を `None` にして読む(拒否はしない)。
- `FORMAT_VERSION` を 5 にする。このアプリより新しい version を拒否する既存の規則は変えない。
- `CLAUDE.md` の「実装上の注意」(現在 4)を 5 に直す。

## 現在の進捗度

`timeline.current_progress(task)` を差し替える。

1. 進捗度の入っている最後の区間の値(0 は入力ありとして返す)。
2. なければ `Task.progress`。
3. どちらもなければ `None`。

塗り・チップ・進捗の状態(遅れの判定)・ダッシュボードの進捗率・PlantUML 出力(`is N% completed`)は、すべてこの関数を通すので、他は変えない。`終了` のタスクをダッシュボードで 100% と数える既存の規則も変えない。

## 編集ダイアログ

- レイアウト `予定・実績` に、`進捗度`の欄(0〜100 の整数)を足す。`すべて` でも出る。隠したレイアウトでも、値は保持し、保存でも失わない(既存の規則)。
- 区間に進捗度が 1 つでもあるときは、欄を読み取り専用にして、区間の最後の値を示し、「実績の区間の値を使っています」と添える。区間の進捗度がなくなる(実績の入力を空にする・進捗度を消す)と、欄は編集できる状態に戻り、`Task.progress` の値を示す。
- 保存では、区間に進捗度があるときも `Task.progress` を変えない(読み取り専用の欄の値を書き込まない)。
- チェックポイントの種別では、欄を出さない。種別を切り替えるときは、`Task.progress` を `None` に戻す(他の通常タスク専用の項目と同じ扱い)。
- 入力の検証は、範囲外・小数・文字を、区間の進捗度と同じ言い方で拒否する(`forms._check_progress` を共有する)。

## 3 者マージ(`merge.py`)

- `progress` を、項目ごとの比較に足す(表示名「進捗度」)。片側だけが変えた値を採り、両側が違う値に変えたときだけ画面で選ぶ。リスト扱いにはしない。
- マージ結果は、読込の検証(上の規則)を通す。

## PlantUML の取り込み(`puml_import.py`)

- `is N% completed` の N が 1〜100 のとき、`Task.progress = N`。0・未指定は `None`。状態は今のとおり、N から決める(0・未指定=未着手、1〜99=実行中、100=終了)。チェックポイントは、`Task.progress` を持たないので入れない(100% で終了、それ以外は未着手のまま)。
- `PlantUmlImport.dropped_progress` と、通知の「進捗度を取り込まなかったタスク n 件」を廃止する。
- `PlantUml` の出力側は変えない(`current_progress` を通す)。往復で、進捗度が戻る。

## 含まないもの

- 状態と進捗度の自動の連動(100% で終了にする、など)。
- 区間の進捗度の廃止・移行。
- 進捗度の履歴(時点ごとの値)。
- ガントのバーのドラッグなどでの進捗度の入力。
- `担当者へ書き出し`(todoapp の形式)への進捗度の追加(独自のキーは足さない規則)。

## テスト

- `storage`: version 5 の保存と読込、キーのない古いファイルは `None`、範囲外・整数以外・真偽値の拒否、version 4 以下の `progress` の無視、チェックポイントの値は `None` で読むこと、往復。
- `timeline`: 優先順位(区間が勝つ・区間に進捗度がなければタスクの値・どちらもなければ `None`・0 の扱い)。
- `task_dialog`・`forms`: 入力と保存、区間があるときの読み取り専用と値の表示、区間をなくしたときの復帰、`Task.progress` を保存で変えないこと、非表示のレイアウトでの保持、チェックポイントへの切り替えで `None`、不正入力の拒否。
- `merge`: 片側だけ変更、両側が違う値(選択)、片側が `None` へ変更。
- `puml_import`: N が 1〜100 のとき `Task.progress` に入る、0・未指定は `None`、チェックポイントは入らない、通知から該当の項目がなくなる、出力の往復で進捗度が戻る。
- ダッシュボード・ガント: `Task.progress` だけのタスクで、進捗率・塗り・チップが出る。
