# 実績の時刻を省略できるオプションの設計(要望 144)

2026-11-16 作成。対象は`docs/requests.md`の要望 144。

## 目的

実績(開始・終了)を入れるとき、時刻を入力せず、日付だけで済ませられるようにする。省いた時刻は、プロジェクトの始業・稼働時間から補う。オプションで、今までどおり時刻を必須にもできる。

## 現状

- タスク編集ダイアログの実績は、日付と時刻の両方が要る。片方だけだと、`compose_actual`(`forms.py`)が`日付と時刻を両方入れてください`で拒否する(実績は時刻を補わない)。
- `compose_actual`は、簡易の入力欄(`ActualFields`)・区間の行(`IntervalFields`)・ガントチャートの棒を Shift クリックして開く小さなダイアログの 3 か所が使う。
- CSV の取り込み(`csv_import.py`)は、日付だけの実績に、次の規則で時刻を補う: 開始は`work_start`、終了は`work_start + daily_hours`(日付だけのとき)。補った終了が開始より前なら、開始に揃える(`max(end, start)`)。
- 実績は`Actual(start: datetime, end: datetime | None)`。プロジェクト設定には`actual_mode`(簡易・区間)があり、ファイルの`version`は 22。

## 決定事項(2026-11-16 に確認済み)

| 項目 | 決定 |
|---|---|
| 省いた時刻の扱い | 始業・終業を補って保存する(CSV の取り込みと同じ規則)。時刻なしの実績という形は持たない |
| オプション | プロジェクト設定`実績の時刻`: `省略できる`(既定)・`必須` |
| 置き場所 | 設定ダイアログの`実績の記録方式`の下 |
| ファイル形式 | `actual_time_optional`(真偽値)を足し、`version`を 22 → 23 に上げる。キーのない古いファイルは、既定(`省略できる`)で読む |
| 補う終了 | `work_start + daily_hours`(CSV の取り込みと同じ。休憩を挟む運用では、実際の終業より遅くなりうる) |

## 補う規則(`省略できる`のとき)

- `fill_actual_times(start_day, start_clock, end_day, end_clock, *, optional, work_start, daily_hours) -> tuple[str, str]`(`forms.py`の純粋関数。`compose_actual`を 2 回呼ぶ代わりに、開始と終了を一緒に作る)を足す。戻り値は`build_actuals(start_text, end_text)`に渡す文字列の組。
  - 日付も時刻も空: 空(実績なし)。
  - 日付と時刻の両方: そのまま(今までと同じ)。
  - 時刻だけ(日付が空): エラー(`日付を入れてください`)。
  - 日付だけ(時刻が空)で、`optional`が真: 開始は`日付 work_start`、終了は`日付 work_start + daily_hours`。`work_start + daily_hours`が翌日にかかるとき(始業 22:00・8 時間など)は、日付をまたいだ日時のまま使う。`optional`が偽なら、今までどおりのエラー(`日付と時刻を両方入れてください`)。
  - 補った終了が、開始より前になるとき(開始に明示した時刻が遅いときなど)は、終了を開始に揃える(CSV の取り込みの`max(end, start)`と同じ)。両方を明示した前後逆は、補っていないので、今までどおり`build_actuals`がエラーにする。
- 保存するのは、補ったあとの`datetime`。データの形・集計は変えない。開き直すと、補った時刻が入った状態で見える(省いたという情報は持たない)。

## `必須`のとき

今の動作のまま(日付と時刻の両方が要る。片方だけはエラー)。

## 画面

- `省略できる`のとき、時刻の欄を空のまま確定できる。空の欄には、薄い案内を出す(開始: `省略: 始業 09:00`、終了: `省略: 終業 17:00`。値は、`work_start`と`work_start + daily_hours`の時刻から作る。日をまたぐときは`翌 07:00`)。
- 状態の自動提案(`ActualFields.filled`・区間の`filled`)は、`省略できる`のとき、日付だけでも、そろっているとみなす(`_parses`の時刻の検査を、省略できるときは外す)。
- `必須`のとき、案内は出さず、今の動作のまま。
- 入口は、簡易の入力欄・区間の行・Shift クリックの小さなダイアログの 3 か所すべて。いずれも、設定の値(`actual_time_optional`・`work_start`・`daily_hours`)を受け取る。

## 設定ダイアログ

- `実績の記録方式`の下に、`実績の時刻`のトグル(`省略できる`・`必須`)を足す。マーカーは`settings-actual-time-optional`。
- 変えても、保存済みの実績は変わらない(確認ダイアログは要らない)。

## ファイルとほかの機能への波及

- `models.py`: `Project.actual_time_optional: bool = True`、`FORMAT_VERSION`を 23 に上げ、変更履歴の注記に`23: 実績の時刻の省略〔actual_time_optional〕`を足す。
- `storage.py`: 書き出し・読み込みに`actual_time_optional`を足す。キーがない・`null`は`True`。真偽値でない値は拒否する(既存の真偽値の設定と同じ)。新しい`version`は、これまでどおり拒否する。
- `settings_io.py`: 設定の書き出し・取り込みに含める(`実績の記録方式`の隣。日本語のキーは`実績の時刻の省略`)。取り込みの確認の表示にも出す。
- `merge.py`: 3 者マージの設定項目に足す(表示名は`実績の時刻の省略`)。
- `extract.py`: 子プロジェクトへの切り出しで引き継ぐ設定に足す(`gantt.md`の引き継ぐ設定の一覧にも書く)。
- CSV の取り込み・書き出し、PlantUML、担当者向けファイルは変えない(CSV の取り込みの補完は、すでに同じ規則)。

## テスト

- 純粋関数`fill_actual_times`: 日付だけの開始・終了、日付と時刻の両方、時刻だけ(エラー)、両方空、日をまたぐ終了、`必須`のときの拒否。
- 補った終了が開始より前のとき、開始に揃える。明示した前後逆は、`build_actuals`がエラーにする。
- 画面: 簡易の入力欄・区間の行・Shift クリックのダイアログで、時刻を空にして確定できる。`必須`では今までどおり拒否する。案内の文字が、設定の始業・終業に合う。状態の提案が、日付だけでも働く。
- 設定ダイアログ: トグルの既定、切り替え、保存。
- ファイル: `version` 23 の読み書き、キーのない古いファイルの読み(`省略できる`)、不正な値の拒否、新しい`version`の拒否。
- 設定の書き出し・取り込み、3 者マージ、子プロジェクトへの切り出しで、値が引き継がれる。

## 範囲外

- 時刻なしの実績を、データとして持つこと(日付だけの`date`型の保存)。
- 補う時刻の個別の設定(始業・終業とは別に決める)。
- CSV の取り込み・書き出しの補完規則の変更。
