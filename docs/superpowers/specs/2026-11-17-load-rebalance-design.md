# 負荷の調整(要望 145)設計書

2026-11-17。経路: architectural。決めた方針は、利用者との対話で承認済み(入口・操作・結果の見せ方)。

## 背景と目的

担当の割り当てが多く、負荷の高い人(ダッシュボードの`人ごとの負荷`で割り当て超過の人)について、担当と割り当て率を簡単に調整できるようにする。今は、負荷の高い人を見つけたあと、ガントで該当のタスクを 1 件ずつ探して、編集ダイアログで担当や率を直す必要がある。調整の効果(負荷・完了見込み)も、直して保存するまで分からない。

## 決めたこと(承認済み)

| 点 | 決定 |
|---|---|
| 入口 | ダッシュボードの`人ごとの負荷`から。割り当て超過の人の行に`調整…`ボタンを出す |
| 操作 | 割り当て率の変更・他の人への移し替え(付け替え)・別の人を足して分ける(担当の追加)の 3 つ |
| 結果の見せ方 | 調整ダイアログの中で、変えるたびに変更前→変更後を出す(確定しないと保存されない試算) |

## 画面

### 入口
- `人ごとの負荷`の行(1 人 1 行)に、その人が割り当て超過(負荷 100% 超の日がある)のときだけ`調整…`ボタンを出す。マーカーは`dashboard-rebalance-<名前>`。
- 超過のない人・`全プロジェクト`をオンにした表示・`カードを編集`中は出さない(全プロジェクトは、他のプロジェクトのタスクを直せないため)。
- 押すと、その人の`負荷の調整`ダイアログを開く。対象の期間は、そのカードの期間と同じ。

### ダイアログ
- 見出しに人の名前と、負荷(平均・最大・100%超の日数)を出す。
- 一覧は、その人が担当する、調整できるタスク(下記の対象)。1 行に、タスク名・残りの工数・今の割り当て率・変更後の欄を持つ。
  - 割り当て率: 数値欄とスライダー(担当の編集と同じ範囲・刻み)。
  - `移す`: 移し先の人を選ぶ。候補は余力の多い順で、余力(時間)を添える。余力がない人は候補の末尾に灰色で並べ、選べる(警告を出す)。
  - `追加`: 足す人を選ぶ。候補の並びは`移す`と同じ。足す人の割り当て率の既定は 50%(元の人の率は変えない。分け合うなら、元の人の率を下げる)。
- 1 行につき、変更は 1 つ(率の変更・移す・追加のどれか)。やり直すときは、その行の`戻す`で元に戻す。
- 下に、結果の欄(下記)と、`キャンセル`・`適用`のボタンを置く。変更がないときは`適用`を押せない。

### 結果の欄(変えるたびに更新)
- 負荷: 関わる人(元の人と、移し先・追加先の人)ごとに、平均・最大・100%超の日数を、変更前→変更後で出す。100% 超の日数が減ったときは緑、増えたときは赤。
- タスク: 変更した行ごとに、完了予定と完了見込み(`forecast.py`)を、変更前→変更後で出す。予定超過になる・なくなるときは印を付ける。
- 見直し: 率が変わって完了予定の見直しが要るタスクの件数を出す(`reassign.needs_review`と同じ判定)。適用すると、`reassign.reviewed_end`と同じ規則で完了予定を見直し、手で指定の完了予定にする。見直さずに適用する選択は出さない(調整のあとの完了予定が、変更前の数字のまま残ると、結果の欄と食い違うため)。

## 計算(`rebalance.py`。NiceGUI から切り離した純粋関数)

```python
@dataclass(frozen=True)
class Edit:
    task_id: str
    kind: Literal["rate", "move", "add"]
    name: str | None = None   # move: 移し先、add: 足す人
    rate: float | None = None  # rate: 新しい率、move: 移し先の率(既定は元の率)、add: 足す人の率

def adjustable(task: Task, name: str) -> str | None
    """調整できるときは None、できないときは理由。"""

def apply_edits(project: Project, edits: Sequence[Edit], ...) -> Project
    """編集を当てた複製を返す(元は変えない)。"""

def preview(project: Project, edits: Sequence[Edit], period: Period, holidays, now) -> Preview
    """関わる人の負荷の前後、変更したタスクの完了予定・見込みの前後、見直しの件数。"""
```

- 負荷は、既存の`dashboard.summarize_loads`を、編集前・編集後のプロジェクトに使う(割り当て超過の縞と同じ前提)。
- 余力は、要望 131 の`dashboard.Candidate`の計算を再利用する(今日から期間の終わりまでの稼働できる時間 − 担当している残りの工数)。編集後は、移し先・追加先の担当が増えた分を引いて数え直す。
- 完了見込みは`forecast.forecast_end`を使う。
- 複数のタスクを同じ人に移す・足すときは、編集を全部当てた後のプロジェクトで負荷を数える(1 件ずつの合計にしない)。

## 適用

- 編集後のプロジェクトのタスクを、元に戻す 1 ステップで保存する(複数タスクでも 1 回の「元に戻す」)。
- 完了予定の見直しは、上記の規則でこの保存に含める。
- 率は 1〜100% の範囲だけ許す(範囲外は`ValueError`。画面ではエラーを出して`適用`を押せない)。移す・追加では、担当が空になることはない。

## 対象と対象外

調整できる: 通常タスクで、状態が`終了`でなく、その人が担当しているもの。
週ごと・日ごとに分けた担当(`weekly_crew`・`daily_crew`)を持つタスクも調整できる(下の`週ごと・日ごとの担当`)。
調整できないタスク(まとめ・プロジェクト参照・チェックポイント・終了したタスク)は、その人の担当として負荷に数えない・調整しても影響しないため、一覧に出さない。
調整できるタスクが 1 件もない人には、ダイアログに理由を出す。

### 週ごと・日ごとの担当(案 B。承認済み)
- その人が出てくる**全週・全日**に、同じ操作を一括で当てる(行に`全週に適用`と注記する)。
  - 率の変更: その人が出てくる全週(日ごとなら全日)を、同じ率にそろえる。
  - 移す: 全週・全日で、その人を移し先に入れ替える(移し先がすでにいる週・日は、率を合算せず、いる側の率を残す)。
  - 追加: その人が出てくる全週・全日に、足す人を足す(その人がいない週・日、足す人がすでにいる週・日は変えない)。
- 率が週・日によって違うタスクは、今の率を`50〜100%`のように範囲で出す。率を変えると全週が同じ率に上書きされることを、行に注記する。
- 適用後も、`assignees`(全週の和集合)と、日ごとの週の`weekly_crew`(7 日の和集合)の整合を保つ(`daily_crew.py`の既存の部品を使う)。
- 完了予定の見直しは要らない(週ごとのタスクの完了予定は、自動算出に追従する。`reassign.needs_review`も対象外にしている)。
- 調整する週・日を、超過の期間に絞る機能は作らない(必要になれば別の要望で足す)。

## 検討した案

- 案 A(採用): 新しい調整ダイアログ + 純粋関数のモジュール。既存の負荷の集計・余力・見込み・付け替えの見直しを再利用できる。
- 案 B(不採用): 遅れ対応の増員の試算(`crew_trial.py`)を広げる。遅れたタスクが前提で、負荷の高い人が起点の今回の入口に合わない。
- ガントのタスク起点の入口(右クリック・下部パネル)は、今回は作らない(利用者の判断。必要になれば別の要望で足す)。
- 週ごと・日ごとの担当は、案 B(全週・全日に一括で当てる)を採用した(利用者の判断。C: 超過の週・日だけに当てる、A: 週ごとの小さな行に展開する、は見送り)。

## テスト

- `rebalance`(純粋関数): 率の変更・移す・追加それぞれの前後の負荷、複数編集の合算、見直しの件数と完了予定、調整できないタスクの理由、担当が空・率が 0 以下の拒否、元のプロジェクトを変えないこと。週ごと・日ごとの担当は、率の一括変更(範囲表示を含む)・移す(移し先がいる週は率を残す)・追加(いる週は変えない)・`assignees`と日ごとの週の`weekly_crew`の整合を確かめる。
- 画面: `調整…`が超過の人にだけ出る・全プロジェクトのオンで出ない、率を変えると結果の欄が更新される、`適用`で 1 回の元に戻すで戻る、変更がないとき`適用`が押せない。
