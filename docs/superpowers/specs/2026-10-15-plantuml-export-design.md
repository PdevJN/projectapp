# PlantUML 形式での出力 設計書

2026-10-15。architectural。ブランチ `feature/plantuml`。

## 背景と目的

ガントチャートは、画像(PNG)と、担当者向けの JSON でしか書き出せない。ドキュメントや Wiki に貼る、PlantUML で描画する、バージョン管理で差分を見る、といった用途にはテキストが要る。

目的は、**プレビューで見ているガントチャートを、PlantUML のガント(`@startgantt`〜`@endgantt`)のテキストとして保存できるようにすること**。

## 決定事項

- 入口は、プレビュー画面の「PlantUML として保存」(画像保存の隣)。プレビューの期間・スケール・表示項目・絞り込み・折りたたみを、そのまま使う。メニューからの全体出力は作らない。
- 先行タスクの連結は、日付を計算済みの値で固定し、矢印だけ添える(`[T1] -> [T2]`)。PlantUML の制約(`starts at`)では表さない。アプリの画面と同じ日程にするため。
- PlantUML のガントは日単位なので、時刻は出さない。開始日から、完了予定の日まで含めて出す(0 時ちょうどに終わるときは前日まで)。
- 保存は、既存の保存ダイアログ(ネイティブウィンドウのみ)。拡張子は `.puml`、UTF-8、LF。既定のファイル名は `<プロジェクト名>_<日付>.puml`。
- プロジェクトファイルは変えない。保存は、プロジェクトを変更扱いにしない。
- 変換は、NiceGUI に依存しない純粋関数(`plantuml.py`)にする。`handoff.py` と同じ作り。

出力しないもの: 優先度、実績(実際に作業した区間)、リンク、添付、カテゴリ、割り当て率、通常タスクの締切、時刻。

## 入力(プレビューの設定)

`PreviewSettings`(`start`・`end`・`scale`・`show_chips`・`show_alerts`・`show_events`)と、ガントチャートの絞り込み(`TaskFilter`)・折りたたみの状態を、そのまま使う。

- **期間**: `start`〜`end`(含む)。`Project starts <start>`。タスクの期間が期間と 1 日も重ならなければ、タスクを出さない(件数を `skipped` に数え、通知する)。一部だけ重なるタスクは、期間の端で切る。開始予定も実効の開始もない(日程が求まらない)タスクも出さない(`skipped`)。
- **スケール**: `日次`→`printscale daily`、`週次`→`weekly`、`月次`→`monthly`。
- **絞り込み・折りたたみ**: 画面に出ている行と同じ。絞り込み中は折りたたみを無視し、一致したタスクだけを出す。折りたたまれたセクションのタスクは出さない(セクションの区切りは出す)。
- **表示項目**:
  - `show_chips`: オンのとき、進捗(`[Tn] is 40% completed`。進捗が求まるときだけ)と、担当者名(表示名の末尾に ` (田中・鈴木)`。4 人目以降は `ほか n 名`)を出す。
  - `show_alerts`: オンのとき、予定超過のタスク(`timeline.is_overdue`)を赤にする(状態の色より優先)。
  - `show_events`: オンのとき、イベントを出す。

## 出力の形

```
@startgantt
title <プロジェクト名>
printscale daily
Project starts 2026-10-12
saturday are closed
sunday are closed
2026-10-12 is closed
2026-10-19 to 2026-10-30 are colored in lightpink
-- イベント --
[繁忙期] as [E1] starts 2026-10-19 and ends 2026-10-30
[E1] is colored in lightpink
-- 開発 / 設計 --
[設計 (田中)] as [T1] starts 2026-10-13 and ends 2026-10-14
[T1] is 40% completed
[T1] is colored in #4c8bf5
[実装] as [T2] starts 2026-10-15 and ends 2026-10-20
[T1] -> [T2]
[本番リリース] happens on 2026-10-23
@endgantt
```

- **タイトル**: `title <プロジェクト名>`。
- **カレンダー**: `saturday are closed`・`sunday are closed`。期間内の祝日は、日付ごとに `<日付> is closed`(祝日の取得に失敗していれば出さない)。
- **イベント**: 期間に重なるものだけ。(1) セルの色: `<開始> to <終了> are colored in <色>`(期間の端で切る。重なる日は PlantUML の描画順に従う)。(2) 先頭の「イベント」セクションに、色つきの帯(`[文字列] as [En] starts … and ends …` と `[En] is colored in <色>`)。文字列を見せるため。色は CSS の色名のまま渡す。
- **セクション**: 区切り行 `-- 名前 --`。入れ子は `-- 親 / 子 --`(PlantUML のガントは入れ子を持てない)。タスクが 1 件も出ないセクションは、区切りも出さない。ルートのタスクは、区切りなしで、先頭に置く(イベントの次)。
- **通常タスク**: `[表示名] as [Tn] starts <開始日> and ends <終了日>`。`n` は出力順の 1 から。
  - **開始**: 実効の開始(`Schedule.start`。先行の押し出しを反映)の日付。
  - **終了**: 実効の完了(`Schedule.end`)の日付。0 時ちょうどのときは前日。終了が開始より前になるときは開始日に合わせる。
  - **色**: 状態の色(`gantt.STATUS_COLORS`の `#rrggbb`)。予定超過で `show_alerts` なら赤(`#e53935`)。
  - **表示名**: タスク名の `[` と `]` を `(` と `)` に替える。同名のタスクは、2 件目以降を `名前#2` にする(PlantUML は、別名を付けても、同じ表示名のタスクを 1 件にまとめるため)。
- **チェックポイント**: `[表示名] happens on <締切日>`。期間の外なら出さない。
- **連結**: 先行と後続の両方が出力されるときだけ `[Tm] -> [Tn]`(先行 → 後続)。片方が出ないときは出さない。
- **記号の扱い**: 表示名・イベントの文字列・セクション名・プロジェクト名は、改行・制御文字を含まない(検証済み)。`[`・`]` だけを替える。行頭が `@end` で始まる文字列は、先頭に空白を足す(終端と取り違えないため)。

## 画面(`preview.py`・`views.py`)

- `PreviewBar` に、「PlantUML として保存」(マーカー `preview-plantuml`)を足す。有効な条件は、画像保存と同じ(期間が正しく、ネイティブウィンドウで、保存中でない)。
- `MainView.save_plantuml`: `build_plantuml` で変換 → タスクが 0 件なら「出力できるタスクがありません」と通知して終了 → `exporter.ask_path(plantuml_filename(...), PLANTUML_FILE_TYPES)` → `write_text`(一時ファイル経由。`handoff.write_json` と同じ作り)→ 通知。出力で省いたタスクがあれば、通知に件数を足す(「保存しました(期間の外などで n 件を省きました)」)。
- 保存の失敗(`OSError`)は、通知だけ出して、プレビューに留まる。
- ショートカットは足さない。

## テスト

- `plantuml.py`: 期間の切り取り(重ならない・一部・包含)・スケールの対応・絞り込み・折りたたみ・セクション(入れ子・空)・同名・記号のエスケープ・色(状態・超過)・進捗と担当者名・連結(片方が出ない)・チェックポイント・休み(土日・祝日)・イベント(期間の端・重なり・オフ)・日程が求まらないタスク・0 時ちょうどの終了。
- 画面: ボタンの有効・無効、保存の流れ(保存ダイアログの偽物)、0 件のときの通知、失敗の通知。
- 描画の確認: `plantuml.jar`(`/usr/local/lib/plantuml.jar`。1.2021.15)と `java` があるときだけ、出力を実際に描画して、構文エラーがないことを確かめるテストを走らせる(なければ skip)。
