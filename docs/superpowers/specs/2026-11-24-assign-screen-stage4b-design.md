# 要望 168 段階 4b: アサイン専用画面の、週ごとの消化の見通し(設計)

## 目的

割り当てを変えながら、このタスクの残りの工数が、どの週にどれだけ減り、どの週で終わるかを、確定する前に見られるようにする。割り当ての行の下に、週ごとに`消化`と`残り`を並べる。段階 4a(不足と余裕)の計算と同じ数え方を使う。

## 決定(利用者の回答・了承)

- 表示は、割り当ての行の下に 1 行(週の幅に合わせて 1 つずつ)。セルの中への重ね書き・ホバーだけの案は採らない
- 日ごとにした週も、週ぜんたいで 1 つ出す
- 基準日(締切・手で決めた完了予定)がなくても出す。基準日を過ぎた週も出す
- ファイル形式は変えない(`version`は 24 のまま)。表示は試算に含めない(`is_dirty`は変えない)

## 計算(`shortage.py`に足す。NiceGUI に依存しない純粋関数)

4a の`task_shortage`と同じ前提(通常のタスクで、終了していない・工数がある・開始日がある・残りの工数がある)で、基準日の代わりに週で区切る。

- `WeekBurn`(凍結データクラス)
  - `week: int` 週の番号(0 始まり。`CellPlan`と同じ)
  - `first: datetime`・`last: datetime` その週の数える範囲 `[first, last)`。最初の週は`max(今, 実効の開始)`から
  - `burn: float` その週に消化できる工数[h](換算率つき。残りを超えない)
  - `left: float` その週の終わりに残る工数[h](0 以上)
  - `done: bool` その週で`left`が 0 になったか(完了する週)
- `weekly_burn(task, project, holidays, now, weeks, origin, schedule=None) -> list[WeekBurn] | str`
  - `weeks`・`origin`は、画面の`CellPlan`の週の数と原点(週 0 の最初の日)
  - 出せないときは、4a と同じ理由の文字列を返す(`通常のタスクではありません`・`終了したタスクです`・`工数がありません`・`開始日がありません`・`残りの工数がありません`)。`基準日`に関する理由は使わない
  - 週 w の範囲は`[origin + 7w 日, origin + 7(w+1) 日)`。始点は`max(今, 実効の開始, その週の頭)`、終点より後ろなら`burn`は 0(過ぎた週)
  - 稼働量は`timeline.work_capacity`。担当は`weekly_crews(task, project)`(週ごと・日ごとの担当)があればそれ、なければ全体の担当(`crew_of`)。稼働日・休み・祝日・メンバーごとの稼働日の上書きは`work_capacity`が反映する
  - 週ごとの`burn`は、`min(週の稼働量, 残りの工数 − それまでの消化の累計)`。累計が残りに届いた週が`done`で、それより後の週は`burn`が 0・`left`が 0
- 残りの工数は`remaining_hours`(進捗度・実績の消化分を引く)で、4a と同じ

## 画面(`assign_screen.py`の拡張)

- `assign_row`の下に、`burn_row`を足す。週ごとの位置・幅は、セルと同じ`edges`で決める(週の頭から、その週の最終日まで)
- 各週の文字
  - 通常: `消化 12.0h / 残り 28.0h`
  - 完了する週: `消化 6.0h / 完了`
  - それより後の週: `—`
  - 開始前・過ぎた週で`burn`が 0 のとき: `消化 0.0h / 残り 40.0h`
- ラベルは週ぜんたいで 1 つなので、日ごとの週も幅は同じ。週の幅が 120px 未満(月次表示など)のときに、`12.0h→28.0h`・`6.0h 完了`の短い形にする
- ヒント(`title`): `11/18〜11/24 の稼働 12.0h。残り 40.0h → 28.0h`
- 出せないとき(開始日がない・残りがない など)は、行を出さない(理由は 4a の不足の行に出る)
- 割り当てを変えるたびに、`refresh`の中で`render_shortage`と一緒に描き直す。マーカーは`assign-burn-{週}`
- `now`は、4a と同じく`AssignScreen`の`now`の関数を使う

## 確かめること(実装の最初)

- 週ごとの`burn`の合計(完了しない場合)が、4a の`capacity`(基準日が最終週の末のとき)と一致するか
- `weekly_crews`の週の番号と、`work_capacity`の`weeks_start`の数え方(7 日ごと。最後の週は以降も続く)が、画面の週の番号と同じか
- 行を足しても、チャートの高さ(`flex: 1 1 0`)と、横スクロールの連動が崩れないか

足りないときは、この設計書を直して利用者に確認する。

## 範囲外(あとの段階)

- 必要な割り当て率・着工遅れの入力(4c)・前後の比較(4d)
- 週ごとの数字からの操作(クリックで率を変えるなど)
- 複数タスク(要望 169)・日の幅の倍率(要望 170)

## テスト

- 純粋関数: 1 週で終わる・複数週にまたがる・完了する週とその後の`—`・最初の週が今から・過ぎた週は 0・日ごとの担当で週の中の稼働量が変わる・週ごとの担当で週ごとに変わる・休みと祝日・稼働日の上書き・進捗度や実績で残りが減る・理由の文字列(通常でない・終了・工数なし・開始なし・残りなし)・合計が 4a の`capacity`と一致
- 画面(スモーク): `assign-burn-0`が出る・割り当てを足すと消化が増える・完了する週に`完了`が出る・開始日がないと行が出ない
